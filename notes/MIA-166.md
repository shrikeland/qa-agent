**Важный нюанс: этот коммит не отдельная задача по MIA-166, а часть другого MR - !408 «feat(homework): домашка на бесплатном доступе и оплата из панели подписки»**, смёрженного 14.09 в связке с не относящимся к MIA-166 функционалом (оплата прямо из панели подписки, правки по откату из freemium при отклонённой/брошенной привязке - см. также MIA-167, где этот же путь возврата в freemium разбирается подробно). **На MR !408 нет ни одного комментария, и в Linear на MIA-166 факт включения флага никак не зафиксирован** - QA прошлого раунда абсолютно справедливо репортил FAIL относительно документированного на тот момент поведения, само расхождение объясняется тем, что продуктовое решение «включить приманку» было принято и закоммичено в обход тикета, который завёл сам тумблер. ## Контекст (исходная заметка от 15.09, справочно - тумблер на тот момент был `false`)

Тумблер в коде (не в админке, не env-переменная - осознанно, см. «Out of scope» задачи) для проверки гипотезы: открыть разбор домашки фремиум-ученикам без подписки, не выкатывая платёжную логику. MR !397 (`feat/MIA-166-homework-freemium-flag`) смержен в master, деплой прошёл автоматически через master-пайплайн (по комментарию разработчика). На момент написания исходной заметки тумблер был выставлен в `false` - **с 14.09 он переключён в `true`, см. «Обновление» выше**.

## Реализация

Код прочитан целиком на текущем HEAD (`master`, коммит `a4836871` на момент MR !397; значение константы обновлено коммитом `6d85a998` от 14.09).

### Тумблер - две синхронные копии константы

- `api/src/constants/homework-access.ts` и `frontend/constants/homework-access.ts` - в обоих `export const HOMEWORK_ON_FREEMIUM = true` (было `false` до 14.09). Комментарий в обоих файлах прямо предупреждает: «копия во фронте/на бэке - менять обе». Общего модуля между api и frontend в проекте нет, рассинхрон возможен только вручную при правке (и, как показал этот раунд, обе копии 14.09 поменяли синхронно - рассинхрона нет).

### Бэкенд - гейт домашки вынесен из контроллера в `accessService.canAccessHomework`

`api/src/services/access.service.ts`:
```ts
async canAccessHomework(user): Promise<boolean> {
  const access = await this.canAccessTrainer(user);
  if (access.allowed) return true;                 // оплаченный доступ - всегда пускает
  if (!HOMEWORK_ON_FREEMIUM) return false;          // тумблер выключен - как раньше
  const status = access.subscription?.status ?? null;
  return status === null || status === SUBSCRIPTION_STATUS.FREEMIUM;  // пускает только "чистый" фремиум
}
```
Ключевая логика: `canAccessTrainer.allowed === false` смешивает в одном флаге два разных состояния - ученика, который **никогда не платил** (`status === null` или `FREEMIUM`), и ученика, у которого доступ **прервался** (`EXPIRED`, `CANCELLED` без активного окна, `PENDING_BINDING`, `BINDING_FAILED`, `TRIAL_CHARGE_FAILED`, `AWAITING_PAYMENT`, неудачный `CHARGING`). Тумблер открывает **только первую категорию** - прерванный доступ остаётся запертым при любом значении флага. Это прямо соответствует Out of scope задачи («Expired и binding_failed остаются за пейволлом»). Логика не менялась 14.09 - изменилось только значение `HOMEWORK_ON_FREEMIUM`.

`api/src/controllers/homework.controller.ts` - `denyUnpaid()` и список открытых домашек теперь вызывают `canAccessHomework()` вместо прежнего прямого `canAccessTrainer().allowed` - гейт применяется на каждом роуте домашки (не только на странице), включая `listOpenHomeworkHandler` (при отказе - пустой список, не ошибка; при включённом тумблере - реальный список).

### Фронтенд - `homeworkOpen(mode)` и точки использования

`frontend/cabinet/shared/access.ts`:
```ts
export function homeworkOpen(mode: AccessMode): boolean {
  if (mode === 'paid') return true;
  return mode === 'freemium' && HOMEWORK_ON_FREEMIUM;
}
```
`AccessMode` - `'paid' | 'freemium' | 'expired'` (см. `toAccessMode()` тут же: `expired` - это именно прерванный доступ, отдельно от `freemium` = никогда не терявший).

Две точки использования:
1. **Плитка «Решить домашку»** (`frontend/cabinet/shared/next-step.ts`, `homeworkTile()` в `frontend/cabinet/shell/nav-vals.ts`): при `expired` - плитка заблокирована (замок), подпись «на паузе до оплаты», клик → `onPaywall('expired')`. При `free && !homeworkOpen(access)` - тоже заблокирована, подпись «доступна с подпиской», клик → `onPaywall('homework')`. Иначе - открытая плитка «Решить домашку» / «Сфотографируй задание — разберём вместе», ведёт на `ROUTES.homework`.
2. **Страница домашки** (`frontend/pages/app/homework/[[id]].vue`): `watchEffect` при `!homeworkOpen(toAccessMode(user.access))` редиректит на `${ROUTES.appChat}?paywall=homework`.

Пейволл-модалка (`frontend/cabinet/overlay/paywall.ts`) для `reason === 'homework'` - для фремиум-ученика при включённом тумблере эта ветка теперь недостижима штатным путём (плитка и страница открыты), но остаётся актуальной для `expired`.

### Связанный MR !408 (14.09, вне скоупа MIA-166, но меняет её же константу)

- `feat(homework): домашка на бесплатном доступе и оплата из панели подписки` - помимо переключения тумблера, добавляет: кнопку в панели подписки, привязывающую карту без промежуточного экрана выбора тарифа (вынесена в общий composable со страницей тарифов); возврат в freemium при брошенной/отклонённой привязке вместо вечного `awaiting_payment` (это и есть код, который разбирает заметка MIA-167 подробнее); упоминание «Разбор домашки» в списке бесплатного тарифа на лендинге.

## Тест-кейсы (исходные, под `false` - актуальны только если тумблер снова выключат)

### 1. Регрессия при выключенном тумблере (СЕЙЧАС НЕ АКТУАЛЬНО - тумблер `true`, см. раздел выше)

1. Зайти фремиум-учеником (никогда не платил, доступ `freemium`) в кабинет. Плитка «Решить домашку» должна быть заблокирована (иконка замка), подпись - «доступна с подпиской».
2. Кликнуть по заблокированной плитке → должна открыться пейволл-модалка «Разбор домашки — в подписке» (`onPaywall('homework')`), а не переход на страницу домашки.
3. Прямым переходом по URL открыть `/app/homework` (или `/app/homework/<id>` с любым id) под тем же фремиум-учеником → должен произойти редирект на `/app/chat?paywall=homework`, страница домашки не должна отрендериться даже на мгновение.
4. `GET` списка открытых домашек от лица этого ученика → пустой список `[]`, без ошибки.
5. Любой POST/GET на роуты домашки от фремиум-ученика → `403` с телом `{ message: 'Разбор домашки открывается с подпиской', reason: 'homework' }`.
6. Оплативший ученик - плитка домашки открыта, страница домашки открывается без редиректа, как и до этой задачи.
7. Ученик с прерванным доступом (например, `EXPIRED`) - плитка заблокирована с подписью «на паузе до оплаты», клик → пейволл с `onPaywall('expired')`, не `'homework'`.

### 2. Юнит-тесты на оба значения флага

Существуют в диффе (`api/src/services/__tests__/access.service.test.ts`, `frontend/tests/cabinet-access.test.ts`) - при живом прогоне достаточно свериться с их сценариями, не изобретать новые комбинации статусов подписки.

## Аналитика/API

Отдельного аналитического события на открытие/начало домашки фремиум-учеником задача не добавляет (в диффе изменений `analytics-events.ts` нет). API-контракт: при закрытом доступе - `403 { message: string, reason: 'homework' }` на всех роутах домашки; при открытом (текущее состояние) - обычные `200` с данными, как у оплатившего ученика. Для удобства тестирования можно точечно дёрнуть любой `GET`-роут домашки от лица фремиум-ученика и свериться с кодом ответа, не проходя весь UI-флоу.

## Открытые вопросы

- **См. «Открытый вопрос (новый, 16.09)» в начале заметки** - переключение тумблера без единого слова в Linear.
- **Рассинхрон констант при blue-green выкате** - фронтенд ловит только `code: 'PAYWALL'`, домашка отвечает `reason: 'homework'` без `code` - в переходном состоянии экран может остаться без объяснения. Актуально при любом значении флага (риск возникает в момент переключения, а не от конкретного значения).
- **Путь через socket-gateway без проверки доступа** (`/internal/homework/task`, `/interaction`, `/submission` в `api/src/routes/internal.routes.ts` проверяют только `ownsSession`) - предсуществующий пробел, не создан этой задачей, требует отдельного тикета, если будет решено чинить. При включённом тумблере риск ниже (фремиум и так пускают легально через REST), но для `expired`-пользователей дыра сохраняется.
