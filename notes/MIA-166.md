## Контекст

Тумблер в коде (не в админке, не env-переменная - осознанно, см. «Out of scope» задачи) для проверки гипотезы: открыть разбор домашки фремиум-ученикам без подписки, не выкатывая платёжную логику. MR !397 (`feat/MIA-166-homework-freemium-flag`) смержен в master 2026-09-11 с константой `HOMEWORK_ON_FREEMIUM = false` (дефолт, поведение не меняется) - именно это состояние описано в исходной части этой заметки и в комментарии разработчика от 2026-09-11.

**Это устарело.** 2026-09-14, то есть ещё до QA-раунда, в master отдельным коммитом (`6d85a998`, не через MR !397) обе копии константы были переключены в `true`. Подробности - см. блок «⚠️ Регрессионный инцидент 15.09» сразу ниже. На момент этого обновления заметки (2026-09-18, HEAD `0164cd7a`) константа **на обеих копиях остаётся `true`** - раздел «Реализация» и тест-кейсы ниже перечитаны и актуализированы под это состояние кода.

## Реализация

Код прочитан целиком на текущем HEAD (`master`, коммит `0164cd7a`, 2026-09-18). Логика (`canAccessHomework`, `homeworkOpen`, контроллер, страница) не менялась с исходного прочтения в MR !397 - сверено построчно, номера и код-цитаты ниже актуальны. Изменилось только значение константы (см. блок про инцидент 15.09 выше).

### Тумблер - две синхронные копии константы

- `api/src/constants/homework-access.ts` и `frontend/constants/homework-access.ts` - **на текущий момент (2026-09-18) в обоих `export const HOMEWORK_ON_FREEMIUM = true`** (дефолт задачи при первом мерже MR !397 был `false`, изменено коммитом `6d85a998` от 2026-09-14 - см. инцидент выше). Комментарий в обоих файлах прямо предупреждает: «копия во фронте/на бэке - менять обе». Общего модуля между api и frontend в проекте нет (подтверждено постановкой задачи и структурой кода), рассинхрон возможен только вручную при правке.

### Бэкенд - гейт домашки вынесен из контроллера в `accessService.canAccessHomework`

`api/src/services/access.service.ts`:
```ts
async canAccessHomework(user): Promise<boolean> {
  const access = await this.canAccessTrainer(user);
  if (access.allowed) return true;                 // оплаченный доступ - всегда пускает
  if (!HOMEWORK_ON_FREEMIUM) return false;          // тумблер выключен - как раньше
  const status = access.subscription?.status ?? null;
  return status === null || status === SUBSCRIPTION_STATUS.FREEMIUM;  // пускает только "чистый" фремиум
}
```
Ключевая логика: `canAccessTrainer.allowed === false` смешивает в одном флаге два разных состояния - ученика, который **никогда не платил** (`status === null` или `FREEMIUM`), и ученика, у которого доступ **прервался** (`EXPIRED`, `CANCELLED` без активного окна, `PENDING_BINDING`, `BINDING_FAILED`, `TRIAL_CHARGE_FAILED`, `AWAITING_PAYMENT`, неудачный `CHARGING`). Тумблер открывает **только первую категорию** - прерванный доступ остаётся запертым при любом значении флага. Это прямо соответствует Out of scope задачи («Expired и binding_failed остаются за пейволлом»).

`api/src/controllers/homework.controller.ts` - `denyUnpaid()` и список открытых домашек теперь вызывают `canAccessHomework()` вместо прежнего прямого `canAccessTrainer().allowed` - гейт применяется на каждом роуте домашки (не только на странице), включая `listOpenHomeworkHandler` (при отказе - пустой список, не ошибка).

### Фронтенд - `homeworkOpen(mode)` и точки использования

`frontend/cabinet/shared/access.ts`:
```ts
export function homeworkOpen(mode: AccessMode): boolean {
  if (mode === 'paid') return true;
  return mode === 'freemium' && HOMEWORK_ON_FREEMIUM;
}
```
`AccessMode` - `'paid' | 'freemium' | 'expired'` (см. `toAccessMode()` тут же: `expired` - это именно прерванный доступ, отдельно от `freemium` = никогда не терявший).

Две точки использования:
1. **Плитка «Решить домашку»** (`frontend/cabinet/shared/next-step.ts`, `homeworkTile()` в `frontend/cabinet/shell/nav-vals.ts`): при `expired` - плитка заблокирована (замок), подпись «на паузе до оплаты», клик → `onPaywall('expired')`. При `free && !homeworkOpen(access)` - тоже заблокирована, подпись «доступна с подпиской», клик → `onPaywall('homework')`. Иначе - открытая плитка «Решить домашку» / «Сфотографируй задание — разберём вместе», ведёт на `ROUTES.homework`.
2. **Страница домашки** (`frontend/pages/app/homework/[[id]].vue`): `watchEffect` при `!homeworkOpen(toAccessMode(user.access))` редиректит на `${ROUTES.appChat}?paywall=homework` (раньше редирект был при `mode !== 'paid'`, то есть чисто по факту оплаты).

Пейволл-модалка (`frontend/cabinet/overlay/paywall.ts`) для `reason === 'homework'` уже существовала (заголовок «Разбор домашки — в подписке», текст «Сфотографировать домашку и разобрать её с Мией можно с подпиской. Тренироваться по бесплатной теме можно и дальше.») - этим MR не менялась, но именно её должен увидеть фремиум-ученик при клике на закрытую плитку/прямом заходе на страницу домашки.

## Тест-кейсы

### 1. [ПРИОРИТЕТ] Регрессия при выключенном тумблере (⚠️ см. инцидент 15.09 выше - на master сейчас `HOMEWORK_ON_FREEMIUM=true`, этот раздел актуален только пока/если тумблер вернут в `false`)

**Шаг 0 (обязателен, выполнять первым, до любых выводов по остальным пунктам).** Проверить фактическое значение тумблера на стенде, а не полагаться на код/комментарии/статус тикета - именно пропуск этого шага сорвал весь регрессионный раунд 15.09. Например: `GET /api/homework` с cookie свежего фремиум-ученика -
- если ответ `403 {message: "Разбор домашки открывается с подпиской", reason: "homework"}` - тумблер выключен корректно, можно продолжать регрессию по пунктам 1-7;
- если ответ `200` с данными (в т.ч. пустой список `[]` для `listOpenHomeworkHandler`, но `200` там, где ожидается `403`, - смотреть именно на роут, отвечающий `403`/`404` при закрытом доступе) или UI показывает открытую плитку/страницу домашки - тумблер где-то включён (на одной или обеих копиях), регрессионный прогон по пунктам 1-7 нужно отложить и сначала выяснить, почему конфигурация стенда/код не соответствуют ожидаемому `false` (см. «Открытые вопросы»).

1. Зайти фремиум-учеником (никогда не платил, доступ `freemium`) в кабинет. Плитка «Решить домашку» должна быть заблокирована (иконка замка), подпись - «доступна с подпиской».
2. Кликнуть по заблокированной плитке → должна открыться пейволл-модалка «Разбор домашки — в подписке» (`onPaywall('homework')`), а не переход на страницу домашки.
3. Прямым переходом по URL открыть `/app/homework` (или `/app/homework/<id>` с любым id) под тем же фремиум-учеником → должен произойти редирект на `/app/chat?paywall=homework`, страница домашки не должна отрендериться даже на мгновение.
4. `GET` списка открытых домашек от лица этого ученика (через сетевую панель браузера или напрямую) → пустой список `[]`, без ошибки.
5. Любой POST/GET на роуты домашки (`api/src/routes/homework...`, если есть прямой доступ к API) от фремиум-ученика → `403` с телом `{ message: 'Разбор домашки открывается с подпиской', reason: 'homework' }`.
6. Оплативший ученик (`access.allowed === true`) - плитка домашки открыта, страница домашки открывается без редиректа, как и до этой задачи (флаг на эту категорию не влияет вообще).
7. Ученик с прерванным доступом (например, `EXPIRED` - смоделировать через тестовый аккаунт с истёкшей подпиской, если такой есть на стенде) - плитка заблокирована с подписью **«на паузе до оплаты»** (не «доступна с подпиской» - разные тексты для разных причин), клик → пейволл с `onPaywall('expired')`, не `'homework'`.

### 2. Поведение при включённом тумблере (`HOMEWORK_ON_FREEMIUM=true` на обеих копиях - ⚠️ по факту это и есть текущее значение на master с 2026-09-14, см. инцидент 15.09 выше; ранее в этой заметке раздел был помечен как «недоступно на стенде» - это больше не так)

Эти пункты проверяются на стенде, где выставлено `true` (сейчас это master в исходном виде) - раньше требовалось отдельно менять константы и пересобирать образы, но раз `true` уже приземлилось в master 14.09, стоит пройтись по этим пунктам как по ОСНОВНОМУ регрессионному раунду, а не как по отложенному:

8. Фремиум-ученик (никогда не платил) - плитка «Решить домашку» открыта, страница домашки открывается без редиректа, задания можно решать без ограничений (по acceptance задачи).
9. Ученик с прерванным доступом (`expired`) - **по-прежнему заперт** даже при `true` (замок, «на паузе до оплаты», `onPaywall('expired')`) - это ключевая проверка, что тумблер не открывает лишнего: `canAccessHomework`/`homeworkOpen` для `expired` не зависят от флага вообще.
10. Юнит-тесты на оба значения флага существуют в диффе (`api/src/services/__tests__/access.service.test.ts`, `frontend/tests/cabinet-access.test.ts`) - при живом прогоне достаточно свериться с их сценариями, не изобретать новые комбинации статусов подписки.

### 3. [Регрессионный риск, не проверить на текущем стенде, но стоит держать в уме] Рассинхрон двух копий константы

Из код-ревью (комментарий разработчика, за скоупом этой задачи, но важно для будущих раскаток тумблера):

11. **Blue-green риск.** Образы api и frontend катятся не атомарно - в промежуточном состоянии одна копия константы может быть `true`, а другая ещё `false` (в любую сторону). Если фронт думает, что домашка открыта (`homeworkOpen === true` на его копии), а бэк её всё ещё запрещает - при заходе на страницу домашки редиректа не будет (клиентская проверка пропустит), а любой запрос к API домашки получит `403 {reason: 'homework'}`. Общий интерцептор `frontend/composables/use-api.ts` авто-редиректит на пейволл только при `code === 'PAYWALL'` в ответе - у домашки в теле ошибки такого поля нет (`reason: 'homework'`, не `code`), значит автоматического восстановления не будет и экран может просто сломаться без объяснения. Проверить целенаправленно можно только искусственно рассинхронив константы на двух образах - не тест-кейс для обычного QA-раунда, скорее пункт для DevOps-чеклиста при первом реальном переключении флага.
12. **Путь через socket-gateway не проверяется тумблером вообще.** `/internal/homework/task`, `/interaction`, `/submission` (`api/src/routes/internal.routes.ts`) проверяют только `ownsSession`, без вызова `canAccessHomework`. Предсуществующая дыра (не создана и не расширена этой задачей - создание самой домашки всё ещё идёт через загейтенный REST, значит никогда не плативший ученик внутрь не попадёт), но ученик с **прерванной** подпиской, у которого уже есть созданная домашка, теоретически может продолжать решать её задания через сокет в обход `denyUnpaid`. Существовало до MIA-166, тумблер эту дыру не открывает и не закрывает - фиксировать отдельным тикетом, если решат чинить, не в рамках этого QA-раунда.

## Аналитика/API

Отдельного аналитического события на открытие/начало домашки фремиум-учеником задача не добавляет (в диффе изменений `analytics-events.ts` нет). API-контракт: `403 { message: string, reason: 'homework' }` на всех роутах домашки при закрытом доступе - для удобства тестирования можно точечно дёрнуть любой `GET`-роут домашки от лица фремиум-ученика и свериться с телом ответа, не проходя весь UI-флоу.
