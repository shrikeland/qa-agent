## Контекст

В админской карточке студента не было видно домашек (`getUserDetail` их не возвращал), провалиться внутрь домашки было некуда - при этом время по домашкам уже трекалось и показывалось в разрезе по этапам. MR !415 (`feat/MIA-172-admin-homework`) смержен в master, едет автоматически на тест (~5-10 минут по комментарию разработчика). Скоуп: блок «Домашки» во вкладке «Обучение» карточки студента (дата, статус, страницы, задач решено/задано, попытки, время, кнопка «Открыть») + детальная страница `/admin/sessions/homework/<id>` (снимки страниц со статусом распознавания, задачи, попытки с вердиктом и score, чат по задаче). Время берётся из уже собираемого `engagement_time`, ничего нового не трекается. Out of scope прямо в задаче: разрез «по темам» для времени домашки (`topicId` у homework-строк пустой) и любое редактирование из админки - только просмотр.

## Реализация

Ключевые файлы: `api/src/admin/homework-summary.ts` (новый), `api/src/admin/session-detail.service.ts`, `api/src/admin/session-detail.admin.controller.ts`, `api/src/admin/admin.routes.ts`, `api/src/admin/admin.service.ts`, `frontend/components/admin/admin-user-sessions.vue`, `admin-user-learning.vue`, `admin-session-header.vue`, `admin-session-task-detail.vue`, `frontend/pages/admin/sessions/[kind]/[id].vue`.

### Блок «Домашки» на карточке студента (вкладка «Обучение» → подвкладка «Сессии»)

`frontend/components/admin/admin-user-sessions.vue:74-101`. Заголовок карточки - `«Домашки»` + счётчик (`homeworks.length`); этот счётчик **не входит** в общий счётчик таба «Сессии» (тот считает только `diagnosticSessions.length + trainerSessions.length`) - отдельная деталь, которую легко принять за баг, если сверять сумму на глаз.

- **Пустое состояние**: иконка `edit`, текст «Домашек не было».
- Каждая строка домашки:
  - Дата создания + короткий id.
  - **Бейдж «удалена»** (`AdminTag tone="ghost"`) - показывается если `homework.deletedAt != null`. **Сама строка из списка не пропадает** - `admin.service.ts` берёт домашки без фильтра `deletedAt: null` (комментарий в коде: «Deleted ones are listed too: a homework the student threw away is exactly what support gets asked about»). Подтверждает заявление разработчика буквально.
  - Статус - маппинг `HOMEWORK_STATUS_LABEL` (`use-admin-format.ts:124-128`): `DRAFT → «Задачи не выбраны»`, `IN_PROGRESS → «Решается»`, `DONE → «Завершена»` (сырое значение как fallback для неизвестного статуса).
  - `· N страница/страницы/страниц`, `· распознано N задача/задачи/задач`; если есть нераспознанные страницы - `(N не разобрано)` (из `pagesFailed`, страницы со статусом `FAILED`).
  - Если есть `engagementSeconds` - длительность рядом.
  - Вторая строка - «последняя попытка дата · относительное время» либо «решений нет», если попыток не было.
  - Справа - бейдж прогресса: `{solvedCount}/{pickedCount} задач · N попытка/попытки/попыток` (тон success при всех решённых, default при частичных), либо ghost-бейдж **«задачи не выбраны»**, если `pickedCount === 0` (домашка создана, но задачи ещё не выбраны - статус `DRAFT`).
  - Кнопка **«Открыть»** ведёт ровно на `/admin/sessions/homework/<id>` - путь совпадает с заявленным в задаче.
- **Пагинации/сортировки/фильтров в блоке нет** - список отсортирован на бэкенде по `createdAt desc`, `take: 50`. У студента больше 50 домашек - старые не покажутся вообще, без какой-либо индикации, что список обрезан.

### Детальная страница `/admin/sessions/homework/<id>`

`frontend/pages/admin/sessions/[kind]/[id].vue` + `admin-session-header.vue` + `admin-session-task-detail.vue`.

- Хедер: кольцо показывает не балл, а «сдано» (`answered/total`) - у домашки нет `finalScore`, поэтому ветка `isHomework` использует другую метрику, чем у тренажёра/диагностики. Бейдж **«удалена учеником»** (ghost), если `session.deleted` (тот же `deletedAt != null`).
- Карточка «Страницы» (только для homework): картинка страницы (presigned URL) или плейсхолдер **«Снимок недоступен»**, если файла нет; бейдж статуса страницы - `success` для `PARSED`, `error` для `FAILED`, иначе `ghost` с сырым значением статуса (не локализовано - если появится промежуточный статус вроде `PENDING`, в UI он покажется как есть, не переведённым). При `FAILED` рядом выводится `failReason` текстом.
- Карточка «Задачи»: список задач слева, справа - степпер «Задача N из M» + `AdminSessionTaskDetail` с `answerLabel="Ответ по версии Мии"` (не «Верный ответ» - это распознанный Мией эталон, а не задача из банка).
- **Вердикт/попытки** (`admin-session-task-detail.vue`): тег «не задана» если `task.picked === false`, тег «удалена» если `task.deleted`. Вердикт: ответ ученика + иконка ✓/✗/`·` (нет вердикта) + эталонный ответ + балл. **Балл всегда по шкале 0-10**, не 0/1 и не проценты (единственное поле в процентах - OCR-уверенность). Ячейки: Балл (`N/10`), Помощь AI (`N/10` + текстовая подсказка «решал сам»/«частично»/«много помощи»), OCR-уверенность (`%` или `-`), Попыток (число), Уровень (`mlLevel`, + «ниже уровня ученика» если применимо), Сверка CAS (сырая строка).
- **Блок «Попытки» показывается только если попыток больше одной** (`showAttempts`, комментарий в коде: «одна попытка - это и есть полоса вердикта выше, добавлять нечего») - при ровно одной попытке блок скрыт целиком, это стоит явно проверить на границе 1 vs 2.
- Вердикт задачи вычисляется не как «последняя попытка», а по правилу: сначала ищем попытку с `isCorrect === true`, иначе берём последнюю - чтобы не показать красный крест на задаче, которую рейтинг и экран ученика уже засчитали решённой.
- Чат по задаче - переиспользуемый компонент `AdminSessionChat`, **read-only**, без полей ввода в разметке страницы; собирается из `homeworkInteraction`, привязанных к `taskId`.
- Доступ к странице и роуту защищён общим `requireAdmin`-хуком (`admin.routes.ts:89`, применяется единым `onRequest`-хуком до регистрации всех admin-роутов) - без исключений для домашки.

## Тест-кейсы

### 1. [ПРИОРИТЕТ] Happy path блока «Домашки» на карточке студента

1. Открыть карточку студента с несколькими домашками (разных статусов). Блок «Домашки» показывает счётчик и список, отсортированный от новых к старым.
2. Проверить строку с завершённой домашкой: статус «Завершена», число страниц, число распознанных задач, попытки, длительность, бейдж прогресса `X/Y задач`.
3. Проверить строку с `DRAFT`-домашкой (задачи не выбраны): статус «Задачи не выбраны», ghost-бейдж «задачи не выбраны», без бейджа прогресса `X/Y`.
4. Нажать «Открыть» - переход на `/admin/sessions/homework/<id>`, URL и содержимое соответствуют выбранной строке.

### 2. Пустое состояние

Открыть карточку студента без домашек - блок показывает иконку `edit` и текст «Домашек не было», без ошибок в консоли.

### 3. [ПРИОРИТЕТ] Удалённая домашка/задача - видимость, а не сокрытие

1. Найти (или создать через тестовый сценарий) домашку, удалённую учеником со своей стороны.
2. В списке на карточке студента - домашка присутствует, с бейджем «удалена» рядом с датой (не пропадает из списка).
3. Открыть её детальную страницу - в хедере тег «удалена учеником», содержимое (страницы, задачи, попытки, чат) отображается полностью, как у неудалённой.
4. Аналогично для отдельной задачи внутри домашки, снятой учеником с выбора (`picked: false` уже после решения) - тег «не задана» на карточке задачи, но задача остаётся в списке; итоговые счётчики решённых/отвеченных задач её не учитывают (по коду это ожидаемое поведение, не баг, но при демонстрации счётчика может создать впечатление «не сходится с списком задач» - сверить оба места).

### 4. Статусы распознавания страниц

1. Домашка с нераспознанной (`FAILED`) страницей - на карточке студента в строке домашки текст `(N не разобрано)` совпадает с фактическим числом страниц статуса `FAILED`; на детальной странице у этой страницы красный бейдж + `failReason` текстом.
2. Домашка, где у страницы нет доступного файла (presign не удался/файл отсутствует в S3) - на детальной странице показывается плейсхолдер «Снимок недоступен» вместо разбитой картинки.

### 5. Границы «Попытки»

1. Задача без единой попытки (`attempts: []`) - блок «Попытки» не отображается, полоса вердикта показывает `·` и `-` по баллу.
2. Задача ровно с одной попыткой - блок «Попытки» тоже скрыт (только верхняя полоса).
3. Задача с двумя и более попытками - блок «Попытки» появляется, в нём отдельной строкой каждая попытка (номер, ответ, вердикт, балл, дата).

### 6. Регресс/периметр доступа

1. Обратиться к `/admin/sessions/homework/<id>` без прав администратора (например, из обычной пользовательской сессии или без авторизации) - ожидается блокировка тем же механизмом, что и у остальных admin-страниц (401/403), без утечки данных домашки.
2. Открыть страницу с несуществующим id домашки - показывается состояние «Сессия не найдена» с кнопкой «Назад к пользователю», не белый экран/500.
3. Студент с >50 домашками - убедиться, что старые (за пределами 50 последних) действительно не показываются в блоке карточки, и явно решить с продуктом/разработчиком, ожидаемо ли отсутствие пагинации для таких случаев (сейчас не баг по коду, но стоит подсветить как потенциальный будущий тикет).

### 7. Проверка заявленного "вне скоупа" (регрессионная, не должно найтись отклонений)

1. На детальной странице домашки убедиться, что нет разбивки времени «по темам» и нет карточки «Влияние на mastery» (она скрыта по коду именно для домашки - `topicId` у неё не собирается).
2. Убедиться, что нигде на странице домашки (список задач, чат, вердикт) нет форм ввода, кнопок сохранения/редактирования - весь интерфейс исключительно для чтения.

## Аналитика/API

Отдельных новых аналитических событий фича не добавляет - это внутренний инструмент админки, без пользовательской (родитель/ученик) стороны. API-проверка для удобства тестирования: `GET /admin/sessions/homework/<id>` под админской сессией должен возвращать полный объект (страницы, задачи, попытки, чат) даже для удалённой домашки - можно свериться напрямую, не проходя весь UI.

## Открытые вопросы

- Отсутствие пагинации при >50 домашках у студента - не баг по текущему acceptance, но стоит подсветить как потенциальный будущий тикет, если у активных учеников домашек становится действительно много.
- Сырые (не локализованные) значения статуса страницы кроме `PARSED`/`FAILED` (возможный `PENDING`/`PROCESSING`) - если такой статус встретится в живых данных, в UI он покажется как техническое значение enum, а не человекочитаемым текстом; не блокер, но стоит зафиксировать как есть.
