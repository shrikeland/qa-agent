## Контекст

Продуктовое правило (см. `docs/payments/freemium-access.md`): бесплатному ученику доступна ровно одна тема целиком - все 5 ML-блоков, 25 core-задач. Фактически стена подписки поднималась после первой же верно решённой задачи из двадцати пяти: условие в контроллере было `countCompletedByUserAndTopicInCycle(...) === 1`. Ученик решал одну задачу, упирался в оплату, не успев увидеть ценность продукта, и уходил.

Баг жил с первой реализации (июнь 2026, коммит `33081130`, тикет LL-1910) до сентября 2026 и нашёлся по жалобе на проде: ученик `a002ea4a-b844-4f4c-b58c-961e834199f6` получил стену через 7 минут после начала занятия (`docs/payments/freemium-access.md`, раздел «Что уже ломалось»).

В воронке повод помечался как `trainer_limit`/`first_task`, хотя отдельного лимита отправок в продукте давно нет - это тоже было историческим наследием, а не осмысленной меткой.

Код прочитан целиком в `/tmp/repo`: основной коммит `65398201` (логика + правка тестов), второй коммит `b01d3c56` (переименование метки воронки + доп. юниты на `topicJustClosed`), оба замержены в master коммитом `90657836`.

## Что изменено

### Источник сигнала "тема закрыта" - только сервис прогресса

`docs/payments/freemium-access.md` (уже существовал в репо как справочный файл этой же задачи, прочитан целиком): «Сигнал "эта задача закрыла тему" отдаёт `topicMlProgressService.registerResolution` (`{ topicJustClosed }`) - только он меняет статусы блоков, поэтому только он и может отличить "стало закрыто" от "было закрыто давно". Считать закрытие снаружи, сравнивая состояние до и после вызова, нельзя: любая правка порядка строк тихо выключит стену навсегда».

`api/src/services/topic-ml-progress.service.ts`: `registerResolution` раньше возвращал `void`, теперь `Promise<{ topicJustClosed: boolean }>`. Вычисление вынесено в приватный `_applyResolution`, который возвращает `true` только в одной точке - когда закрывается именно 5-й (последний) ML-блок **и** после этого `isTopicClosed(finalBlocks)` подтверждает, что тема закрыта целиком:
```ts
if (block.mlLevel === 5) {
  ...
  // Блоки закрываются по порядку, поэтому тема закрывается ровно здесь - на закрытии ML5.
  return this.isTopicClosed(finalBlocks);
}
return false;
```
Все промежуточные пути (блок остался `ACTIVE`, закрылся не последний блок, тема уже была закрыта раньше - блока в статусе `ACTIVE` для поиска нет вообще) возвращают `false`. Юнит-тесты (`topic-ml-progress.service.test.ts`) закрывают оба края: ML5 закрылся по исчерпании резерва задач с подсказками → `topicJustClosed: true`; повторное решение (перезачёт) уже закрытого ML5 в режиме "practiceOpen" → блок обновляется, но `topicJustClosed: false` (тема была закрыта раньше, второй сигнал не подаётся).

### Контроллер - только транслирует сигнал в триггер пейвола

`api/src/controllers/trainer.controller.ts`, `updateTrainerSubmission`:
```ts
let topicJustClosed = false;
if (getActiveVersion() === 'v3' && submission.status === 'review-complete') {
  ({ topicJustClosed } = await topicMlProgressService.registerResolution(
    submission.trainerSession.userId,
    submission.assignment.topicId,
  ));
}
...
let freemiumPaywallTrigger = false;
try {
  if (topicJustClosed) {
    const student = await userRepository.get(submission.trainerSession.userId);
    const access = await accessService.canAccessTrainer(student);
    freemiumPaywallTrigger =
      access.level === 'freemium' && access.freeTopicId === submission.assignment.topicId;
  }
} catch (err) {
  logger.error({ err, submissionId }, 'freemium paywall trigger check failed');
}
```
Было: `if (submissionData.isCorrect === true)` → дальше отдельный запрос `countCompletedByUserAndTopicInCycle(...) === 1`. Теперь: условие входа - `topicJustClosed` (булев сигнал сервиса), внутри - только проверка, что доступ `freemium` и закрытая тема совпадает с закреплённой бесплатной темой ученика (`access.freeTopicId === submission.assignment.topicId`) - защита от ситуации, когда каким-то образом закрылась не та тема. Запрос `countCompletedByUserAndTopicInCycle` из этого пути убран полностью (в тесте `тема не та, что бесплатная` видно, что счётчик решённых задач больше не участвует).

Ошибка внутри `try` (например, `canAccessTrainer` упал) по-прежнему гасится логом, ответ уходит `200` с `freemiumPaywallTrigger: false`, а не `500` - поведение унаследовано от старого кода, тест `проверка доступа упала -> 200 с freemiumPaywallTrigger false` подтверждает, что это сохранилось.

### Зависимость от версии скоринга (see также docs)

`registerResolution` (а значит и весь сигнал) вызывается только при `getActiveVersion() === 'v3'` и `submission.status === 'review-complete'` - на v1/v2 ML-блоков не существует, тема никогда не закрывается программно, стена из тренажёра в принципе не может подняться (остаются стены на прямом заходе в закрытую тему/контрольную/домашку). Тест `под v2 тема не закрывается -> registerResolution не зовут, стены нет` подтверждает, что на v2 сервис даже не вызывается.

### Как сигнал доходит до пейвола на фронте

REST-ответ `updateTrainerSubmission` с полем `freemiumPaywallTrigger` читает не сам фронт напрямую, а `socket-gateway` (`socket-gateway/src/handlers/trainer.handler.ts:594`):
```ts
if (updated?.freemiumPaywallTrigger) {
  userData.userSocket.emit(UserSocketMessages.FREEMIUM_PAYWALL_TRIGGER, {});
}
```
Фронт слушает сокет-событие `freemium:paywall_trigger` в нескольких местах (`frontend/cabinet/overlay/use-paywall.ts`, `frontend/components/freemium-paywall-modal.vue`, `frontend/cabinet/chat/use-session.ts`) и открывает панель/модалку пейвола.

## Тест-кейсы

Все ниже - на v3 скоринга (стенд тестовый/прод и так на v3 по `docs/payments/freemium-access.md`; на v2 сценарий недостижим по коду, см. выше).

### 1. Фремиум-ученик решает задачи 1..N-1 из бесплатной темы - пейвол не появляется

1. Завести/использовать фремиум-аккаунта (`access.level === 'freemium'`, никогда не платил), бесплатная тема ещё не закреплена или закреплена, но не пройдена.
2. Решить подряд несколько задач из бесплатной темы верно, включая явно первую (это ровно тот путь, что раньше ломался на `countCompleted === 1`).
3. **Ожидается:** ни после первой, ни после последующих задач (пока тема не закрыта целиком) пейвол не появляется - ни панель на странице тренажёра, ни модалка. Можно закрыть 1-4 из 5 ML-блоков и убедиться, что стена так и не поднялась.

### 2. Закрытие последней задачи темы - пейвол появляется сразу

1. Тем же аккаунтом дорешать тему до конца - закрыть последний (5-й) ML-блок (обычно это решение всех core-задач и, если потребовалось, резервных, до исчерпания резерва или до accuracy).
2. **Ожидается:** сразу на этой же задаче (без дополнительных действий) появляется пейвол - либо панель посреди занятия (`serverTrigger === 'free_topic_done'`, если `session.phase === 'live'`), либо, если ученик к этому моменту уже вне занятия и заходит в тему заново - через редирект `?paywall=topic`. Именно в момент решения задачи, закрывшей тему, а не на следующей попытке что-то открыть.

### 3. Метрика - в Метрику уходит именно `free_topic_done`

1. Воспроизвести кейс 2 (закрыть тему), поймать сетевой запрос/событие аналитики (девтулы, вкладка Network → XHR/beacon к Метрике, либо смотреть по `analytics.track` в консоли, если стоит debug-режим).
2. **Ожидается:** событие `freemium_paywall_show` с параметром `trigger: 'free_topic_done'`.
3. Отдельно проверить панель во время занятия и по прямому заходу в закрытую тему - оба пути должны слать `free_topic_done`/`topic` соответственно (панель посреди занятия - `free_topic_done`, обычный заход в закрытую тему - `topic`; это два разных, оба ожидаемых значения, разница по коду - `session.phase.value === 'live'`).
4. Убедиться, что `trainer_limit` и `first_task` в принципе больше не встречаются ни в одном событии воронки этого пейвола - по коду они удалены полностью (не behind a flag, не deprecated-алиас), так что технически увидеть их в новых событиях невозможно; если они всё же всплывут в живом трафике - это отдельный баг (закешированный старый фронтенд-бандл на клиенте, а не серверная логика).

### 4. Граничный случай - тема из одной задачи

1. Если на курсе есть тема с одним ML-блоком/малым числом задач (уточнить у разработчика/по данным курса - в общем случае темы по 5 блоков и 25 core-задач, но стоит спросить, есть ли исключения), решить эту единственную задачу.
2. **Ожидается:** то же поведение, что и для обычной темы - решение единственной задачи одновременно закрывает и первый, и последний (5-й/единственный) блок, `topicJustClosed` становится `true` на этом же решении, пейвол поднимается сразу после неё - **не позже и не по отдельному лишнему условию**. Это тот же путь кода (`block.mlLevel === 5` → `isTopicClosed`), просто блок 5 оказывается одновременно первым решённым - логика от числа блоков в принципе не зависит, специальной ветки под "тема из одного блока" в коде нет, так что риск скорее в данных курса (нет ли где 1-блочных тем, которые ведут себя иначе по другой причине), чем в этой логике.

### 5. Платный ученик (paid) - пейвол не показывается независимо от прогресса по теме

1. Оплаченным аккаунтом (`access.level === 'full'`/`access.allowed === true`) пройти несколько тем целиком, включая полное закрытие темы (все 5 блоков).
2. **Ожидается:** пейвол не появляется ни разу, независимо от того, сколько тем и как быстро закрыто - `topicJustClosed` от `registerResolution` может быть `true` (сервис прогресса не знает про доступ, он общий для всех), но контроллер эту ветку не пускает дальше: `access.level === 'freemium'` не выполняется для платного, `freemiumPaywallTrigger` остаётся `false`. Юнит-тест `полный доступ -> freemiumPaywallTrigger false` покрывает это на уровне кода.
3. Это регресс, не новая логика в этой задаче - но общий контроллер (`updateTrainerSubmission`) правился, так что стоит перепроверить рядом с основными кейсами, а не полагаться только на факт, что тест зелёный.

### Дополнительно, что держать в уме при регрессе

- **Тема закрылась, но это не закреплённая бесплатная тема ученика.** По коду (`access.freeTopicId === submission.assignment.topicId`) пейвол не должен подняться, если каким-то образом закрылась чужая/не та тема - тест `тема не та, что бесплатная -> freemiumPaywallTrigger false` это подтверждает. Специально воспроизвести вживую сложно (тема фиксируется первой отправкой и дальше не меняется по правилу 2 из `freemium-access.md`), но если увидите пейвол на неожиданной теме - это красный флаг именно сюда.
- **Повторное решение (перезачёт/practice) уже закрытой темы не поднимает стену второй раз** - логика сервиса прогресса специально не даёт повторного `topicJustClosed: true`, если блок уже был закрыт раньше (см. юнит `тема была закрыта до этой задачи (повторение) -> freemiumPaywallTrigger false`). Если на стенде есть возможность вернуться в уже пройденную бесплатную тему и порешать её снова (practice/повторение) - стоит убедиться, что пейвол не всплывает заново на каждой такой отправке.
- **Ошибка при проверке доступа не должна ронять сохранение результата задачи** - `canAccessTrainer` под try/catch, ответ всё равно `200`. Специально спровоцировать сложно без доступа к бэкенду, но если увидите `500` на отправке решения именно на задаче, закрывающей тему - смотреть в первую очередь сюда.
