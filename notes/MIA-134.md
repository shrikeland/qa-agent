# MIA-134: обзорный тур первого входа в кабинете ученика

## Контекст

Перенос обзорного тура первого входа из дизайна «Кабинет ученика v2»: на первом заходе в домашний чат Мия за шесть карточек показывает ученику ключевые узлы кабинета и уводит к первому занятию. Метка о прохождении — существующее поле `onboarding.dashboardTourDoneAt`, миграции и новые события аналитики не нужны (переиспользуются `onboarding_dashboard_tour_step` / `_complete` / `_skip`).

MR !341 (ветка `feat/MIA-134-cabinet-tour`) слит в master, коммит `171b350e`. Ветка после мержа в GitLab удалена — код читан прямо по коммиту `171b350e18785bf12f2801ca440e5188989f6a2f` (`git checkout 171b350e`), это ожидаемо и не «код не найден».

## Реализация

**Шесть шагов тура** (`frontend/cabinet/overlay/tour-vals.ts`, `TOUR_STEPS`):
0. Приветствие по имени, без подсветки (`target: null`) — «Привет, {Имя}! Я Мия» / «Привет! Я Мия», если имени нет.
1. `primary` — кнопка «Начать» (data-tour на `chat-primary-cta.vue`).
2. `sessions` — список занятий в боковой колонке (`data-tour="sessions"` на `.cabinet-sidebar__threads`).
3. `composer` — композер чата (`data-tour="composer"` на `.cabinet-composer`).
4. `metrics` — метрики шапки (`data-tour="metrics"` на `.cabinet-header__metrics`).
5. `tabs` — разделы навигации (`data-tour="tabs"` на `.cabinet-sidebar__nav`).

**Счётчик шагов.** Приветствие — вне нумерации («Знакомство»), остальные считаются «Шаг N из 5» (`SPOTTED` = число шагов с `target`).

**Затемнение и подсветка** (`tourClipPath`, `overlay-tour.vue`): один `clip-path` с дыркой по подсвеченному узлу; внешний контур — фиксированный `±99999px` (не по размеру вьюпорта — так исключён баг «затемнена только четверть экрана», когда обёртка приложения крупнее вьюпорта). Шаг без подсветки даёт дырку нулевого размера (то же число сегментов clip-path — переход не дёргается). Клик по затемнению = «Дальше». Отдельная рамка `&__spot` вокруг узла с pulse-анимацией; сам узел остаётся кликабельным (`pointer-events` не перехватываются на нём).

**Позиционирование карточки** (`tourTipBox`): порядок попыток — справа от подсветки → слева → снизу → сверху; если не влезает нигде — прижимается к стороне с наименьшим перекрытием. Без подсветки (или `rect: null`) — по центру экрана. Ширина карточки адаптивная: `tourTipWidth` = `min(384, max(240, vw - 32))`.

**Управление:**
- Точки-переключатели (`tourDots`) — клик на любую ведёт на её шаг (вперёд и назад), активная точка шире (20px vs 6px), пройденные/будущие — разным цветом.
- «Дальше» (`tourNextLabel`) — на последнем шаге текст меняется на «Начать заниматься», это же действие закрывает тур (кнопка «Закрыть» на последнем шаге скрыта — `tourHasSkip: !last`).
- «Закрыть» (`tourSkipLabel`) видна на всех шагах кроме последнего.
- **Escape закрывает тур первым, до всего остального** (`whiteboard-escape.ts`, `nextCabinetEscapeAction`): `tourOpen` проверяется раньше `theoryOpen`/доски/кроппера — если тур открыт поверх доски, Escape закрывает именно тур, а не доску под ним.
- Фокус: при открытии карточка получает `focus()` (не модальный trap — Tab уходит и на подсвеченный узел), при закрытии фокус возвращается на элемент, с которого стартовал тур.

**Запуск и завершение** (`use-cabinet.ts`, `useCabinetTour`):
- `ready` = ученик (`role === 'STUDENT'`), нет `onboarding.dashboardTourDoneAt`, открыт именно домашний чат (`isHomeChat`), доска закрыта и не в процессе закрытия. Запуск — через 500 мс после того, как `ready` стало true (ждёт, пока соберётся шапка/композер).
- Уход из домашнего чата (навигация, открытие доски) во время тура → `finish(false)` — тур закрывается без прохождения до конца, метка всё равно ставится.
- Финал (последний шаг) и «Закрыть»/Escape одинаково зовут `markOnboarding('dashboardTourDoneAt')` (`stores/user.ts`) — локально проставляется сразу (оптимистично), затем `PATCH /me/onboarding` (сервер: `api/src/routes/auth.routes.ts:265`). Сбой запроса не всплывает (лог в консоль) — тур просто попробует показаться заново на следующем входе.
- Только на завершении по финалу (`completed: true`, не по «Закрыть»/Escape) — конфетти (`celebrate()` из `use-toast.ts`).
- Аналитика: `onboarding_dashboard_tour_step` на каждый шаг (`{ step }` — индекс), `onboarding_dashboard_tour_complete` / `onboarding_dashboard_tour_skip` на завершении (`{ step }` — индекс, на котором закончили).

**Адаптив.** На узком экране (`size().narrow`) боковая колонка — выезжающий ящик: шаги `primary`/`sessions`/`tabs` открывают его, остальные (`composer`, приветствие) закрывают (`setDrawer`). Пересечение порога ширины посреди тура (поворот планшета) переигрывает текущий шаг в новой разметке.

**Повторный показ.** Ученики, прошедшие прежнюю версию тура, новый не увидят — `dashboardTourDoneAt` у них уже стоит (это ожидаемое поведение по скоупу, не баг).

## Тест-кейсы

### Happy path

1. **Первый показ тура.** Зайти в кабинет учеником без `onboarding.dashboardTourDoneAt`, попасть в домашний чат.
   Ожидание: тур открывается сам примерно через 0.5 с после загрузки чата. Первая карточка — приветствие по имени («Привет, {Имя}! Я Мия»), счётчик «Знакомство», подсветки нет, карточка по центру, есть заметка «Можно закрыть в любой момент, тур больше не появится».
2. **Прохождение всех шести шагов кнопкой «Дальше».** Пройти весь тур до конца.
   Ожидание: на шагах 1–5 счётчик «Шаг N из 5», подсвечивается соответствующий узел (кнопка «Начать» → список занятий → композер → метрики шапки → разделы навигации), карточка встаёт рядом с подсветкой (не перекрывая её). На последнем шаге кнопка «Дальше» подписана «Начать заниматься», кнопки «Закрыть» нет.
3. **Завершение тура.** Нажать «Начать заниматься» на последнем шаге.
   Ожидание: тур закрывается, играет конфетти, `dashboardTourDoneAt` проставляется (перезайти в кабинет — тур больше не показывается), уходит `onboarding_dashboard_tour_complete` с шагом = 5.

### Альтернативные способы закрытия

4. **Закрытие кнопкой «Закрыть» на промежуточном шаге.** Открыть тур, дойти до шага 2–3, нажать «Закрыть».
   Ожидание: тур закрывается без конфетти, метка ставится, повторно тур не приходит; уходит `onboarding_dashboard_tour_skip` с номером шага, на котором закрыли.
5. **Закрытие клавишей Escape.** Открыть тур, нажать Escape.
   Ожидание: тур закрывается (как «Закрыть»), метка ставится.
6. **Escape при туре поверх доски.** Открыть тур на шаге, где параллельно как-то оказалась открыта доска/кроппер (или наоборот — успеть открыть доску до того как тур стартовал так, что оба на экране), нажать Escape один раз.
   Ожидание: закрывается именно тур, а не доска/кроппер под ним — Escape должен потребоваться второй раз для доски.
7. **Клик по затемнению.** На любом шаге кликнуть в тёмную область мимо карточки и подсветки.
   Ожидание: это равнозначно «Дальше» — переход на следующий шаг, тур не закрывается.
8. **Уход из домашнего чата во время тура.** Открыть тур, не закрывая его, перейти в другой раздел/занятие/диагностику (клик по подсвеченному узлу, если он ведёт наружу, либо навигация мимо тура).
   Ожидание: тур закрывается сам, не остаётся затемнением поверх нового экрана; метка ставится (`onboarding_dashboard_tour_skip`).
9. **Открытие доски во время тура.** Спровоцировать открытие доски, пока тур активен (если возможно на шаге с подсвеченным композером).
   Ожидание: тур закрывается, доска открывается нормально, без затемнения поверх неё.

### Точки-переключатели

10. **Переход вперёд и назад по точкам.** На середине тура кликнуть по точке, соответствующей более раннему шагу, затем по точке дальше текущей.
    Ожидание: тур переходит на выбранный шаг в обе стороны, подсветка и текст карточки обновляются корректно, счётчик синхронизирован с фактическим шагом.
11. **Точка приветствия.** Кликнуть по первой точке (соответствует шагу-приветствию) с любого другого шага.
    Ожидание: возврат на приветствие — снова по центру, без подсветки, счётчик «Знакомство».

### Адаптив

12. **Узкий экран — открытие ящика на нужных шагах.** На мобильной ширине пройти тур: шаги «Кнопка Начать», «Занятия не теряются», «Карта/отчёты/награды».
    Ожидание: на этих шагах боковая колонка (ящик) открывается сама, подсветка корректно наведена на узел внутри ящика.
13. **Узкий экран — закрытие ящика на нужных шагах.** На той же мобильной ширине дойти до шага «Решай, как в тетради» (композер) или приветствия.
    Ожидание: ящик боковой колонки закрывается, композер/приветствие видны без перекрытия ящиком.
14. **Поворот экрана посреди тура.** Начать тур на широком экране, посреди прохождения сузить окно ниже порога боковой колонки (или наоборот).
    Ожидание: текущий шаг переигрывается в новой разметке — подсветка не остаётся наведённой на скрытый/другой по размеру узел, карточка не вылезает за край экрана.
15. **Карточка не вылезает за край окна.** На любом узком экране (в т.ч. телефон) на всех шести шагах.
    Ожидание: карточка тура всегда полностью в пределах вьюпорта с отступом от края, не наезжает центром ровно на свою же подсветку.

### Состояния и повторный показ

16. **Тур не приходит повторно после прохождения.** После завершения (по любому способу закрытия) обновить страницу / зайти заново в домашний чат.
    Ожидание: тур не запускается снова.
17. **Ученик, прошедший прежнюю версию тура.** Взять ученика с уже проставленным `dashboardTourDoneAt` (от старой версии тура).
    Ожидание: новый тур не показывается — это ожидаемое поведение по скоупу, не баг.
18. **Тур не запускается вне домашнего чата.** Зайти в кабинет сразу на другом разделе (не домашний чат) — если это вообще достижимо на первом входе, либо перейти туда до истечения 0.5 с задержки запуска.
    Ожидание: тур не стартует, пока ученик не окажется в домашнем чате.
19. **Тур не запускается при открытой доске.** Спровоцировать состояние, когда доска открыта/закрывается в момент, когда тур мог бы стартовать.
    Ожидание: запуск тура откладывается до закрытия доски.
20. **Роль не «ученик».** Если есть техническая возможность посмотреть кабинет под другой ролью (не STUDENT) с непроставленной меткой.
    Ожидание: тур не показывается.

### Регресс

21. **Кнопка «Начать» остаётся рабочей во время тура.** На шаге с подсветкой кнопки «Начать» кликнуть по самой кнопке (не по «Дальше»/затемнению).
    Ожидание: срабатывает штатное действие кнопки (переход к занятию), а не только листание тура — подсвеченный узел не перехватывается турой для клика.
22. **Обычная работа доски/кроппера/теории не задета.** После прохождения или закрытия тура — Escape на доске/кроппере/окне теории по-прежнему работает как раньше (без тура в цепочке).
23. **Toast и конфетти на других экранах не задеты.** Проверить, что стандартные уведомления (`toast`) и празднование карточек (`celebrateRef`) на других экранах кабинета работают как раньше — новый метод `celebrate()` не мешает существующему `celebrateRef`.

## Аналитика/API

- События `onboarding_dashboard_tour_step` (на каждый шаг, параметр `step` — числовой индекс шага, включая 0 для приветствия), `onboarding_dashboard_tour_complete` и `onboarding_dashboard_tour_skip` (на завершении/закрытии, параметр `step` — индекс, на котором закончили) — события существуют в `frontend/constants/analytics-events.ts` и `api/src/constants/analytics-events.ts` уже давно (переиспользованы, не новые). Сверить в аналитике/логах, что `step` действительно приходит числом и совпадает с фактическим шагом при закрытии из разных мест (кнопка/Escape/уход из чата).
- Метка о прохождении — `PATCH /me/onboarding` с телом `{ dashboardTourDoneAt: <ISO-время> }` (`api/src/routes/auth.routes.ts:265`, `requireAuth`). Полезно для ускорения ручных прогонов: сбросить метку можно вручную в БД (`onboarding.dashboardTourDoneAt`) или через админский сброс онбординга — но он гасит весь объект `onboarding` целиком (включая метку знакомства Мии в чате), это стоит иметь в виду при подготовке стенда.
- Локальный оптимизм: метка проставляется в сторе сразу, до ответа сервера — при сетевой ошибке PATCH ошибка не всплывает пользователю (лог в консоль), только тур может вернуться на следующий вход. Отдельно перепроверить: отключить сеть/симулировать 5xx на `PATCH /me/onboarding` при закрытии тура — тур должен закрыться как обычно, без ошибки в UI.

## Открытые вопросы

- В спеке из описания задачи и комментария автора для проверки предлагается сброс через прямой SQL (`UPDATE "user" SET onboarding = onboarding - 'dashboardTourDoneAt' ...`) — при прогоне на стенде нужен доступ к БД или готовые одноразовые ученики; без него кейсы 1, 16, 17 придётся гонять на новых аккаунтах.
- Не проверено чтением кода: поведение при очень быстрой навигации между разделами до истечения 500 мс задержки запуска (кейс 18) — стоит перепроверить руками, возможна гонка между переключением `ready` и таймером `opening`.
- Чат-туры «Сначала осмотрюсь», «Как устроена доска» и коуч-карточка на доске — вне скоупа этой задачи, в тест-кейсы не включены.
