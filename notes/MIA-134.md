# MIA-134: Обзорный тур первого входа в кабинете ученика

## Контекст

Перенос обзорного тура первого входа из дизайна «Кабинет ученика v2»: Мия за минуту показывает
ученику, где что лежит, и уводит к первому занятию. Шесть карточек — приветствие по имени и пять с
подсветкой узла кабинета (кнопка «Начать», список занятий, композер, метрики шапки, вкладки
раздела). Запускается сам, на первом входе в домашний чат; метка о прохождении — в существующем
`onboarding.dashboardTourDoneAt`, миграций нет. Аналитика — на существующие события
`onboarding_dashboard_tour_step` / `_complete` / `_skip`.

MR !341 (`feat/MIA-134-cabinet-tour`, автор Kirill Verzhitskii) → master.

Вне скоупа: чат-туры «Сначала осмотрюсь» и «Как устроена доска», коуч-карточка на доске (тот же
макет, отдельная задача); повторный показ тем, кто прошёл прежнюю версию тура — у них
`dashboardTourDoneAt` уже стоит, новый тур им не покажется.

## Реализация (код, ветка MR !341)

**Изменённые файлы:** `frontend/cabinet/overlay/tour-vals.ts` (новый), `frontend/cabinet/overlay/use-tour.ts`
(новый), `frontend/components/cabinet/overlay/overlay-tour.vue` (новый), `frontend/tests/cabinet-tour-vals.test.ts`
(новый) + точки подключения: `frontend/cabinet/shell/use-cabinet.ts`, `frontend/cabinet/shell/use-toast.ts`,
`frontend/components/cabinet/chat/chat-composer.vue`, `frontend/components/cabinet/chat/chat-primary-cta.vue`,
`frontend/components/cabinet/shell/shell-header.vue`, `frontend/components/cabinet/shell/shell-sidebar.vue`,
`frontend/pages/app.vue`, `frontend/stores/user.ts`, `frontend/utils/whiteboard-escape.ts` +
`frontend/tests/whiteboard-escape.test.ts`.

**Шесть шагов** заданы в `TOUR_STEPS` (`tour-vals.ts`): приветствие (`target: null`, здоровается по
имени — `helloLine(firstName)`, без имени просто «Привет! Я Мия», вне нумерации — счётчик
«Знакомство»), затем пять с `target`:

| # | target | data-tour в разметке | где живёт узел |
|---|--------|----------------------|----------------|
| 1 | `primary` | `chat-primary-cta.vue` | кнопка «Начать» — в боковой колонке (сайдбар/drawer) |
| 2 | `sessions` | `shell-sidebar.vue` (`.cabinet-sidebar__threads`) | список занятий — в боковой колонке |
| 3 | `composer` | `chat-composer.vue` | композер — в основной колонке чата |
| 4 | `metrics` | `shell-header.vue` (`.cabinet-header__metrics`) | метрики шапки — в основной колонке |
| 5 | `tabs` | `shell-sidebar.vue` (`.cabinet-sidebar__nav`) | вкладки (карта/дашборд/отчёты) — в боковой колонке |

Узел ищется по `[data-tour="..."]` в DOM (не по ссылкам сверху) — так тур не привязан к конкретной
ветке разметки, которая на узком экране может быть то в сайдбаре, то в ящике.

**Композиция:** `useCabinetTour` (`use-tour.ts`) — стейт-машина шага и замер прямоугольника узла;
`tourVals()` (`tour-vals.ts`) — чистая функция, собирающая поля для шаблона (тестируется без
оркестратора, см. `cabinet-tour-vals.test.ts`); `overlay-tour.vue` — сам компонент оверлея.
Подключается в `use-cabinet.ts` (`useCabinetTour({...})`), рендерится в `app.vue` как
`<CabinetOverlayTour :tour="tour" />`, z-index `400` — выше drawer’а сайдбара (`z-index: 210`).

**Когда запускается (`ready` в `use-cabinet.ts`):**
```ts
ready: computed(() => {
  const u = userStore.getUser;
  if (!u || u.role !== 'STUDENT' || u.onboarding?.dashboardTourDoneAt) return false;
  return isHomeChat.value && !board.open.value && !board.closing.value;
}),
```
Тур ждёт именно домашнего чата (не любой раздел) и закрытой доски. В `use-tour.ts` смена `ready`
с `false→true` при `idx < 0` ставит `setTimeout(500)` и запускает `go(0)` — задержка ровно
полсекунды, как в комментарии MR. Один отложенный запуск на всех: повторные переключения `ready`
в эти полсекунды не плодят второй таймер (иначе он вернул бы ученика с середины тура на начало).
Обратный переход (`ready: true→false` при открытом туре) закрывает тур как «пропущен»
(`finish(false)`) — то самое требование «уход из домашнего чата не оставляет тур затемнением
поверх занятия», т.к. подсвеченная кнопка кликабельна и с шага можно уйти прямо в диагностику.

**Метка `onboarding.dashboardTourDoneAt`:** ставится в `onFinish` кабинета (и по завершению, и по
закрытию) через `userStore.markOnboarding('dashboardTourDoneAt')` (`stores/user.ts`) — локально
пишется оптимистично (до ответа сервера) и уходит `PATCH /me/onboarding`; неудачный запрос не
всплывает, просто на следующий вход тур покажется снова. При завершении (`completed: true`)
дополнительно стреляет `celebrate()` — глобальное конфетти (`use-toast.ts`, без привязки к узлу).

**Точки-переключатели:** `tourDots` в `tourVals()` — по одной на каждый из 6 шагов (включая
приветствие), клик — `onGo(i)` → `go(i)` в `use-tour.ts`, прыжок на любой шаг в любом направлении.
Активная — тёмная и шире (20px), пройденные — светлее (`#c9c5ac`), будущие — самые светлые
(`#e6e3cf`).

**Клик по затемнению = «Дальше»:** `<span class="cabinet-tour__scrim" @click="v.tourNext()" />` —
одно затемнение на весь экран с вырезом (`clip-path`) по подсвеченному узлу; сам узел остаётся
кликабельным (вырез = `pointer-events` до подсветки), а клик по остальной площади — то же самое,
что кнопка «Дальше».

**Закрытие тремя способами:**
- «Закрыть» (`tourSkip`, есть на всех шагах кроме последнего — `tourHasSkip: !last`) → `finish(false)`.
- Escape → `nextCabinetEscapeAction()` (`utils/whiteboard-escape.ts`) отдаёт `tourOpen` наивысший
  приоритет («тур поверх всего, поэтому и ключ забирает первым» — раньше теории, окна жалобы,
  доски) → `tour.close()` → тот же `finish(false)`.
- Финал (последний шаг, кнопка «Начать заниматься») → `tourNext()` на последнем шаге вызывает
  `go(idx+1)`, `idx+1 >= TOUR_STEPS.length` → `finish(true)`.

И `finish(false)`, и `finish(true)` в итоге вызывают один и тот же `onFinish` → метка ставится
один раз независимо от способа закрытия; повторно на новый вход `ready` уже `false` из-за
`dashboardTourDoneAt`.

**Узкий экран / drawer (`go()` в `use-tour.ts`):** брейкпоинт `narrow` — `vw < 1080`
(`use-viewport.ts`, тот же порог использует и `chrome.ts` для `narrow`/`drawerOpen`), `phone` —
`vw <= 560`. На узком экране при переходе на шаг:
```ts
if (size().narrow) input.setDrawer(target === 'primary' || target === 'sessions' || target === 'tabs');
```
Шаги 1/2/5 (кнопка «Начать», занятия, вкладки) физически лежат в `shell-sidebar.vue`, который на
узком экране становится fixed-drawer (`.cabinet-sidebar--drawer`, `translateX(-101%)` ↔ `.is-open`)
— тур открывает его перед этими шагами и закрывает перед шагами 3/4 (композер, метрики — они в
основной колонке чата, drawer поверх них мешал бы).

**Переигровка при смене ширины:** отдельный `watch(() => size().narrow, () => { if (idx.value >= 0) go(idx.value) })`
— пересечение порога 1080px посреди тура (поворот планшета/ресайз) переигрывает **тот же** шаг
заново в новой раскладке, а не остаётся с рамкой на закрытом ящике.

**Позиционирование карточки (`tourTipBox` в `tour-vals.ts`):** приоритет — сбоку от подсветки
(вправо, затем влево), потом под, потом над; если целиком не влезает нигде (типично для телефона,
где список занятий занимает почти весь экран) — прижимается к стороне с наименьшим наложением, но
**никогда не в центр** поверх самой подсветки (иначе `pointer-events: auto` карточки отобрал бы
клик у узла, к которому она относится). Ширина карточки — `tourTipWidth(vw)`: `min(384, max(240, vw-32))`,
на 360px становится 328px. Высота меряется `ResizeObserver`'ом по реальному DOM-узлу карточки
(`TIP_H_GUESS = 240` — оценка до первого замера). Повторные замеры узла идут `setInterval(60ms)`
до 420мс после перехода на шаг (`SETTLE_MS`) — под анимацию выезда ящика (320мс).

**Фокус:** при открытии тура фокус уходит на карточку (`tip.value?.focus()`), но тур не модальный —
Tab не заперт внутри, подсвеченный узел остаётся доступным с клавиатуры. При закрытии фокус
возвращается туда, откуда пришёл (`cameFrom`).

**Стилизация:** `overlay-tour.vue` использует фиксированные hex-значения (`#fffef7`, `#1a1a1a`,
`#ffa946` и т.д.), а не `$cabinet-*` SCSS-токены из `_cabinet-tokens.scss`, которыми пользуются
соседние компоненты кабинета (`shell-sidebar.vue`, частично `overlay-curator.vue`) — отклонение от
конвенции `docs/code-style.md` («Все [переменные] в `frontend/assets/scss/_variables.scss`»), но
не функциональный дефект; на глаз палитра совпадает с остальным кабинетом.

## Тест-кейсы

### 1. Первый запуск и happy path
1.1. Зайти в кабинет учеником с ролью STUDENT, у которого `onboarding.dashboardTourDoneAt` не
     стоит (или ключа `onboarding` нет вовсе) → попасть в домашний чат.
     **Ожидаемо:** тур открывается сам примерно через 0.5 с после загрузки чата (не мгновенно и не
     через заметно дольше), первая карточка — приветствие по имени ученика («Привет, <Имя>! Я Мия»),
     счётчик «Знакомство», подсветки нет, карточка по центру.
1.2. Нажать «Дальше» пять раз подряд, дойдя до финала.
     **Ожидаемо:** каждый шаг подсвечивает свой узел вырезом в затемнении (рамка со свечением
     вокруг: кнопка «Начать» → список занятий → композер → метрики шапки → вкладки раздела),
     заголовки карточек и счётчик «Шаг N из 5» соответствуют списку из комментария к MR
     («Кнопка "Начать"», «Занятия не теряются», «Решай, как в тетради», «Твой прогресс», «Карта,
     отчёты, награды»); карточка не перекрывает подсвеченный узел. На последнем шаге кнопка «Закрыть»
     исчезает, вместо «Дальше» — «Начать заниматься», рядом с заголовком бейдж «финал».
1.3. Нажать «Начать заниматься» на финале.
     **Ожидаемо:** тур закрывается, играет конфетти, ученик остаётся в домашнем чате (не
     перенаправляется автоматически никуда специально этой задачей — кнопка лишь закрывает тур).
1.4. Перезагрузить страницу / зайти в кабинет заново тем же учеником.
     **Ожидаемо:** тур повторно не показывается.

### 2. Точки-переключатели
2.1. На любом шаге (2–6) кликнуть по точке шага 5 (последней с подсветкой).
     **Ожидаемо:** тур сразу переходит на шаг 5 (можно прыгать вперёд, не проходя промежуточные).
2.2. С шага 5 кликнуть по точке приветствия (первая точка).
     **Ожидаемо:** тур возвращается к приветствию по имени (переход назад работает так же, как
     вперёд).
2.3. Проверить внешний вид точек: активная — заметно шире и тёмная, пройденные — среднего тона,
     будущие — самые светлые.

### 3. Клик по затемнению
3.1. На любом шаге с подсветкой кликнуть по затемнённой области вне карточки и вне подсвеченного
     узла.
     **Ожидаемо:** тур переходит на следующий шаг — то же самое действие, что кнопка «Дальше»
     (включая переход в финал/закрытие, если кликнуть по затемнению на последнем шаге).

### 4. Закрытие тремя способами
4.1. На шаге 3 нажать «Закрыть».
     **Ожидаемо:** тур закрывается немедленно, конфетти не играет (закрытие — не завершение),
     `dashboardTourDoneAt` проставляется (перезайти — тур не появится).
4.2. Открыть тур заново (сбросить метку, см. ниже), на шаге 2 нажать Escape.
     **Ожидаемо:** тур закрывается (Escape поверх всего остального в кабинете — теории, окна
     жалобы, доски, если бы они были открыты параллельно), метка ставится, повторно не приходит.
4.3. Пройти тур до конца через «Начать заниматься» (п. 1.3) — финал тоже ставит метку (уже
     проверено в 1.4), закрытие финалом и закрытие «Закрыть»/Escape эквивалентны по результату
     (метка стоит), но финал — единственный путь, который считается «completed» для аналитики и
     конфетти (см. раздел «Аналитика»).

### 5. Подсвеченная кнопка кликабельна / автозакрытие при уходе с шага
5.1. На шаге 2 («Кнопка "Начать"», подсвечена кнопка старта занятия) кликнуть прямо по
     подсвеченной кнопке, не закрывая тур явно.
     **Ожидаемо:** нажатие проходит сквозь вырез в затемнении, кабинет уходит в диагностику/занятие
     как обычно; тур при этом закрывается сам (не остаётся висеть затемнением поверх задания) —
     проверить, что после перехода на экран задания оверлея тура нет и клики по нему ничем не
     блокируются.
5.2. Аналогично — уйти прямо в задание/на другую страницу другим способом (например, ссылкой) во
     время любого шага тура.
     **Ожидаемо:** тур закрывается автоматически при выходе из домашнего чата, метка ставится
     (событие `_skip`, `step` — номер, до которого дошёл).

### 6. Узкий экран (~1080px и уже, не телефон)
6.1. Установить ширину окна между ~560 и 1080px (например, 1000px), запустить тур с нуля (сброс
     метки).
     **Ожидаемо:** на шаге 1 («Кнопка "Начать"») боковая колонка автоматически открывается как
     выезжающий ящик (drawer) поверх контента — подсветка ложится на кнопку внутри ящика.
6.2. Перейти на шаг 2 («Занятия не теряются»).
     **Ожидаемо:** ящик остаётся открытым (тот же узел — список занятий — тоже в сайдбаре).
6.3. Перейти на шаг 3 («Решай, как в тетради», композер).
     **Ожидаемо:** ящик закрывается (композер — в основной колонке, ящик поверх него мешал бы).
6.4. Перейти на шаг 4 (метрики шапки).
     **Ожидаемо:** ящик остаётся закрытым.
6.5. Перейти на шаг 5 (вкладки раздела).
     **Ожидаемо:** ящик снова открывается (вкладки — в сайдбаре).
6.6. Находясь на шаге 1 или 2 (ящик открыт), изменить ширину окна так, чтобы пересечь порог 1080px
     в любую сторону (например, повернуть планшет).
     **Ожидаемо:** текущий шаг переигрывается — рамка подсветки и положение карточки пересчитываются
     под новую раскладку (ящик закрывается/остаётся, если стало широко; открывается, если стало
     узко), тур не остаётся с рамкой на пустом месте.

### 7. Телефон (≤560px, например 375–390px)
7.1. Запустить тур с нуля на ширине ~375px.
     **Ожидаемо:** на каждом шаге карточка Мии не встаёт по центру экрана поверх подсветки (что
     перекрыло бы сам подсвеченный узел и отобрало бы у него клик) — она прижимается к свободному
     краю (сверху/снизу/сбоку), даже если целиком не помещается ни с одной стороны. Карточка не
     вылезает за пределы вьюпорта.
7.2. Приветствие (шаг без подсветки) на телефоне — карточка по центру (это единственный шаг, где
     центр ожидаем, т.к. подсветки нет).

### 8. Регресс: прежняя версия тура уже пройдена
8.1. Взять ученика, у которого `onboarding.dashboardTourDoneAt` уже проставлен (мигрировал с
     прежней версии тура или уже проходил новый) → зайти в домашний чат.
     **Ожидаемо:** тур не запускается вовсе, ни через 0.5с, ни позже.
8.2. Ученик с ролью не STUDENT (если применимо к тестовым аккаунтам) → тур не запускается
     независимо от метки.
8.3. Тур не запускается вне домашнего чата (например, сразу открыть занятие/диагностику по прямой
     ссылке, минуя домашний чат) — даже без метки.

## Сброс метки для повторного тестирования

Метка живёт в `onboarding.dashboardTourDoneAt`. Погасить только её (не трогая остальной
онбординг):
```sql
UPDATE "user" SET onboarding = onboarding - 'dashboardTourDoneAt' WHERE id = '<student-id>';
```
Альтернатива — кнопка сброса онбординга в админке (`resetOnboardingHandler`,
`api/src/admin/admin.controller.ts`): она стирает **весь** объект `onboarding` целиком
(`onboarding: Prisma.DbNull`), а не только этот ключ — вместе с `dashboardTourDoneAt` пропадут и
`welcomeSeenAt`, `workspaceTourDoneAt`, `trainerHelpDoneAt`, и в частности `miaIntroDoneAt` (метка
знакомства Мии в чате, вне скоупа этой задачи). Использовать админку для точечного теста тура
можно, но нужно понимать, что заодно обнулится состояние других онбордингов у этого ученика.

## Аналитика

Три существующих события (см. `frontend/constants/analytics-events.ts` и
`api/src/constants/analytics-events.ts` — идентичны в обоих файлах, ключи зеркалятся по конвенции
проекта):
- `onboarding_dashboard_tour_step` — `analytics.track(..., { step })` при каждом переходе на шаг
  (`onStep` в `use-tour.ts` → `go()`), включая переходы назад и через точки. `step` — числовой
  индекс шага (0 = приветствие, 1–5 = подсвеченные), а не «шаг из тексте карточки».
- `onboarding_dashboard_tour_complete` — при финале (`completed: true`), `step` — индекс достигнутого
  шага (для финала — всегда последний, 5).
- `onboarding_dashboard_tour_skip` — при любом незавершённом закрытии («Закрыть», Escape, уход из
  домашнего чата), `step` — индекс шага, на котором тур был прерван.

Проверить в тест-кейсах: событие `_step` стреляет на каждый реальный показ шага (включая прыжки по
точкам туда-обратно — не дедуплицируется), `_complete` и `_skip` — взаимоисключающие и ровно один
раз за прохождение тура (закрытие не должно посылать оба).

## Открытые вопросы

- Не удалось проверить вживую (стенд не поднимался в рамках подготовки документации, только чтение
  кода): точную визуальную синхронизацию анимации выезда ящика (320мс) и переигровки шага (эффект
  `SETTLE_MS = 420мс` в `use-tour.ts`) — стоит на глаз оценить на реальном стенде, нет ли короткого
  мигания рамки в неверном месте на границе анимации.
- Порог `narrow` (`vw < 1080`) и `phone` (`vw <= 560`) — код читает их из `use-viewport.ts` /
  `chrome.ts`; фактическую точку переключения стоит перепроверить на стенде на 1079/1080px и
  559/560px (граничные значения).
- Стилизация `overlay-tour.vue` через хардкод hex вместо `$cabinet-*` SCSS-токенов (см.
  «Реализация») — не блокер для QA, но стоит на заметку как расхождение с `docs/code-style.md`.
- Поведение при повторном быстром клике по «Дальше»/по затемнению (двойной клик) не выделено в
  коде отдельно — судя по `go()`, лишний клик на последнем шаге просто вызовет `finish` ещё раз
  (идемпотентно, `idx.value = -1` уже стоит), но не проверялось вживую.
