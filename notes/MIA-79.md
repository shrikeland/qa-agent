# MIA-79: Кнопка «Сообщить о проблеме»

## Контекст

Ученик должен иметь возможность пожаловаться на неточность (ошибка в задании, неверная оценка, кривое распознавание, ошибка в теории, неверный ответ Мии) прямо со страницы, не уходя в сторонний канал. Жалобы падают в админку `/admin/problem-reports` с полным контекстом задачи и диалога.

**Важно:** формулировка «кнопка одна, в шапке (`TrainerTopBar` / `slot#actions`)» из версии заметки MR !305 устарела. После более позднего редизайна кабинета (отдельного от MR !348, датировку не устанавливали) тренажёр, диагностика, контрольная и разбор результатов объединены в один SPA-кабинет под `/app/*`; старых страниц `frontend/pages/trainer/`, `frontend/pages/diagnostic/`, `frontend/pages/control-test/` в коде больше нет. Кнопка теперь одна на весь кабинет, живёт в боковой колонке (см. «Реализация»), а не привязана к шапке конкретной страницы.

MR !305 (`alekseybobrakov/mia-79-knopka-soobshchit-o-netochnosti` → master, автор Алексей Бобраков) — исходная реализация фичи, уже неактуальна по путям файлов, но актуальна по бизнес-логике (гейты, тексты, серверные проверки — они пережили редизайн почти без изменений, см. ниже). В скоуп задачи по спеке входила ещё правка промпта Мии («если ученик спорит с вердиктом — подскажи нажать кнопку»), но её как не было, так и нет ни в MR !305, ни в MR !348 — см. «Открытые вопросы».

## Реализация (код, master @ `3e8cf3e6`, после редизайна кабинета)

Старые пути `frontend/components/trainer/problem-report.vue` и `TrainerTopBar` из версии заметки MR !305 **больше не существуют** — перепроверено по коду 25.08.2026. Кнопка и окно жалобы переехали в кабинетный SPA-шелл (`frontend/cabinet/*`, `frontend/components/cabinet/*`), список чекбоксов по-прежнему берётся из `frontend/constants/problem-report.ts`.

**Кнопка открытия** — `frontend/components/cabinet/shell/shell-sidebar.vue:148`:
```html
<button type="button" class="cabinet-issue" @click="v.openIssue()">Сообщить о неточности</button>
```
Лежит в подвале боковой колонки (`.cabinet-sidebar__foot`), последней в столбце: куратор → «Что Мия обо мне помнит» → «Сообщить о неточности». В коде это прямо прокомментировано: *«Between the curator and the complaint on purpose: all three are about what to do when something is off»*. Кнопка всегда видна текстом — не сворачивается в иконку, `aria-label` из старой версии заметки (`"Сообщить о проблеме"`) в разметке отсутствует, потому что не нужен: текст не прячется.

**Боковая колонка → drawer.** `frontend/components/cabinet/shell/shell-sidebar.vue` (304px в обычном виде) + `frontend/cabinet/shell/use-viewport.ts`: `narrow: vw < 1080` (брейкпоинт заметно шире прежнего ≤768px). На узком экране колонка получает класс `cabinet-sidebar--drawer` — `position: fixed; z-index: 210`, выезжает `translateX` по тумблеру (`drawerOpen`/`setDrawer`). Открытие окна жалобы дополнительно закрывает drawer: `useCabinetIssue(context, () => setDrawer(false))` в `frontend/cabinet/shell/use-cabinet.ts` — второй параметр вызывается из `openIssue()`.

**Окно жалобы — больше не `UiModal`.** Свой оверлей `frontend/components/cabinet/overlay/overlay-issue.vue`: `position: fixed; inset: 0; z-index: 250`, scrim + карточка `width: min(440px, 100%)`. Клик по scrim (`@click="v.closeIssue()"`) и крестик (`&times;`) закрывают, как в старой версии; `@click.stop` на карточке — клик внутри не всплывает и не закрывает.

**Бизнес-логика** разнесена по трём файлам вместо одного `problem-report.vue`:
- `frontend/cabinet/overlay/issue.ts` — `issueModal()` (тексты/стадии form/notice/sent по поверхности), `issueContextOf()` (из чего строится контекст: что открыто в кабинете прямо сейчас), `issueBody()`/`issueEventParams()`.
- `frontend/cabinet/overlay/use-issue.ts` — `useCabinetIssue()`: состояние (`picks`, `comment`, `sent`, `sending`), снапшот чекбоксов на момент открытия (как и раньше — не computed, чтобы не сдвигать галки под пальцем ученика при появлении `hasMiaMessages` посреди сессии), отправка, аналитика, счётчик гонок `req` (второй запрос не перезаписывает результат первого).
- `frontend/cabinet/overlay/issue-vals.ts` — view-model для шаблона `overlay-issue.vue`.

Поверхность (`IssueSurface` в `issue.ts`) вычисляется не по адресу страницы явно, а через `issueContextOf()`, которому кабинет отдаёт срез своего состояния (`frontend/cabinet/shell/use-cabinet.ts:379-407`):

| `surface` | Когда включается (`frontend/cabinet/shell/where.ts`) | Чекбоксы (`anchorsFor`) | `sessionKind` на сервере |
| --- | --- | --- | --- |
| `trainer` | `isTrainer` — в адресе есть `topicId` | (`MESSAGE`, если `hasMiaMessages`) + `GRADING`, `TASK`, `RECOGNITION`, `THEORY` | `trainer` |
| `diagnostic` / `control_test` | `isTest` — путь `/app/diagnostic` или `/app/control-test`, юзер залогинен | `GRADING`, `TASK`, `RECOGNITION` | `diagnostic` (тип сессии в БД всё равно `CONTROL_TEST`, см. сервер) |
| `chat` — **новая поверхность**, вне исходного скоупа MIA-79 | `isHomeChat` — открыт общий чат `/app`, не тренажёр и не тест | чекбоксов нет — сервер сам подставляет `MESSAGE`; жалоба привязана к `messageId` последнего ответа Мии | `chat` |
| ни одно из условий не сработало — **включая `/app/review`** (бывший «Разбор результатов») | — | fallback на `surface: 'trainer'` с `session: 'none'` | — |

**⚠ Находка по коду (не проверялась вживую).** `frontend/constants/problem-report.ts` по-прежнему объявляет поверхность `results` (свои чекбоксы `GRADING`+`TASK`, свой текст `REPORT_DONE_TEXT.results`), но она нигде не используется — ни в `issue.ts`, ни в `where.ts` нет ветки под `/app/review`. `where.ts` считает `isTest`/`isTrainer`/`isHomeChat` строго по адресу, и путь `/app/review` не проходит ни под одно условие. Значит на странице разбора результатов (аналог старых тест-кейсов №12-16 из этой заметки) кнопка «Сообщить о неточности», скорее всего, попадает в дефолтную ветку `surface: 'trainer'`, видит `trainer.open === false` и показывает нецелевой нотис «Жалоба привязывается к задаче или к ответу Мии. Открой тему в тренажёре или задай вопрос в чате — и кнопка заработает» вместо жалобы на просмотренное задание. На бэкенде ограничения нет — `problem-report.service.ts` по-прежнему умеет принять `sessionId` диагностической сессии независимо от текущего адреса, так что это чисто фронтовый пробел в проводке, а не серверный. К MR !348 и комментарию Кирилла это не относится — похоже на побочный эффект более раннего редизайна кабинета. **Нужно перепроверить руками на `/app/review` в первую очередь** в следующем раунде.

**Кнопка «Отправить»:** `disabled`, пока не отмечена ни одна галка (кроме `chat`, где галок нет вовсе и достаточно наличия `messageId`) ИЛИ идёт отправка ИЛИ жалобы нет активной цели. Логика гейта не изменилась по сути — просто теперь выражена через `issueModal()`.

**Текст после отправки** (`REPORT_DONE_TEXT` / ветки `issueModal()`, зависит от поверхности):
- `trainer` → зовёт написать Мие в чат («...напиши Мие в чат: она разберёт решение по шагам»).
- `diagnostic` / `control_test` → «Разберём решения после теста, в разборе» (чат там не идёт, звать некуда).
- `chat` → «Спасибо, жалоба ушла команде — проверим ответ Мии. Если что-то осталось непонятным, спроси её ещё раз, другими словами».
- `results` в `problem-report.ts` формально существует («Спасибо, жалоба ушла команде»), но недостижима — см. находку выше.

**Поле текста:** необязательное, `maxlength=500`, счётчик `N/500` — без изменений.

**Ошибки отправки** (`reportSubmitFailReason`) — без изменений: 429 → «Ты уже отправил несколько сообщений. Мы их получили, разберёмся» (читается как «приняли», а не как отказ); 403 → терминальная «Эта сессия больше не доступна. Обнови страницу и попробуй снова»; 400 → терминальная «Не получилось отправить эту жалобу…»; 5xx/сеть → «Не удалось отправить. Попробуй ещё раз» (retryable). Галки и текст **не сбрасываются** при ошибке — повтор в один клик.

**Закрытие — то, что чинил MR !348.** Работают три способа: крестик, клик по scrim (не зависели от Esc-бага и раньше), и Escape — теперь по двум независимым путям:
1. **`UiModal`** (`frontend/components/ui/modal.vue`) — используется в 9+ местах (`auth/login-modal.vue`, `auth/success-modal.vue`, `auth/parent-platform-modal.vue`, `subscription/bind-*-modal.vue`, `subscription/soft-card-prompt.vue`, `top-bar.vue`, styleguide), не в самой жалобе. Слушатель `keydown` теперь навешивается на `document` через `watch(() => props.open, listenForEscape, { immediate: true })` на всё время, пока `open === true`, и снимается в `onBeforeUnmount`. Раньше был `@keydown.esc` на `div.modal-backdrop`, но фокус после клика по кнопке-триггеру оставался на самой кнопке (она вне `Teleport to body`), поэтому keydown до backdrop не доходил.
2. **Окно жалобы** — свой путь, не через `UiModal`, поэтому фикс (1) его не касался. `frontend/cabinet/shell/use-cabinet.ts` вешает один `keydown`-слушатель на `window` (`onEscape`, ~строка 307) на весь кабинет и решает, что закрыть, через `nextCabinetEscapeAction()` (`frontend/utils/whiteboard-escape.ts`). До MR !348 функция знала только про тур и теорию — жалоба не значилась в очереди вовсе, и Escape её не трогал. Теперь очередь по z-index: **тур (400) → теория (300) → жалоба (`issueOpen`, карточка на z-index 250) → доска**; жалобу можно закрыть Escape и без открытой доски под ней (`frontend/tests/whiteboard-escape.test.ts`, кейсы «closes the complaint window before the board under it» / «yields to the tour and the theory above it» / «closes the complaint window even with no board under it»).

`close()` (внутри `use-issue.ts` — `closeIssue()`) дополнительно шлёт `report_close_without_submit`, если жалоба не была отправлена и не в процессе отправки (гард на `sending`/`sent`) — как и раньше. Повторное открытие сбрасывает форму.

**Сервер** (`api/src/services/problem-report.service.ts`) — принцип владения не изменился, добавлена третья ветка под `chat`: `trainerSessionRepository`/`diagnosticSessionRepository.findOwnerContext` для `trainer`/`diagnostic`, «чужая» и «несуществующая» сессия дают одинаковый 403; `assignmentId` для тренажёра клиентом не принимается вовсе (`problemReportAssignmentIdNotSupportedForTrainer`); для диагностики/контрольной клиентский `assignmentId` проверяется на членство в диагностике (`isAssignmentInDiagnostic`), иначе 403. Новое: `sessionKind: 'chat'` ищет сообщение через `homeInteractionRepository.findForReport(messageId)`, проверяет `userId`, что сообщение не удалено (`deletedAt`) и что это ответ Мии, а не ученика (`sender !== 'ai'` → 403) — жаловаться можно только на реплики Мии. `sessionType` (DIAGNOSTIC/CONTROL_TEST/TRAINER/CHAT) пишется из строки БД, не из тела запроса. Рейт-лимит — 15/час, ключ по `userId` (не по IP) — без изменений.

**Схема тела запроса** (`api/src/routes/problem-report.routes.ts`) — расширилась относительно версии MR !305 (это уже фиксировала пометка от 10.08 про `sessionKind`, сейчас перепроверено по коду): `anchorTypes` — непустой массив уникальных значений `TASK|MESSAGE|RECOGNITION|THEORY|GRADING`; **обязательный** `sessionKind: trainer|diagnostic|chat`; при `sessionKind: 'chat'` обязателен `messageId` и **запрещены** `sessionId`/`assignmentId` (ветка `if/then/else`, не `oneOf` — комментарий в коде поясняет, что `oneOf` с `removeAdditional` в ajv у Fastify срезал бы поля не сработавшей ветки ещё до валидации); иначе обязателен `sessionId` (1–64 симв.) и запрещён `messageId`; `text` ≤500 симв. или null; `additionalProperties: false`.

## Тест-кейсы

### Тренажёр
1. Открыть тему, пока Мия ещё не писала в чат → открыть модалку — ровно 4 галки, без «Неверные ответы Мии».
2. Дождаться первого сообщения Мии → открыть модалку — уже 5 галок, «Неверные ответы Мии» первой в списке.
3. Кнопка «Сообщить» серая, пока не отмечена ни одна галка; появляется подсказка «Выбери, что не так».
4. Отметить любую галку → кнопка активна, подсказка исчезает.
5. Отправить с текстом и без текста — оба варианта уходят (текст необязателен).
6. Ввести 500+ символов — `textarea` не даёт вписать больше 500, счётчик показывает `500/500`.
7. После успешной отправки — текст зовёт написать Мие в чат; кнопка «Вернуться к решению» закрывает модалку и возвращает на страницу без потери состояния.
8. Жалоба появилась в `/admin/problem-reports` с привязкой к текущему заданию сессии.

### Диагностика / контрольная работа (в процессе)
9. Открыть модалку на активной диагностике — ровно 3 галки: «Неверная оценка», «Ошибка в задании», «Некорректное распознавание» (без «Ошибка в теории» и без «Неверные ответы Мии» — там нет ни теории, ни чата).
10. После отправки текст **не** упоминает чат — отсылает в разбор (страницу результатов).
11. То же на контрольной работе (`control_test`) — идентичное поведение и `sessionType` в жалобе проставлен `CONTROL_TEST`, не `DIAGNOSTIC`.

### Разбор результатов (`results` / теперь `/app/review`) — под вопросом после редизайна, перепроверить в первую очередь

По коду похоже, что этот экран вообще не подключён к `issueContextOf()` (см. «Реализация» → находка) — кнопка глобальная (в сайдбаре, не на странице), поэтому пункт 14 «кнопки нет, если нечего показывать» в старом смысле не применим: кнопка есть всегда, вопрос в том, что она показывает и куда шлёт жалобу. 13. Переключиться на **другую** задачу через навигацию по заданиям внутри разбора → пожаловаться → в админке жалоба привязана к той задаче, что была открыта на экране в момент отправки, а не к первой/текущей на момент входа.
14. Открыть разбор без единого решённого задания — по старой логике кнопки не должно быть вовсе; в новой архитектуре кнопка в сайдбаре есть всегда, проверить, что происходит при клике в этом состоянии (не должно приводить к ошибке/пустой форме без объяснения).
15. После отправки — «Спасибо, жалоба ушла команде», без призыва куда-либо (или актуальный текст для этой поверхности — сверить с `REPORT_DONE_TEXT`/`issueModal()` на момент проверки).

### Мобильная адаптивность (375px) — переписано под редизайн 25.08.2026
17. На ширине < 1080px (375px в том числе) боковая колонка становится выдвижным drawer (`.cabinet-sidebar--drawer`, `z-index: 210`), скрытым по умолчанию. Кнопка «Сообщить о неточности» видна только при открытом drawer, текстом целиком (не иконкой) — прежний пункт «сворачивается в иконку, `aria-label` для доступности» из версии MR !305 больше не актуален, компонент устроен иначе.
17a. На 375px кнопка «Сообщить о неточности» **не наезжает на заголовок ни одной страницы**, потому что кнопки в шапке страниц больше нет вообще ни на одной из поверхностей — весь корпус жалобы переехал в боковую колонку. *Исторический прогон — оба пункта из «Не прошло» ниже по состоянию на 25.08.2026 закрыты со стороны разработки, см. раздел выше «Результаты QA (проверка фикса, 25.08.2026)». Секция сохранена как есть — как база для регресса и источник наблюдений, которые фикса не касались.*

**Прошло:** кнопка на всех трёх поверхностях (тренажёр/диагностика/разбор), сворачивается в иконку-флажок на ≤768px без горизонтального скролла; наборы галок по страницам совпадают с ТЗ (5/3/2, кнопки нет на разборе без ответов); гейт «Сообщить» до выбора галки; тексты после отправки различаются по поверхности как задумано; привязка жалобы к текущей (третьей по навигации) задаче на разборе — подтверждена и в UI, и через API (чужой `assignmentId` → 403); жалоба до отправки решения корректно привязывается к текущему заданию; настоящая ветка 429 (15 запросов подряд) даёт «приняли, разберёмся», галки и текст сохраняются, повтор в один клик; сетевая ошибка — retryable, аналогично; лимит по `userId`, не по IP; owner-проверки и негативы API (401/403/400 по каждому пункту схемы) чисты; повторное открытие модалки после успеха — чистая форма; аналитика — все 5 событий (`report_open`, `report_close_without_submit`, `report_submit_attempt`, `report_submit_success`, `report_submit_fail`) стреляют без задвоения, PII в параметрах нет; админский API (фильтры, счётчик учеников vs строк — `complaintCount=3` при `reportCount=17`, лента активности, CSV-выгрузка) работает.

**Не прошло:**
1. **Esc не закрывает модалку**, пока ученик не кликнул куда-то внутри неё (в textarea или т.п.) — открыл кнопкой → сразу Esc → модалка остаётся, `document.activeElement` всё ещё на кнопке-триггере. Крестик и клик по фону закрывают исправно. Воспроизводится и в тренажёре, и на странице разбора.
2. **На 375px кнопка жалобы наезжает на заголовок `h1` страницы разбора диагностики** (`/diagnostic/results/<id>`) — обе кнопки («Сообщить о проблеме» и «На главную») лежат поверх заголовка, визуально закрыты последние буквы слова «ответов». Друг на друга сами кнопки не наезжают (пункт чеклиста «кнопки не налезают друг на друга» формально выполнен), но результат всё равно битый.

**Куда смотреть:**
1. По Esc — обработчик `@keydown.esc` висит на `div.modal-backdrop` в `UiModal`, но фокус после клика по кнопке-триггеру остаётся на кнопке (она вне `Teleport to body`), поэтому keydown до backdrop не доходит; `.modal` имеет `tabindex="-1"`, но никто его не фокусирует при открытии. Причина общая для всех `UiModal`, открываемых кликом — не специфична для MIA-79, но пункт acceptance числится за этой задачей.
2. По вёрстке разбора — заголовку на мобильном нужен `padding-right` под обе угловые кнопки, либо кнопки переносятся в отдельную строку.

**Наблюдения (не блокеры):**
- Правка промпта Мии (раздел «Решения по итогам» спеки, п.2 — подсказывать нажать кнопку при споре с вердиктом) по-прежнему не реализована нигде в `api/src`, `socket-gateway/src`, `ai-proxy` — та же незакрытая позиция, что и в разделе «Открытые вопросы» ниже; при трёх репликах со спором Мия ни разу не упомянула кнопку.
- `additionalProperties: false` не отклоняет лишние поля 400-й ошибкой — ajv/Fastify их молча срезает (`removeAdditional`); не дыра, но пункт теста «лишнее поле → 400» по факту не воспроизводим, тест-кейс #30 стоит поправить под срезание, а не отказ.
- Сервер не ограничивает набор `anchorTypes` по типу сессии (`THEORY` принимается и для diagnostic, хотя в UI такой галки там нет) — категорийная статистика теоретически может немного загрязняться.
- Валидация схемы тела срабатывает раньше авторизации (400 раньше 401 при отсутствии cookie) — ничего не раскрывает, но к сведению.

**Не покрыто:** поверхность `control_test` (freemium не поднимает сессию без подписки — нужен ученик с доступом); состояние «4 галки на пустом чате тренажёра» практически недостижимо (приветствие Мии успевает прийти до открытия модалки); визуальная часть `/admin/problem-reports` (шторка, стрелки, Escape внутри шторки) — админка за basic-auth, недоступна браузерному инструменту, проверена только на уровне API и наличия строк в чанке; гонка `report_close_without_submit` × `report_submit_success` не воспроизведена вживую (гард по коду есть); распознавание рукописи с доски не проверялось.
