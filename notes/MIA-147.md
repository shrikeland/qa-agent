### Найденный баг: `/admin/ai-cost` теряет сегодняшние вызовы demo_chat (и часть demo_board) из-за интерпретации `to`

Подтверждена ровно гипотеза разработчика из последнего комментария. Механика по коду:

1. **Фронт** (`frontend/pages/admin/ai-cost/index.vue`, `periodRange()`, строки 76-83):
   ```ts
   function periodRange(p: Period): { from: string; to: string } {
     const to = new Date();
     const from = new Date();
     if (p === '7d') from.setDate(from.getDate() - 7);
     else if (p === '30d') from.setDate(from.getDate() - 30);
     else from.setDate(1);
     return { from: from.toISOString().slice(0, 10), to: to.toISOString().slice(0, 10) };
   }
   ```
   `to` - это `new Date()` (текущий момент), но в API уходит **только календарная дата** (`YYYY-MM-DD`, часть до `T`), без времени. Т.е. вместо «до текущего момента» на бэкенд летит просто «сегодняшнее число».

2. **Бэкенд** (`api/src/admin/admin.controller.ts`, `getAiCostDashboardHandler`, строка 384):
   ```ts
   const to = parseDate(request.query.to) ?? new Date();
   ```
   а `parseDate` (строка 9-13) делает `new Date(s)` без модификаций. `new Date('2026-09-09')` (формат `YYYY-MM-DD` без времени) парсится JS как **UTC-полночь этой даты**, то есть `2026-09-09T00:00:00.000Z` - начало суток, а не конец.

3. **`aiCostService.dashboard(from, to)`** (`api/src/admin/ai-cost.service.ts`, строки 142, 154, 159, 181, 191) везде фильтрует `created_at <= ${to}`. С `to = <сегодня>T00:00:00Z` из окна выпадает **весь текущий день от полуночи UTC до момента запроса** - то есть фактически все вызовы, сделанные сегодня (по МСК это ещё хуже: полночь UTC = 03:00 МСК, так что «выпадает» весь рабочий день начиная с 3 часов ночи по Москве).

Это и объясняет наблюдение QA: `demo_chat` целиком исчез (обе реплики созданы «сегодня» и попали в отрезанный хвост), а `demo_board` показал 1 вызов на $0.00 - по-видимому, более старую строку (созданную раньше границы `to`, возможно с нулевой ценой из-за отсутствия usage/ошибки), тогда как новый костный вызов из этого прогона тоже попал под ту же отсечку и не отобразился. Повторный прогон увеличивал счётчики в защищённом API (без даты-фильтра по умолчанию иначе там тоже могла быть проблема - но GET к API без `to` в тесте, видимо, использовал явный диапазон) - в самой БД данные целые, баг чисто в отображении.

**Важно: у самого запроса `GET /admin/ai-cost` (без UI) та же уязвимость** - если явно передать `to=2026-09-09` (без времени), заголовок отрежет всё сегодняшнее. QA обошёл это, передав диапазон с точным include текущего дня (видимо, ISO-datetime или `to`, сдвинутый на завтра) - стоит воспроизвести именно этот трюк при ретесте, чтобы отличить «баг в парсинге даты» от «баг в данных».

Ручной выбор диапазона в UI недоступен («Указать диапазон…» → тост «Функция в разработке», `index.vue` строка 162) - обойти проблему через UI сейчас нельзя вообще, единственный способ увидеть сегодняшние demo_-вызовы в браузере - если бэкенд починят.

**Что НЕ является тем же классом бага (проверено отдельно):** `/admin/whiteboard-blobs` (`frontend/pages/admin/whiteboard-blobs/index.vue`) вообще не отправляет `from`/`to` в фильтрах UI (только `kind`/`recognitionStatus`/`wasCorrect`) - там дата не режет список, поэтому PASS QA по этому пункту не под вопросом и не завязан на этот же баг.

### Учёт костов в ai_usage (демо-поверхности)

- **Схема.** Миграция `20260904090000_demo_board_usage_and_blobs`: `ALTER TABLE "ai_usage" ALTER COLUMN "student_id" DROP NOT NULL`, добавлена `client_side_id TEXT`, плюс CHECK `ai_usage_owner_present`: `student_id IS NOT NULL OR client_side_id IS NOT NULL` - запись без владельца физически невозможна. Тип `whiteboard_kind` получил значение `DEMO_BOARD`; `whiteboard_submission_blob` получил колонку `demo_session_id`.
- **Определение поверхности.** `socket-gateway/src/helpers/ai-usage.helper.ts`, `usageSurface()`: приоритет полей `userData` - `trainerSessionId → diagnosticSessionId → homeChat → homeworkTaskId → demoBoardSessionId → demoChat`; если ничего не подошло - `null`, и вызов не пишется вовсе (комментарий в коде: «cost with no source»). `isAnonymousSurface()` отмечает `demo_board`/`demo_chat` как анонимные - тогда `studentId: null`, `clientSideId: userData.userId`. Используется и в успешном пути (`recordStreamAiUsage`), и при обрыве стрима без `STREAM_END` (`recordFailedCall`, статус `error`/`timeout`) - раньше такие обрывы не оставляли в `ai_usage` вообще никакого следа.
- **Фактическая цена вместо плоских оценок.** `api/src/services/ai-usage/ai-usage.service.ts`, `record()` считает `costUsdMicros = computeCostUsdMicros(model, usage, …)` из реального `usage` модели; если модели нет в прайсинге - `null` + метрика `aiUsageMissingPriceTotal`. Приватный `accrueDemoSpend()` списывает с дневного бюджета лендинга (Redis) именно эту фактическую сумму (или `UNPRICED_CALL_FALLBACK_USD = $0.01`, если цены нет вообще) - комментарий в коде прямо говорит, что раньше был плоский расчёт («$0.05 за разбор», `text.length/4` для чата), теперь списывается «то, что вызов действительно стоил». Списание идёт **после** записи в БД, деньги «прилетают» через секунды после того, как гейт уже пропустил вызов - разработчик сознательно допускает возможный небольшой перерасход бюджета на один вызов.
- **Живой Mathpix OCR не путается с деньгами разбора.** `if (input.kind === 'ocr') return;` в `accrueDemoSpend` - OCR не списывается с общего денежного бюджета доски/чата, у него отдельный **счётчик числа вызовов** в Redis (`demoBoardService.consumeMathpixCall()`, ключ `demo_board:mathpix:<дата>`, лимит `DEMO_BOARD_MATHPIX_DAILY_MAX` = 2000/день по умолчанию). Строка в `ai_usage` при этом всё равно создаётся (`kind: 'ocr'`, `surface: 'demo_board'` или `'trainer'`/`'diagnostic'`) - видна в `/admin/ai-cost`, деньги по ней могут быть $0, если Mathpix ещё в бесплатном месячном диапазоне (это подтвердил QA).
- **Бюджет доски и чата раздельные, плоский эндпоинт снятия удалён.** `demoBoardService` (Redis-ключ `demo_board:budget:<дата>`, дефолт $10/день) и `demoChatService` (`demo:daily_budget:<дата>`, дефолт $40/день) - два независимых кошелька, чтобы флуд на одной поверхности не клал другую. Раньше существовал отдельный эндпоинт списания по плоской оценке - теперь `api/src/routes/internal.routes.ts` регистрирует только `/internal/demo-board/limits` (проверка) и `/internal/demo-board/review-used` (счётчик попыток посетителя, деньги тут не списываются - см. комментарий в `demo-board.controller.ts`: «Деньги дневного бюджета списываются не здесь, а в момент записи ai_usage»); `/internal/demo-board/budget` в роутах отсутствует - 404 ожидаем и корректен, это не баг.

### WebSocket-цепочка доски и общий sessionId

- **`demo-session.helper.ts`, `demoSessionId()`**: берёт `sessionId` из `socket.handshake.auth.sessionId`, иначе из `query.sessionId`, иначе генерирует новый `uuid`. И `demo-board.handler.ts`, и обработчик демо-чата читают его одинаково - поэтому доска и чат одного визита пишутся под одним и тем же `sessionId`, а не расходятся на два треда. Есть отдельный юнит-тест на оба источника (`demo-board-persistence.test.ts`: «runs the sitting under the visitor session id» и «takes the session id from the handshake query too»).
- **`demo-board:session:start` → `demoBoardStartHandler`** (`demo-board.handler.ts`): валидирует `grade` (целое 5..9, иначе `DEMO_BOARD_SESSION_ERROR{reason:'bad_grade'}`), берёт задание через `getDemoBoardTask`, создаёт сессию в `demoBoardSessions` (in-memory по `socket.id`, комментарий явно объясняет почему это безопасно при двух репликах шлюза - сообщения по одной сессии всегда идут на тот же инстанс) и шлёт `demo-board:session:started {sessionId, task}`.
- **`demo-board:submit` → `demoBoardSubmitHandler`**: без `image` в payload → `DEMO_BOARD_SESSION_ERROR{reason:'empty_board'}`. Проверяет `checkDemoBoardLimits` (посетительский лимит разборов + дневной бюджет) - при отказе `DEMO_BOARD_SESSION_ENDED{reason}` (`budget_exhausted`/`already_used`). Дальше: сохраняет блоб (`WHITEBOARD_BLOB_ENABLED=true` включает запись), строит промпт (латех от живой транскрипции - через `createTextGradingPrompt`, иначе vision-fallback через `createSubmissionRecognitionPrompt`), вызывает распознавание, при латехе дополнительно сверяет ответ CAS-движком (`checkEquivalence`). Если доска нечитаема (`unreadable`) - попытка **не** тратится (`markDemoBoardReviewUsed` не вызывается), но блоб и тред всё равно сохраняются с `status: 'ERROR'`/`errorCode: 'recognition_failed'`. Итог шлётся как `demo-board:review:result {isCorrect, review, transcription, unreadable, canRetry, attemptsLeft, durationMs}`, при исчерпании попыток или верном ответе - следом `demo-board:session:ended`.
- **Сохранение как блоб + два хода в `demo_chat`.** `saveWhiteboardBlob({kind: 'DEMO_BOARD', userId: null, demoSessionId: session.sessionId, …})` - блоб без владельца-студента, но с demo-session-id. `saveReviewTurns()` пишет через `addDemoInteraction` **ровно два** сообщения под тем же `sessionId`: `sender: 'user'` с текстом решения (`meta.kind = 'board_submission'`, ссылка на `blobId`) и `sender: 'ai'` с вердиктом (`meta.kind = 'board_review'`, `isCorrect`). Подтверждено юнит-тестами `demo-board-persistence.test.ts` (2 interactions на прогон, включая ветку «модель не вернула текст вердикта» - подставляется заглушка `[разбор без текста]`, чтобы схема роута не отвергла пустой текст и тред не остался разорванным).
- **Изоляция анонимного сокета.** `demo-board-isolation.test.ts` (интеграционный, через реальный `socket.io`) подтверждает: анонимный демо-сокет получает только `demo-board:session:start`/`demo-board:submit`, но не имеет обработчиков `trainer:*`/`diagnostic:*`/`control-test:*`/`homework:*`.

### 1. Демо-доска целиком: happy path

1. Открыть лендинг, дойти до блока демо-доски, выбрать класс (5-9, например 7).
2. Убедиться, что показано задание и доступна доска для ввода (клавиатура/стилус/фото - в зависимости от того, что доступно на UI лендинга).
3. Решить задачу и отправить на проверку.
4. Ожидаемо: цепочка `session:joined → demo-board:session:started → demo-board:review:result → demo:interaction:receive`; в разборе непустая транскрипция и вердикт; в журнале demo_chat (по API или в БД) - 2 новые AI-реплики того же `sessionId`, что и `sessionId` доски.
5. В `/admin/whiteboard-blobs`, фильтр «Демо-доска» - новая запись: статус «Распознано», транскрипция, вердикт, **пустой** User ID (анонимный визит), при включённом `WHITEBOARD_BLOB_ENABLED` - выгрузка WEBP в S3.

### 2. Негативные ветки старта/отправки

- Некорректный класс (вне 5-9, нецелое, отсутствует) → `demo-board:session:error {reason: 'bad_grade'}`.
- `demo-board:submit` без изображения (пустая доска) → `demo-board:session:error {reason: 'empty_board'}`.
- Нечитаемая доска (мусор вместо решения) → `unreadable: true` в результате, попытка посетителя **не** расходуется (следующая отправка всё ещё доступна), но блоб и тред (2 сообщения) всё равно создаются, статус блоба `ERROR`/`errorCode: recognition_failed`.
- Исчерпание посетительских попыток (`DEMO_BOARD_VISITOR_DAILY_REVIEWS`, дефолт 5) или дневного бюджета доски (`DEMO_BOARD_DAILY_BUDGET_USD`, дефолт $10) → `demo-board:session:ended {reason: 'already_used' | 'budget_exhausted'}`. **Не гонять на общем тестовом стенде** без согласования - это общий лимит, совместно используемый другими тестировщиками (как и в прошлом раунде, лучше проверить на локальном/выделенном окружении с переопределённым лимитом).
- Повторная отправка после уже засчитанного разбора → `demo-board:session:ended {reason: 'already_used'}` без нового вызова модели.

### 3. Живая транскрипция (Mathpix OCR) на лендинге

1. `POST /api/mathpix/strokes-session` с `surface: 'demo'` без авторизации → 200, выдаётся токен сессии (при включённом `DEMO_BOARD_ENABLED`; при выключенном - 403 `Demo board disabled`).
2. `POST /api/mathpix/strokes` с тем же токеном → распознавание, в `ai_usage` появляется строка `surface: demo_board (или соответствующий), kind: 'ocr'`, стоимость может быть $0, если Mathpix ещё в бесплатном месячном лимите - это ожидаемо, не баг.
3. Убедиться, что строки `kind: 'ocr'` **не** списываются с денежного дневного бюджета доски/чата (`accrueDemoSpend` явно их пропускает) - косвенно проверяется тем, что после серии OCR-вызовов `remainingUsd` бюджета доски не падает, а падает только собственный счётчик числа OCR-вызовов (`DEMO_BOARD_MATHPIX_DAILY_MAX`, дефолт 2000/день).
4. Исчерпание суточного потолка OCR-вызовов → `POST /api/mathpix/strokes` отвечает 429 `Demo transcription limit reached` (лимит высокий - 2000/день, тестировать не понижая через прод-конфиг стенда, если нет тестового переключателя).
5. Живьём в браузере: реальный ввод стилусом/на touch-девайсе с живой транскрипцией в canvas - **не покрыто прошлым раундом**, стоит закрыть в этом (см. «Не покрыто»).

### 4. Периметр внутренних/интеграционных роутов (регресс прошлого раунда, повторить)

- `POST /api/internal/demo-board/review-used` без сервисной авторизации → 401.
- `GET /api/internal/demo-board/budget` (или любой другой путь с `/budget` в этом неймспейсе) → 404 - подтверждает, что плоский эндпоинт списания удалён и не восстановился случайно при доработке фикса дат.
- `POST /api/internal/demo-board/limits` без авторизации → 401 (по аналогии, не проверялось явно в прошлом раунде - стоит добавить).

### 5. `ai_usage` / `/admin/ai-cost` - данные (в дополнение к приоритетному кейсу выше)

- После связки доска+чат по свежей анонимной сессии - `SELECT` (или защищённый API с явным widened-диапазоном) должен показать: `student_id IS NULL`, `client_side_id` заполнен, `surface` = `demo_board`/`demo_chat`, `cost_usd_micros` не NULL и > 0 для `kind: recognition`/`chat`.
- Модель без прайсинга (искусственно, если есть тестовый способ) → `cost_usd_micros = NULL` + инкремент метрики `ai_usage_missing_price_total` + в логе `error` «no pricing for model»; бюджет демо всё равно спишется по fallback `$0.01`, чтобы не остаться совсем без потолка - проверить, что `remainingUsd` в этом случае действительно уменьшился на $0.01, а не на 0.
- Оборванный стрим (таймаут/ошибка провайдера) на демо-доске или демо-чате → строка в `ai_usage` со `status: 'timeout'`/`'error'`, `usage: null`, `cost_usd_micros: null` - раньше такие обрывы не оставляли следа вообще, это отдельный регресс-кейс из описания задачи, специально не снимался в прошлом раунде.
- В `/admin/ai-cost` (после фикса дат) карточки «По фичам продукта» для `demo_board`/`demo_chat` должны показываться отдельными строками с человекочитаемыми подписями (если такие подписи заведены - на момент чтения кода `SURFACE_LABEL`/`KIND_LABEL` в `index.vue` **не содержат** записей для `demo_board`/`demo_chat`/`ocr`(recognition) - вероятно, отобразятся как есть, сырыми ключами `demo_board`/`demo_chat`; это не баг по acceptance («поверхности видны»), но стоит явно свериться, не смущает ли это отображение - см. «Открытые вопросы»).

- Обрыв стрима (таймаут/ошибка провайдера) на демо-поверхностях - код это явно чинит (`recordFailedCall`), но живой прогон с реальным таймаутом не делался.

## Открытые вопросы

- **[Блокер ретеста] Дата-диапазон `/admin/ai-cost`.** См. «Реализация» и приоритетный тест-кейс выше - это единственный незакрытый пункт acceptance, конкретная причина найдена чтением кода (`periodRange()` во фронте отдаёт только календарную дату, `parseDate`/`new Date(YYYY-MM-DD)` на бэкенде трактует её как начало суток UTC, а не конец, и `created_at <= to` режет весь текущий день).
- **`SURFACE_LABEL`/`KIND_LABEL` в `frontend/pages/admin/ai-cost/index.vue` не заведены для `demo_board`/`demo_chat`/`ocr`-recognition.** Не блокер acceptance (там сказано «видны», не «красиво подписаны»), но стоит спросить постановщика - остаётся ли это на «после фикса дат» или нужно в этом же MR.
- **Ручной выбор диапазона в `/admin/ai-cost` не реализован** («Указать диапазон…» → тост-заглушка) - значит единственный способ проверить сегодняшние демо-вызовы через сам UI (не API) - это дождаться исправления бага с `to`, обходных путей через интерфейс нет.
