## Контекст

Фича (label `Feature`): условие текущего задания и кнопка «Следующее задание» переезжают в чат Мии — раньше условие жило в отдельной карточке слева сверху, кнопка перехода — у доски, диалог с Мией был физически отделён от управления заданием.

Код — на ветке `feat/MIA-88-edu-v3-ml-rating`, MR !280 «Edu v3: mastery levels + рейтинг ученика» (не совпадает с `gitBranchName` из Linear `andreichepurchenko/mia-91-...`, найдено через GitLab API по MR, указанному автором в комментарии). **Важно:** это большой совместный MR — вместе с этой задачей и MIA-89 на той же ветке едет отдельная объёмная фича Edu v3 (ML-блоки, процентный рейтинг, миграция пользователей на v3, 100 новых заданий «найди ошибку» и т.д.), которая тестируется отдельно и в этой заметке не рассматривается. Ниже — только код, относящийся к MIA-91.

Автор отчитался о готовности прямо в задаче (см. `Как проверять` в комментарии) — этот раздел учтён при построении тест-кейсов.

**Статус прогона.** Задача прошла первый QA-прогон (2026-07-30, тест-стенд test-1.mia360.ru, фронт с фичей целиком в задеплоенном чанке `_nuxt/BUcmW2ma.js`). Подавляющее большинство сценариев — PASS, но найден блокирующий дефект адаптива (строка условия в свёрнутом мобильном чате практически не видна) плюс небольшой сопутствующий баг с «зависающей» кнопкой перехода. Статус задачи из-за этого сдвинут в Testing (было Ready for Test). ## Реализация

Ключевые файлы: `frontend/components/trainer/chat-assignment-card.vue` (новый компонент карточки-сообщения), `frontend/components/trainer/chat-messages.vue`, `frontend/pages/trainer/[topicId].vue`, `frontend/components/trainer/chat-header.vue`, `frontend/components/mia-sheet.vue`, `frontend/components/mobile-sheet.vue`, `frontend/components/mobile-sheet-native.client.vue`, `frontend/constants/mia-sheet.ts`.

- **Условие как сообщение Мии.** `assignmentFeedEntries` (`[topicId].vue`) строит синтетические записи по истории взаимодействий: у каждого `interaction` есть `assignmentId`/`assignment.id`, для каждого уникального задания берётся карточка (`trainerSessionStore.topicAssignments` + текущее задание) и добавляется в ленту с флагом `isCurrentAssignment`. Если для текущего задания сообщений ещё не было — запись всё равно добавляется в конец ленты (условие видно сразу, до первого сообщения). `chatFeedMessages` сортирует эти записи вперемешку с обычными сообщениями по времени создания.
- **Залипание условия.** `TrainerChatMessages` рендерит `TrainerChatAssignmentCard` для таких записей; текущему заданию (`isCurrentAssignment`) присваивается класс `chat-messages__assignment--sticky` — `position: sticky; top: 0` внутри скролл-контейнера чата, с градиентной подложкой (чтобы текст под карточкой уходил под затухание, а не резко обрезался).
- **Карточка задания** (`chat-assignment-card.vue`): шапка «ЗАДАНИЕ» + шеврон (шеврон и сворачивание доступны только для текущей залипшей карточки — `isCurrent`; прошлые условия в истории не сворачиваются). Сворачивание — CSS grid-rows транзишен (`1fr` → `0fr`), формула (`MathFormula`/KaTeX) вынесена **отдельным блоком вне сворачиваемой зоны** — то есть при сворачивании условия формула остаётся видна, прячется только текстовая инструкция. Если у задания нет формулы (`expression` пуст) и карточка свёрнута — рядом с шевроном показывается однострочный обрезанный превью текста задания.
- **Задания «найди ошибку».** Если `assignment.kind === 'find_error'`, внутри той же сворачиваемой зоны рендерится нумерованный список шагов предложенного решения (`presentedSolution.steps`) с математикой через KaTeX (тот же парсер дробей/выражений, что и в остальном чате) и подсказка «Найди шаг с ошибкой и объясни в чате, что в нём не так».
- **Кнопка «Следующее задание».** Рендерится внутри `TrainerChatMessages` при `canGoNext` (после ленты сообщений, на всю ширину, с иконкой стрелки), в разметке — как элемент с `key="next-button"` внутри `<TransitionGroup name="msg-appear">`, наравне с сообщениями ленты. Текст меняется на «Завершить тему», когда `isTopicClosed`. По клику эмитит `next` вверх до `nextAssignment()` в `[topicId].vue`, который вызывает **тот же** `trainerSessionStore.nextAssignment(...)`, что и существующая кнопка у доски — отдельной логики перехода не заведено, оба пути идентичны. Аналитическое событие `trainer_task_next` (`ANALYTICS_EVENTS.TRAINER_TASK_NEXT`) шлётся не из обработчика кнопки, а из `watch` на смену `trainerProblem.value.id` — значит сработает одинаково независимо от того, какая из двух кнопок инициировала переход, и ровно один раз на переход. Подтверждено QA-прогоном: аналитика не задваивается ни в чате, ни у доски.
- **Карточка задания слева убрана.** `TaskCard`/`WorkspaceCard` с условием в верхнем левом углу страницы тренажёра из шаблона `[topicId].vue` больше не рендерится (подтверждено QA — 0 совпадений `.task-card`/`.workspace-card` в DOM); вычисляемое `trainerProblem` осталось в коде только для аналитики (`task_id`), на экране не используется.
- **Мобильный peek.** `TrainerChatHeader` получил проп `taskPreview` (`trainerSessionStore.currentAssignment?.task`) — однострочный текст условия под именем Мии (`.chat-header__task-preview`, `white-space: nowrap; text-overflow: ellipsis`). Строка видна только при ширине экрана ≤1024px (`bp.tablet`, `_breakpoints.scss`, `display: none` → `display: block`) — то есть на телефоне/планшете, где чат — выезжающая панель (`mobile-sheet.vue` → `MobileSheetNative` на мобильном, `.ms-panel` на десктопе) и может быть свёрнута в «peek»; на десктопе (боковая панель, всегда открыта) строка скрыта.
  - Peek-высота задаётся константой `MIA_PEEK_PX = 93` (`frontend/constants/mia-sheet.ts`), которую разделяют `mobile-sheet.vue` и `mobile-sheet-native.client.vue`. В `mobile-sheet-native.client.vue` это значение напрямую становится высотой snap-точки «свёрнуто»: `<div slot="snap" :style="{ '--snap': calc(${peek}px + env(safe-area-inset-bottom)) }" class="initial" />` — то есть именно 93px (+ safe-area) физически видимой высоты шапки в состоянии peek, констан­та используется и в расчёте общей высоты шита (`measureContent` → `MIA_PEEK_PX + naturalContentHeight() + footerHeight`). Значение констатнты **не пересматривалось** при добавлении строки `taskPreview` в `chat-header.vue` — она добавлена как ещё одна строка `<p>` под `.chat-header__row`, увеличивая реальную высоту шапки, но `MIA_PEEK_PX` осталась прежней. Это технически подтверждает гипотезу автора QA-комментария о причине дефекта (см. «Открытые вопросы»).
- Кнопка у доски явно **не убрана** — обе кнопки сосуществуют (проверено, что в шаблоне доски переход не тронут).

## Тест-кейсы

**Happy path**
1. Открыть тему в тренажёре → условие текущего задания видно в чате как сообщение Мии, залипшее к верху ленты (карточка «ЗАДАНИЕ»), сразу, даже до первого сообщения ученику. **PASS.**
2. Проскроллить чат вниз (написать/дождаться несколько сообщений) → карточка условия остаётся залипшей к верху ленты чата (десктоп: смещение 24px, высота 125px), остальные сообщения уходят под неё с плавным затуханием фона. **PASS.**
3. Решить задание → нажать «Следующее задание» **в чате** (кнопка на всю ширину под последним сообщением) → в ленте появляется новая карточка условия следующего задания и залипает уже она; предыдущее условие остаётся в истории беседы (не залипшим, доступно скроллом вверх). Кнопка появляется только когда задание зачтено, исчезает на новом нерешённом задании. **PASS.**
4. То же самое, но нажать существующую кнопку **у доски** → переход работает идентично п.3 (общий обработчик). **PASS.**
5. Дойти до последнего задания темы (тема закрывается) → кнопка в чате меняет подпись на «Завершить тему» (и у доски — аналогично, если применимо). **Частично покрыто** — подпись на закрытой теме проверялась только по ветке в коде, глазами не проверена (см. «Не покрыто»).

**Сворачивание карточки**
6. У текущей залипшей карточки нажать шеврон → текстовая инструкция задания сворачивается (121→81px на десктопе), но математическая формула (если есть) остаётся видна. **PASS.**
7. То же самое на задании **без формулы** (просто текст) → при сворачивании рядом с шевроном появляется обрезанное однострочное превью текста задания (`text-overflow: ellipsis`). **PASS.**
8. Прошлые (не текущие) карточки условий в истории беседы — шеврон/сворачивание у них не показывается (не активно), они не залипают. **PASS.**

**Задания «найди ошибку»**
9. Открыть задание типа «найди ошибку» → в карточке условия под текстом виден список шагов предложенного (ошибочного) решения с формулами (KaTeX) и подсказка «Найди шаг с ошибкой…»; свернуть/развернуть карточку → список шагов сворачивается вместе с текстом инструкции. **Не покрыто в этом прогоне** — в теме «Одночлены» есть 10 таких заданий (kind: find_error, mlLevel 3), но выдаются только на ML3/ML5; свежий одноразовый ученик стартует ниже этого уровня, ручки для принудительной установки ML-уровня нет — рендер списка шагов не проверялся вживую.

**Карточка слева**
10. Убедиться, что отдельной карточки задания в левом верхнем углу страницы тренажёра больше нет ни в одном состоянии (открытие темы, переход к следующему заданию, «найди ошибку»). **PASS** — 0 совпадений `.task-card`/`.workspace-card` в DOM на всех проверенных состояниях.

**Адаптив / мобильный**
11. **ИЗВЕСТНЫЙ ДЕФЕКТ (не PASS).** На ширине ≤1024px (планшет/телефон) свёрнутая по умолчанию при входе панель чата (peek) должна показывать читаемую строку условия в шапке — по нюансам задачи «при свёрнутой панели оно должно оставаться доступным». Фактически строка присутствует в DOM с правильным текстом, но обрезана нижним краем экрана: видно только ~4px из ~16px высоты строки на всех трёх проверенных мобильных ширинах:

   | Вьюпорт | Шапка чата (top-bottom) | Строка условия (top-bottom) | Видно от строки |
   |---|---|---|---|
   | 375×812 | 740–841 | 808–824 | 4 px из 16 |
   | 390×844 | 772–873 | 840–856 | 4 px из 16 |
   | 768×1024 (планшет) | 952–1053 | 1020–1036 | 4 px из 16 |

   Читается только «Мия / Сейчас: ожидает», условие приходится доставать разворотом панели. Не деплой и не CSS-правило видимости (строка рендерится, `display:block` по `bp.tablet` отрабатывает на всех трёх ширинах) — причина геометрическая. См. «Открытые вопросы» — гипотеза подтверждена чтением кода: `MIA_PEEK_PX = 93` не пересматривался при добавлении строки `taskPreview` в шапку.
12. На desktop-ширине (>1024px, боковая панель) убедиться, что этой строки-превью в шапке нет — панель и так всегда открыта, условие видно в ленте. **PASS.**
13. Развернуть свёрнутую мобильную панель → чат открывается, скролл сразу на последнем сообщении/залипшей карточке условия. **PASS** (проверялось попутно при снятии геометрии п.11).

**Регресс/пограничные**
14. Перезагрузить страницу посреди темы (после нескольких выполненных заданий) → условия предыдущих заданий по-прежнему видны в истории чата (восстанавливаются из истории взаимодействий), текущее — залипшее. **PASS** формально, но см. наблюдение ниже.
    - **Наблюдение (не блокер).** После перезагрузки лента открывается в начале истории (`scrollTop = 0`): вверху видно условие первого, давно решённого задания, текущее (залипшее) — вне зоны видимости, пока не проскроллишь вниз. Противоречит цели «условие всегда на виду» по духу задачи, но acceptance формально не нарушает (данные корректны, залипание работает после скролла). Стоит рассмотреть автоскролл к текущему заданию при восстановлении из истории.
15. Очень длинный текст условия/много шагов «найди ошибку» — карточка не ломает вёрстку чата, скролл внутри ленты работает. **Не покрыто в этом прогоне отдельно**, косвенно не сломано на обычных заданиях.
16. **Новый тест-кейс — регресс «кнопки-призрака».** После перехода к следующему заданию кнопка «Следующее задание» должна полностью и своевременно уходить из DOM/hit-test, не оставаясь кликабельной в частично-прозрачном виде. Шаги: решить задание → нажать «Следующее задание» → навести курсор в место в ленте, где раньше была кнопка, подождать 20+ секунд. Ожидается: кнопка отсутствует в DOM или, если ещё анимируется, `pointer-events` не активны и по клику ничего не происходит. **Известный дефект найден в этом прогоне** — см. «Открытые вопросы» / «Наблюдения». Кнопка остаётся в DOM в незавершённом leave-состоянии (одновременно классы `msg-appear-enter-from msg-appear-leave-from msg-appear-leave-active`, `opacity: 0`), живёт дольше 20 секунд, при наведении курсора «всплывает» до ~92% непрозрачности, но клик по ней ничего не делает (обработчик неактивен). Воспроизведено 3 раза на тест-стенде.

## Открытые вопросы

1. **Главный дефект (блокер релиза фичи в текущем виде).** Строка условия в свёрнутом (peek) состоянии мобильного/планшетного чата практически не видна — обрезана нижним краем экрана, видно ~4px из ~16px строки на всех проверенных мобильных ширинах (375×812, 390×844, 768×1024). Причина, подтверждённая чтением кода: константа `MIA_PEEK_PX = 93` (`frontend/constants/mia-sheet.ts`) задаёт высоту снап-точки «свёрнуто» в `mobile-sheet-native.client.vue` (`--snap: calc(93px + env(safe-area-inset-bottom))`) и не была пересмотрена, когда в `chat-header.vue` добавили строку `taskPreview` под identity-row. Реальная высота шапки с строкой условия больше видимой части peek — строка физически оказывается ниже границы обрезки. Варианты фикса: увеличить `MIA_PEEK_PX` на высоту добавленной строки, либо переместить превью условия в саму identity-row (не как отдельную строку снизу), либо сузить/уменьшить сам `.chat-header__task-preview` так, чтобы шапка целиком укладывалась в текущие 93px. Требуется решение автора/дизайна перед повторным прогоном.
2. **Сопутствующий баг — «зависающая» кнопка «Следующее задание».** После перехода к следующему заданию кнопка (внутри `<TransitionGroup name="msg-appear">`, `key="next-button"`) не всегда корректно завершает leave-анимацию: в `chat-messages.vue` определены классы `.msg-appear-enter-active/-from` и `.msg-appear-leave-active/-to`, но в проблемном сценарии узел зависает одновременно с классами входа и выхода (`enter-from` + `leave-active`), `transitionend` не приходит, Vue не убирает узел из DOM. Кнопка остаётся кликабельной (частично, ~92% opacity при hover), но обработчик не срабатывает — то есть без визуального бага пользователь тыкал бы в «мёртвую» кнопку. Воспроизведено 3 раза за один QA-прогон, не в 100% случаев — похоже на гонку между быстрым повторным появлением/исчезновением элемента с одинаковым key и незавершённым CSS-transition предыдущего цикла. Нужно воспроизвести с DevTools Performance/Animations открытым для точной диагностики (что именно прерывает transition) и решить: явный `transitioncancel`-фоллбэк, `mode="out-in"`, либо `pointer-events: none` на leave-active как временная защита от кликов вникуда.
3. Сворачивание карточки с формулой оставляет в шапке только заголовок «ЗАДАНИЕ» без превью текста (превью показывается только когда формулы нет) — возможно, ожидаемо, но стоит уточнить у автора/дизайна, не выглядит ли это как «пропавшее» условие для ученика. (Перенесено из прошлой версии заметки, не проверялось отдельно в новом прогоне.)
4. Восстановление скролла чата после перезагрузки страницы — лента открывается с начала истории, а не с текущего (залипшего) задания; см. тест-кейс 14. Не блокер, но стоит рассмотреть автоскролл вниз/к текущей карточке при инициализации из истории.
5. Онбординг-тур показывается заново после каждой перезагрузки, даже если его пропускали — обнаружено в этом прогоне, но не относится к периметру MIA-91 (заведено отдельным наблюдением, не тест-кейсом).
