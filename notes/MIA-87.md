## Контекст

Баг (label `Bug`): кнопка «Подсказка» в тренажёре не выдавала методические (авторские) подсказки из справочника заданий — Мия только сама их генерировала. Причина по тексту задачи: gateway искал authored-подсказки в клиентском payload задания (`interaction.assignment.hints`), а клиент их больше не присылает — это следствие fail-closed выдачи из MIA-83 (до неё канал тоже был ненадёжен: публичная схема уже срезала поле `level`, по которому подсказка матчится). Сама логика выбора подсказки по уровню (MIA-77, `hintLevelForPress`/`hintTextForLevel`) в коде рабочая — сломана была только доставка данных до неё.

Код прочитан на реальной ветке MR !278 — `feat/MIA-87-authored-hints-server-side` (не совпадает с `gitBranchName` из Linear `andreichepurchenko/mia-87-...`, найдено через GitLab API по MR). Дифф маленький и точечный — 3 файла в `socket-gateway` (`handlers/trainer.handler.ts`, `services/trainer.prompt.ts` + тест). Согласно `relatedTo` в Linear, связан с MIA-77 (лестница подсказок) и MIA-83 (причина поломки).

## Что было сломано

`createHintRequestPrompt` в `trainer.prompt.ts` брал авторские подсказки из `interaction.assignment?.hints` — поля клиентского payload задания, которое шлёт браузер вместе с запросом подсказки. После fail-closed изменений MIA-83 клиент это поле больше не получает (или получает без `level`, по которому идёт матчинг) — `hintTextForLevel` всегда возвращала `null`, и промпт подсказки уходил без блока «есть готовая подсказка этого уровня», так что Мия для любого задания генерировала подсказку сама, даже если в справочнике была авторская.

## Что изменено (по коду)

Сверено diff'ом с базовой веткой (коммит `fd7c667`, файлы `trainer.handler.ts` / `trainer.prompt.ts`):

1. **`trainer.handler.ts`**, ветка `isRequestHint`: перед сборкой промпта подсказки, если у `interaction.assignment.id` есть значение, gateway дергает `aiMathApi.getAssignment(id)` — внутренний серверный роут (`/internal/assignments/:id`, тот же, что уже использует грейдинг решений в этом файле для `answer`) — и берёт `fullAssignment.hints`. Результат (`authoredHints`) прокидывается в `createHintRequestPrompt` пятым аргументом.
2. Если запрос к API упал (ошибка/таймаут) — `catch` логирует warning (`failed to fetch authored hints, falling back to generated hint`) и `authoredHints` остаётся `null` — код продолжает работу, поведение как раньше (генеративная подсказка), без пробрасывания ошибки пользователю.
3. **`trainer.prompt.ts`**, `createHintRequestPrompt`: добавлен параметр `authoredHints`; матчинг подсказки по уровню теперь `hintTextForLevel(authoredHints ?? interaction.assignment?.hints, level)` — приоритет у серверных данных, старый путь через клиентский payload оставлен как fallback (сейчас фактически мёртвый, раз клиент `hints` не присылает, но не мешает).
4. Секреты по-прежнему не утекают клиенту: `authoredHints` идёт только в текст `instructions` промпта (инструкция модели), а `interaction.assignment` (клиентская копия, которая эмитится обратно в `TRAINER_INTERACTION_REPLACE`) не модифицируется — это отдельно проверено тестом (`captured.prompt?.assignment?.hints` остаётся `[]`).
5. Уровень подсказки определяется как раньше: `hintLevelForPress(pressCount)` = `trunc(repeatCount)` зажатый в `[1, MAX_HINT_LEVEL=3]`; `repeatCount` приходит от API (`trainerInteraction.repeatCount`) — растёт при повторных нажатиях «Подсказка» на одном задании (логика MIA-77, в этом MR не менялась).

## Как перепроверить

Основной сценарий (из комментария автора к задаче):
1. Взять задание темы, у которой в справочнике заданы авторские подсказки (уровни 1–3) — см. MIA-86 (эталонное решение/справочник) или спросить методиста, у какой темы уже заведены подсказки. Открыть задание в тренажёре.
2. Нажать «Подсказка» — **ожидаемо:** текст подсказки по смыслу совпадает с уровнем 1 из справочника (Мия может слегка адаптировать формулировку, но не должна добавлять шагов сверх неё; не должна называть сам ответ).
3. Нажать «Подсказка» повторно (на том же задании, без отправки решения) — уровень должен вырасти до 2, третье нажатие — до 3 (сверить текст с справочником для каждого уровня).
4. Проверить в DevTools/Network или в WS-сообщениях: поле `hints` в assignment, который приходит клиенту (`TRAINER_INTERACTION_REPLACE`/`TRAINER_INTERACTION_RECEIVE`), по-прежнему пустое/отсутствует — секрет не должен утечь через сам факт починки доставки (регресс на MIA-83).
5. Задание **без** авторских подсказок в справочнике — поведение прежнее: Мия генерирует подсказку сама, содержание меняется от уровня к уровню (уровень всё ещё растёт по числу нажатий).

Что посмотреть рядом (регресс):
6. Отключить/уронить доступность API на время (если есть тестовый способ, напр. через сетевой троттлинг internal-роута) — при ошибке обогащения подсказка должна упасть в тот же генеративный фолбэк, без ошибки в чате и без зависания «Подсказка»-кнопки (проверено юнит-тестом `falls back to a generated hint when assignment enrichment fails`, стоит один раз перепроверить вживую).
7. Другие типы взаимодействий в чате тренажёра, не тронутые этим MR, но идущие через тот же хендлер — «Теория», «Пример», «Шаги», обычная отправка решения (whiteboard/чат) — не должны были измениться (диффа в их ветках нет).
8. Задание с `id` отсутствующим у `interaction.assignment` (маловероятный edge-case) — код просто не делает запрос к API (`if (payload.interaction.assignment?.id)`), подсказка сгенерируется как раньше без похода в справочник.

## Аналитика/API

Отдельного аналитического события на эту фичу не заводится (в `analytics-events.ts` изменений в MR нет). Из API-специфики — на удобство ручной проверки нет отдельного эндпоинта; сверка справочных подсказок делается через админку/справочник заданий (см. заметку MIA-86) либо напрямую в БД, если доступ есть у тестировщика.

## Открытые вопросы

- Нужно заранее знать/подобрать конкретное задание с заполненными authored-подсказками для уровней 1–3, иначе основной сценарий не проверить наглядно — стоит уточнить у автора/методиста id темы или задания для теста.
- Комментарий автора называет MR влитым («смержен») — при проверке важно попасть на сборку стенда, где этот MR уже задеплоен (автодеплоем, ~10 мин после мержа по комментарию); если подсказки всё ещё генеративные при наличии авторских — вероятно, стенд ещё не обновился, а не регресс.
