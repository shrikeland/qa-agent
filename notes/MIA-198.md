Нет отдельного MR — влито напрямую двумя коммитами в master (ветка `andreichepurchenko/mia-198-polosa-nad-doskoi-ne-hovorila-chto-ostalos-sdelat`): `3335d1ef` (основной фикс полосы) и `057795fa` (донастройка: снятие цели вместе с потраченным шорткатом + сжатие длинных подписей). Комментариев в Linear кроме исходного описания нет.

## Контекст

Полоса над доской в тренажёре показывала одну неизменную строку-цель вида «нужно 8 из 10» — тот же текст, что и в окне точности блока, но без самих клеток окна и без пояснения, которые есть рядом в чате. Строка не менялась несколько задач подряд, не говорила ученику, где он сейчас находится (сколько верных подряд ещё нужно), и через точку соседствовала с условием задачи, из-за чего читалась как часть самого задания. Отдельно: когда блок был исчерпан (задач на чистое окно уже не хватит) или потрачен ML1-шорткат (добит до нуля), полоса продолжала называть цель, которую уже не обещает, либо предлагала «можно перескочить» рядом с «цель достигнута».

## Что изменено

Код прочитан по коммитам `3335d1ef` и `057795fa` (полные diff).

**Общая логика (`frontend/cabinet/chat/task.ts`, `toCabinetTaskProgress`).** Это единственная функция, откуда берут формулировки и чат (окно точности с клетками), и полоса над доской — вычисление стадии (`stage`) сделано один раз и используется для всех выходных полей, поэтому у чата и доски физически не может разойтись текст:
- Стадии: `probe-one`/`probe-two` (шорткат ещё активен, осталось 1 или 2 чистых попытки), `done` (цель достигнута — включая шорткат, добитый до нуля), `exhausted` (задач на чистое окно уже не хватит), `one` (осталась 1 попытка), `streak` (осталось N > 1).
- Новые поля `CabinetTaskProgress.short` (короткая фраза для полосы доски: «Ещё 3 верных подряд», «Ещё одна без ошибок», «Цель достигнута», «Остались последние задачи» и т.п., словарь `SHORT`) и `shortGoal` (приглушённая пара рядом: `Блок N · нужно X из Y` или `Блок N · хватит 2 без ошибок`; для `exhausted` — только `Блок N`, без цели, коммит `3335d1ef`).
- `note` (длинная формулировка для чата) и `badge` («Можно перескочить») переведены на ту же `stage`; `badge` пуст на стадиях, отличных от `probe-one`/`probe-two`.
- Коммит `057795fa` донастраивает `goal` (и, соответственно, `shortGoal`): раньше `goal` вычислялся отдельно от `stage` и при потраченном до нуля шорткате (`stage === 'done'` из-за `probeLeft`) всё ещё показывал `хватит 2 без ошибок` — то есть бейдж уже снимался, а цель рядом продолжала называть шорткат правилом закрытия. Теперь `goal` берётся из того же `stage`: `stage === 'probe-one' || stage === 'probe-two' ? 'хватит 2 без ошибок' : 'нужно X из Y'` — при исчерпанном шорткате полоса и бейдж, и цель одновременно возвращаются к обычной цели блока.

**Полоса над доской (`frontend/cabinet/board/board-strip-vals.ts`, `frontend/cabinet/board/board-host.ts`, `frontend/cabinet/shell/use-cabinet.ts`, `frontend/components/cabinet/board/board.vue`):**
- `boardStripVals()` вместо старого `goal: string | null` принимает `blockStatus: { label: string; goal: string } | null`; `boardStripLabel` берёт `blockStatus.label` (было — статичный `goal` или «Задача N»), новое поле `boardStripGoal` — `blockStatus.goal` (в диагностике/тесте всегда `''`, цель блока к тесту не липнет).
- `use-cabinet.ts`: `blockStatus: liveProgress ? { label: liveProgress.short, goal: liveProgress.shortGoal } : null` — то самое место, где полоса доски подключена к общей логике `task.ts`.
- `board.vue`: рядом с `boardStripLabel` (остаток работы, слева) добавлен `<span v-if="v.boardStripGoal" class="cabinet-board__strip-goal">` — приглушённая пара («Блок 2 · нужно 8 из 10»), стилизована отдельным приглушённым цветом `$cabinet-text-faint`, capsом (`text-transform: uppercase`, `letter-spacing`) — видима постоянно, не через `title`/hover (на телефоне доска — основная поверхность, `title` там не показывается вовсе).
- **Обрезание длинных подписей** (коммит `057795fa`): `&__strip-label` и `&__strip-goal` в `board.vue` получили `min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap` вместо старого `flex-shrink: 0` — раньше подписи были короткими парой слов и не сжимались; когда `label`/`goal` стали полноценными фразами, несжимаемый элемент шире полосы обрезался overflow'ом полосы целиком без многоточия («обрубок»), теперь каждая подпись сжимается сама и обрезается многоточием.

## Как перепроверить

Тренажёр (не диагностика/тест — там полоса не участвует, см. регресс ниже), телефон и десктоп.

1. Открыть занятие с открытым блоком, решить подряд несколько задач с верными ответами. Ожидается: строка над доской слева меняется по ходу решения («Ещё 3 верных подряд» → «Ещё 2 верных подряд» → «Ещё один верный ответ»), а не стоит неизменной; рядом справа/снизу видна приглушённая пара «Блок N · нужно X из Y» — как отдельный, всегда видимый текст, без наведения и без долгого тапа (title).
2. Сверить формулировку полосы с формулировкой в чате (окно точности рядом с сообщением Мии, поле `note`/`goal`) на той же самой задаче — они должны описывать одно и то же состояние блока (общий источник — `toCabinetTaskProgress`), расхождений в цифрах быть не должно.
3. **Исчерпанный блок** (осталось меньше задач, чем нужно для чистого окна — стадия `exhausted`): полоса показывает «Остались последние задачи», рядом с ней — только «Блок N» без цели («нужно X из Y» не показывается, лишнего обещания нет).
4. **ML1-шорткат.** Пока шорткат активен (осталось 1-2 чистых попытки): в полосе «Ещё одна/две без ошибок», рядом — «Блок N · хватит 2 без ошибок», где-то виден бейдж/предложение «Можно перескочить». Добить шорткат до нуля (дать ошибку либо закрыть окно): полоса переходит на «Цель достигнута», цель рядом — снова «Блок N · нужно X из Y» (обычная цель блока, не «хватит 2 без ошибок»), предложения перескочить рядом больше нет.
5. **Длинная подпись.** На узком экране (телефон/уменьшенное окно) с длинным именем блока/большими числами убедиться, что подпись обрезается многоточием и не вылезает за край полосы, не наезжает на условие задачи и не разрывает layout.
6. Десктоп — то же самое (пп. 1–5), полоса не должна вести себя иначе, чем на телефоне.

## Что посмотреть рядом (регресс)

- Диагностика/тест: `boardStripGoal` должен оставаться пустым, `boardStripLabel` — своей подписью теста («Задача N из M»), цель блока к тестовой полосе не должна прилипать (это отдельная ветка в `boardStripVals`, `diag ? ... : ...`).
- Именно это чинили в задаче — после фикса стоит специально проверить, что текст в чате (окно точности, `note`/`goal`) и текст на полосе доски (`short`/`shortGoal`) не разошлись на каких-то пограничных состояниях (последняя попытка, только что открытый блок, переход между блоками) — обе строки читаются из одной `stage`, но стоит прогнать несколько раз вручную, а не полагаться только на юнит-тесты.
- Переход между блоками (закрытие текущего блока и открытие следующего) — полоса должна сразу переключиться на цель нового блока, а не показать на секунду цель уже закрытого.
- Клетки окна точности в чате не были частью этого фикса — стоит мельком свериться, что они по-прежнему соответствуют реальному прогрессу окна, независимо от текста полосы над доской.
