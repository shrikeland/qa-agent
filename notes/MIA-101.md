## Контекст

Фича (без лейбла, наблюдаемость/инфраструктура): по каждому запросу к AI теперь пишется длительность и исход (успех/таймаут/ошибка), а неудачные попытки тоже попадают в учёт — раньше это было видно только частями (у проверки решения с доски — в базе, у чата — в метриках без привязки к ученику, у вызовов из api — приветствие/память/отчёт родителю — вообще никак), а таймауты были заметны только через грепанье логов контейнера.

Повод — генерация приветствия ученику: медиана 2,9 с при лимите 3 с, каждый четвёртый вызов не укладывается и ученик получает шаблон вместо персонального приветствия.

MR !306 «MIA-101: длительность и исход каждого запроса к AI» (коммит `88f76df`, влит в master коммитом `159bc79`) — уже в master, читал по коммиту.

Из скоупа задачи алерт «доля таймаутов выросла» в этот MR не входит — по последнему комментарию автора, он настраивается вручную на monitoring-хосте и только после того, как метрика доедет до прода. На тестовом стенде это не проверяемо.

## Реализация

Ключевые файлы: `api/prisma/schema.prisma` + миграция `20260730060000_ai_usage_duration_status`, `api/src/services/ai-usage/ai-usage.types.ts`, `api/src/services/ai-usage/ai-usage.service.ts`, `api/src/services/openai/openai-responses.client.ts`, `api/src/services/memory/greeting-ai.service.ts`, `api/src/services/memory/memory-extraction.service.ts`, `api/src/services/parent-report-ai.service.ts`, `api/src/services/parent-report.service.ts`, `api/src/metrics.ts`, `api/src/routes/internal.routes.ts`, `api/src/admin/ai-cost.service.ts`, `frontend/pages/admin/ai-cost/index.vue`, `frontend/composables/use-admin-format.ts`, `socket-gateway/src/helpers/ai-usage.helper.ts`, `socket-gateway/src/sockets/streams/conversation.stream.ts`, `socket-gateway/src/sockets/streams/recognition.stream.ts`, `socket-gateway/src/types.ts`.

- **Схема.** `ai_usage` получила `duration_ms` (nullable) и `status` (`TEXT NOT NULL DEFAULT 'ok'`) + индекс `(status, created_at)`. Дефолт и nullable — специально, чтобы блю-грин деплой не требовал простоя и старый код продолжал писать строки без изменений (комментарий в миграции это явно фиксирует).
- **`ai-usage.types.ts`.** `usage` стал `NormalizedUsage | null` (null — вызов, который не успел вернуть usage: таймаут/ошибка); добавлены `status: 'ok' | 'timeout' | 'error'` и `durationMs`.
- **`ai-usage.service.ts` → `record()`.** При `usage: null` в БД пишутся нулевые токены и `costUsdMicros: null`, но метрика `aiUsageMissingPriceTotal` (алерт «нет цены для модели») больше **не** срабатывает — иначе она бы стреляла на каждый таймаут провайдера (проверено тестом «does not report a missing price for a request that never produced usage»). Если передан `durationMs` — гистограмма Prometheus `ai_request_duration_seconds{kind, model, status}` (новая, `api/src/metrics.ts`) получает наблюдение.
- **`openai-responses.client.ts` → `call()`.** Раньше возвращал `ResponsesResult | null`, теперь — `ResponsesOutcome`: `{ ok: true, durationMs, ...ResponsesResult }` либо `{ ok: false, status: 'timeout' | 'error' | 'skipped', durationMs }`. `'skipped'` — нет `OPENAI_API_KEY`, запроса вообще не было, писать в учёт нечего. Таймаут отличается от прочих ошибок по `err.name` (`TimeoutError`/`AbortError` от `AbortSignal.timeout`), всё остальное — `'error'`.
- **`greeting-ai.service.ts` и `memory-extraction.service.ts`.** Оба симметрично обрабатывают `!outcome.ok`: если `status !== 'skipped'` — пишут в `aiUsageService.record` с `usage: null`, реальными `status`/`durationMs`; на успехе — как раньше, плюс `status: 'ok'` и `durationMs`.
- **`parent-report-ai.service.ts` (`requestSummary`) и `parent-report.service.ts`.** Не симметрично двум предыдущим: при `!outcome.ok || !outcome.text` метод просто возвращает `null` — `durationMs`/`status` неудачного вызова теряются и никуда не пишутся; `aiUsageService.record` в `parent-report.service.ts` (3 места) вызывается только в ветке успеха (`status: 'ok'` добавлен туда). См. «Открытые вопросы» — похоже на тот же класс пробела, что чинили у greeting/memory до этого MR, только тут он остался.
- **Чат и распознавание (потоковые, `socket-gateway`).** `ConversationStream`/`RecognitionStream` уже имели `startedAt: Date`; `recordStreamAiUsage` (`ai-usage.helper.ts`) теперь считает `durationMs = Date.now() - stream.startedAt.getTime()` и пишет `status: 'ok'` — но только когда есть `endPayload`. `finish(endPayload?)` вызывается двумя путями: на штатном завершении (`STREAM_END`, `endPayload` есть) и на `abort()`/ошибке прокси (`this.finish()` без аргумента, `endPayload === undefined`). `recordStreamAiUsage` в самом начале делает `if (!endPayload) return;` — то есть путь таймаута/обрыва потока для чата и распознавания вообще ничего не пишет в `ai_usage` (см. «Открытые вопросы»).
- **`internal.routes.ts` (`aiUsageBodySchema`).** Приняты новые опциональные поля `status` (enum) и `durationMs`; `usage` теперь тоже допускает `null` в теле запроса.
- **Админка, `ai-cost.service.ts` → `dashboard()`.** SQL по `bySurfaceKind` считает `COUNT(*) FILTER (WHERE status = 'timeout')` как `timeouts` и `percentile_cont(0.5|0.95) WITHIN GROUP (ORDER BY duration_ms)` как `p50Ms`/`p95Ms` (округлены `Math.round`, `null` → 0, если все `duration_ms` в периоде пустые — старые строки).
- **`frontend/pages/admin/ai-cost/index.vue`.** У каждой строки surface×kind справа от полосы добавлена колонка `secs(p50Ms) / secs(p95Ms)` (`X.X с`, одна цифра после запятой) с `title`-подсказкой («Медиана N мс, 95-й процентиль N мс, таймаутов N»); если `p50Ms` falsy (0 — нет записей с длительностью в периоде) — вместо чисел прочерк `-`. Если `timeouts > 0` — рядом красным (`var(--c-pulse)`) бейдж «N таймаут.». Новые подписи: surface `memory` → «Память», kind `ocr` → «Распознавание (OCR)», `greeting` → «Приветствие», `parent_report` → «Отчёт родителю», `memory_extraction` → «Память о ученике».
- `frontend/composables/use-admin-format.ts` — тип `AiCostDashboard.bySurfaceKind` расширен полями `timeouts`/`p50Ms`/`p95Ms` (сихронно с бэкендом).
- OCR (`mathpix.service.ts`, `whiteboard-photo.service.ts`, kind `ocr`) этим MR не тронут — по-прежнему без `durationMs`/`status`, что и было до задачи (в скоупе тикета явно называлась только тройка «приветствие, память, отчёт родителю»).

## Тест-кейсы

### Happy path
1. **Успешный вызов приветствия.** Зайти в тренажёр свежим учеником (`cohort: 'memory'`, есть `contextBlock`) → сгенерировать приветствие → открыть Админка → AI-расходы за сегодня → у строки «Приветствие» (surface «Тренажёр»/«Диагностика» + kind «Приветствие») в новой колонке должны появиться два числа вида «X.X с / Y.Y с» (медиана/p95), а не прочерк.
2. **Чат и распознавание (успех).** Пройти обычный диалог в тренажёре (несколько сообщений) и/или отправить фото на распознавание вайтборда → в дашборде у kind «Чат» и «Распознавание (OCR)» / «Распознавание» тоже должны появиться заполненные времена.
3. **Округление и формат.** Числа в колонке времени — с одним знаком после запятой («2.9 с»), не «2.9000000001 с» и не целые секунды без дробной части, если исходно доли секунды значимы.
4. **Пустая история / старые записи.** Если в выбранном периоде для какого-то surface×kind нет ни одной строки с заполненным `duration_ms` (например, весь период — до миграции) — колонка показывает `-`, без `NaN`/`0.0 с`/визуальных артефактов.
5. **Переключение периода (7d/30d/mtd).** Смена периода над таблицей не ломает новые колонки ни при наличии, ни при отсутствии данных за выбранный период.

### Таймаут — ключевой сценарий тикета
6. **Таймаут приветствия.** Спровоцировать таймаут вызова приветствия (например, временно уронить/задержать прокси на тестовом стенде дольше лимита) → в `ai_usage` должна появиться строка `status='timeout'`, без токенов и стоимости, но с `duration_ms`; в дашборде у «Приветствие» — красный бейдж «N таймаут.» рядом с временами, и `calls` для этого kind вырос (неудачный вызов теперь учитывается, а не пропадает).
7. **Таймаут памяти (`memory_extraction`).** Аналогично п.6 для извлечения памяти — красный бейдж и время должны появиться у kind «Память о ученике».
8. **Таймаут/обрыв чата или распознавания (регресс-проверка находки ниже).** Спровоцировать таймаут/обрыв потока в чате тренажёра (не отвечать от AI-прокси дольше `AiStreamAutoAbortTimeout`) → по описанию задачи ожидание, что это тоже попадёт в учёт с исходом «таймаут»; по прочтению кода (`ConversationStream.abort()` → `finish()` без `endPayload` → `recordStreamAiUsage` выходит раньше проверки статуса) ожидаю, что в `ai_usage` вообще НЕ появится новая строка и счётчик «N таймаут.» у kind «Чат»/«Распознавание» не изменится — стоит воспроизвести вживую и подтвердить/опровергнуть эту гипотезу отдельно, это расхождение с заявленной целью задачи.
9. **Отчёт родителю — таймаут/ошибка (вторая находка, см. ниже).** Спровоцировать сбой генерации отчёта родителю (таймаут провайдера) → по коду (`parent-report-ai.service.ts`) неудача просто возвращает `null`, `aiUsageService.record` в этой ветке не вызывается вовсе → ожидаю, что строка в `ai_usage` не появится и «Отчёт родителю» в дашборде не покажет таймаут, хотя задача прямо называла отчёт родителю в числе трёх вызовов, которые «не измеряются вовсе». Перепроверить вживую.

### Регресс / совместимость
10. **Обратная совместимость деплоя.** Существующие (старые) записи `ai_usage`, созданные до миграции — `duration_ms IS NULL`, `status = 'ok'` (дефолт колонки) — не ломают ни дашборд (не считаются как таймауты), ни расчёт медианы/p95 по свежим данным.
11. **Приветствие всё ещё показывается ученику при успехе** — фикс наблюдаемости не должен был задеть сам happy path генерации приветствия (текст, персонализация).
12. **Стоимость (`usd`) и число вызовов (`calls`) в дашборде считаются как раньше** — новые колонки добавлены, а не заменили существующие метрики затрат.

## Аналитика/API

- Пользовательских аналитических событий фича не добавляет — это внутренняя админ-метрика; проверять в `frontend/constants/analytics-events.ts`/`api/src/constants/analytics-events.ts` нечего.
- `POST /internal/ai-usage` (`internal.routes.ts`) — тело теперь допускает необязательные `status` (`ok`/`timeout`/`error`) и `durationMs`, а `usage` — `null`; старые вызывающие без этих полей по-прежнему обязаны проходить валидацию как раньше (регресс несовместимости схемы).
- Prometheus: `ai_request_duration_seconds{kind, model, status}` — если есть доступ к `/metrics` на стенде, можно свериться с цифрами из БД отдельно.

## Открытые вопросы / код-наблюдение (не блокеры, но стоит перепроверить вживую до закрытия задачи)

1. **Таймаут/обрыв чата и распознавания не пишется в `ai_usage`.** `ConversationStream.abort()` и обработчик ошибки прокси зовут `this.finish()` без `endPayload`; `recordStreamAiUsage` делает `if (!endPayload) return;` в самом начале — значит `status`/`durationMs` для этого пути никогда не вычисляются и не отправляются. Итог: пункт задачи «неудачные попытки тоже попадают в учёт» для чата и распознавания на практике не выполняется, только для приветствия и памяти. Возможно, это осознанно оставлено на следующий шаг — стоит уточнить у автора и воспроизвести вживую (см. тест-кейс 8).
2. **Неудачный вызов `parent_report` тоже не попадает в учёт.** `parent-report-ai.service.ts:requestSummary` при `!outcome.ok` возвращает `null`, теряя `durationMs`/`status`; `parent-report.service.ts` пишет `aiUsageService.record` только там, где `summaryResult` не `null` (успех). Тот же класс пробела, что чинили у greeting/memory_extraction в этом же MR, здесь не закрыт (см. тест-кейс 9).
3. **Алерт на рост доли таймаутов не в этом MR.** По словам автора — ручная настройка на monitoring-хосте после выхода метрики на прод; на тестовом стенде не проверяем, отдельный acceptance-пункт задачи закрыть тестированием сейчас нельзя.
