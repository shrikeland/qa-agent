# MIA-101: тайминги AI-запросов — длительность, исход и алерт на таймауты

## Контекст

До фичи длительность и исход AI-запроса были видны только частями: у проверки решения с доски — в базе, у чата — в метриках без привязки к ученику, у вызовов из api (приветствие, память Мии, отчёт родителю) — вообще никак. Неудачные вызовы (таймаут/ошибка) не попадали в учёт совсем, поэтому нельзя было увидеть, что медиана генерации приветствия (2.9 с) стоит на грани лимита в 3 с и каждый четвёртый вызов срывается в шаблон.

Первый MR (!306, `feat/MIA-101-ai-request-timings`, коммит `88f76dff`) завёл тайминги/исход в общем учёте и на дашборде `/admin/ai-cost`. QA-прогон 31.07 нашёл три расхождения — все три (разрез по ученику, видимость `error`, запись неудачи отчёта родителю) закрыты коммитами `d33f70fb`/`f5bde952`. QA-прогон 18–20.08 (после `master@2793ba2f`) подтвердил все три закрытыми, но нашёл два новых пробела в «неудачные попытки попадают в учёт»: автоаборт распознавания по таймауту и `kind='ocr'` не пишет `durationMs`.

Это четвёртый раунд. Оба пробела round 3 исправлены в MR !346 (коммиты `d4b6215d`, `6a57d960`), подтверждено чтением кода — см. «Реализация». Побочно в том же MR закрыты три смежные находки, которые вскрылись при работе над основным фиксом:
- **Ступень бесплатной тысячи `mathpix-strokes`** считалась как `count(model = 'mathpix-strokes')` без фильтра по исходу — начни писать неудачи, каждая съедала бы слот бесплатного лимита и сдвигала последующие сессии в платный диапазон. Теперь считаются только `status = 'ok'`.
- **Классификация `AbortError` в `mathpixFetch`.** Каждый вызов Mathpix ограничен своим `AbortController` (8 с, 15 с для страниц), и срабатывание таймаута приходит обычным реджектом, неотличимым от прочих ошибок без разбора `err.name === 'AbortError'`. Без этого разбора колонка таймаутов у `ocr` осталась бы вечно нулевой — все сбои шли бы как `error`.
- **`res.json()` вне `try`.** В `createStrokesSession` разбор ответа не был обёрнут в `try/catch` — ответ `200` с не-JSON телом не оставлял записи в `ai_usage` вовсе. Теперь обёрнут.

Ветка задачи (`fix/MIA-101-ai-usage-failed-ocr-and-abort`) смержена и удалена — ожидаемо, как и в прошлых раундах. Код читан из отдельного worktree на финальном коммите MR (`6a57d960`, включает `d4b6215d` как предка): `/tmp/worktrees/MIA-101`.

## Реализация

Проверено чтением файлов на `6a57d960` (worktree `/tmp/worktrees/MIA-101`).

**Закрыто (round 1–2, подтверждено на round 3–4).**
- Чат и распознавание (`socket-gateway`): `socket-gateway/src/helpers/ai-usage.helper.ts` → `recordStreamAiUsage`/`recordFailedCall` пишет запись без `usage`/стоимости, но с `status`/`durationMs`, когда `finish()` вызван с `failure`.
- Отчёт родителю: `api/src/services/parent-report.service.ts` → `recordParentReportUsage` зовётся безусловно, неуспех (`status: 'timeout' | 'error'`) попадает в `ai_usage`. Единственный случай без записи — `status === 'skipped'` (не задан ключ провайдера).
- Разрез по ученику: `api/src/admin/ai-cost.service.ts` → `breakdownForParent` отдаёт `p50Ms`/`p95Ms`/`timeouts`/`errors` по `surface`/`kind`. `frontend/components/admin/admin-user-ai-cost.vue` — колонка «Медиана / 95%», бейджи таймаутов/ошибок (строки 78–79), тултип со всеми четырьмя цифрами (строка 74).
- Исход `error` виден в UI: и в карточке ученика, и на общем дашборде (`frontend/pages/admin/ai-cost/index.vue`).

**Закрыто round 4 (было открыто в round 3).**

1. **Автоаборт распознавания теперь пишет исход.** `socket-gateway/src/sockets/streams/recognition.stream.ts:129-135`, метод `abort()`:
   ```ts
   async abort() {
     logger.warn({ msg: 'RecognitionStream.abort - stream timed out', streamId: this.id });
     this.unbind();
     if (!this.finishedAt) {
       await this.handlers.abortStream(this.prompt!, this.id);
       this.finish(undefined, 'timeout');
     }
   }
   ```
   Симметрично `conversation.stream.ts:165-175`, куда сверялись в прошлом раунде — оба теперь зовут `finish(undefined, 'timeout')`. Проверено также, что это не смешивает разные состояния: `abort()` достижим только из авто-таймера (`AiStreamAutoAbortTimeout` = 120 с) и из ручного контроля зависшего провайдера — оба значат «провайдер завис». Уход ученика со страницы (`recognition.pool.ts:120-125`, `conversation.pool.ts` — `abortStreamsForUser`) по-прежнему зовёт `finish()` без `failure` и следа в `ai_usage` не оставляет — это подтверждено чтением кода как осознанное, не регресс.
   Тест на ветку: `socket-gateway/src/sockets/streams/__tests__/stream-abort-usage.test.ts` (новый) — покрывает оба канала (`recognition` и `chat`) одним и тем же сценарием `stream.abort()`, проверяя `status: 'timeout'`, `usage: null`, корректный `kind`.

2. **`kind='ocr'` теперь пишет `durationMs` и `status` во всех трёх местах.**
   - `api/src/services/mathpix.service.ts:94-161` (`createStrokesSession`, модель `mathpix-strokes`): `startedAt`/`recordUsage(responseId, status)` считает `Date.now() - startedAt`, вызывается на всех трёх исходах (сетевая ошибка/таймаут — строка 136, `!res.ok` — строка 142, ошибка `res.json()` — строка 150, успех — строка 154). Добавлена функция `mathpixFailureStatus(err)` (строка 56): `AbortError` → `'timeout'`, всё остальное → `'error'`.
   - `api/src/services/whiteboard-photo.service.ts:46-93` (`createFromUpload`, модель `mathpix-text`): `ocrStartedAt`/`ocrDurationMs`, `ocrStatus` теперь выставляется через `mathpixFailureStatus(err)` в `catch` (было — ранее `record(...)` в этом файле вообще не передавал `durationMs`).
   - `api/src/services/homework/homework.service.ts:473-499` (`_readPageLines`, модель `mathpix-text`): было даже хуже, чем «нет `durationMs`» — вызов `aiUsageService.record(...)` стоял только внутри `try`, и неудачное распознавание (`catch`) вообще не писало ничего в `ai_usage`. Теперь `record(status)` вызывается на обоих путях: `record('ok')` в `try`, `record(mathpixFailureStatus(error))` в `catch`.
   Во всех трёх местах на неуспехе `usage: null` → `cost_usd_micros = null` (нет токенов и стоимости за незавершённый запрос).

**Общее поведение (проверить как регресс):**
- `p50Ms`/`p95Ms` = 0 (или отсутствие данных) рендерится как `-`, а не `0.0 с` — важно для старых записей до миграции (`duration_ms = NULL`).
- Доля таймаутов/ошибок считается одним SQL-запросом (`COUNT(*) FILTER (WHERE status = 'timeout' | 'error')`), без похода в логи.
- **Перцентили теперь с `FILTER (WHERE status = 'ok')`** — это меняет находку прошлого раунда («не блокер, но искажает картину»): `api/src/admin/ai-cost.service.ts`, обе SQL-выборки (`breakdownForParent` строки 92–95, `dashboard` строки 177–180) считают `percentile_cont` только по успешным вызовам. Подтверждено в `ai-cost.service.test.ts` (строка 41: ровно два вхождения `FILTER (WHERE au.status = 'ok')` в SQL). Новое наблюдение автора, стоит проверить отдельным тест-кейсом: **у фичи, где все вызовы за период неуспешны, `p50`/`p95` теперь дают прочерк** (успешной длительности там нет) — раньше в этом случае показывалась «медиана» из проваленных попыток (например, ровно `TIMEOUT_MS`), что вводило в заблуждение сильнее, чем прочерк.
- Склонение `N таймаут.` / `N ошиб.` заменено на `pluralWith` (`frontend/utils/plural.ts`, реэкспорт из `use-admin-format.ts`) в обоих местах (`admin-user-ai-cost.vue:78-79`, `ai-cost/index.vue:392-393`): формы `['таймаут', 'таймаута', 'таймаутов']` / `['ошибка', 'ошибки', 'ошибок']` — по коду `pluralWith` при `n=5` действительно даёт третью форму, т.е. «5 таймаутов» / «5 ошибок», не «5 таймаут.».
- Алерт на рост доли таймаутов — **вне поставки этого тикета**, настраивается отдельно на monitoring-хосте после того, как метрика доедет до прода.

## Тест-кейсы

### Приоритет: закрытые в round 4 пробелы — перепроверить

1. **Автоаборт распознавания попадает в учёт.** Спровоцировать зависание `recognition`-стрима на 120+ с (решение фото/текстом с недоступным/подвешенным ai-proxy). Если недостижимо руками на стенде — свериться по юнит-тесту `stream-abort-usage.test.ts` (кейс «recognition: a stream the provider left hanging lands in ai_usage as a timeout»), написанному до правки: по описанию автора recognition был красным, chat — зелёным.

3. **Свежий успешный OCR показывает тайминги.** Пройти happy path по всем трём OCR-путям: `whiteboard-photo` (доска), `mathpix-strokes` (рукописный ввод, если доступен на стенде), `homework` (загрузка фото домашки).

### Новые тест-кейсы на побочные фиксы round 4

4. **Счётчик бесплатной тысячи `mathpix-strokes` учитывает только успешные вызовы.** Спровоцировать несколько неудачных `createStrokesSession` (плохой ключ/сеть) в текущем месяце, затем — успешный.
   Ожидание: неудачные вызовы не двигают счётчик бесплатного лимита — `priorStrokesSessionsThisMonth` в `computeCostUsdMicros` считает только `status='ok'` (`api/src/services/ai-usage/ai-usage.service.ts:25-32`); успешная сессия после серии неудач всё ещё попадает в бесплатную тысячу, если реальных успешных сессий в месяце меньше 1000.
5. **Перцентили с `FILTER` считают медиану только по успешным.** На окне со смешанными исходами одной фичи (несколько `ok` разной длительности + один `timeout`) свериться, что `p50Ms`/`p95Ms` не включают длительность таймаута (в отличие от прежнего поведения, где таймаут искажал медиану). Отдельно проверить крайний случай — окно, где по фиче/`kind` вообще нет ни одного `ok`: ожидание `p50Ms`/`p95Ms` = `-` (прочерк), не 0 и не время таймаута.

### Регресс: закрытые в round 1–3 пункты (проверить, что не отвалились)

6. **Тайминги и исход у покрытых типов вызовов.** Под свежим учеником пройти: `greeting` (вход в тему), `chat` (пара сообщений Мии), `recognition` (отправка решения текстом — happy path, не автоаборт), `memory_extraction` (пара сессий с чатом), `parent_report` (сформировать отчёт, если доступно на стенде).
   Ожидание: в таблице «по фиче/типу» на дашборде и в карточке ученика у каждой строки — медиана и 95-й процентиль (`X.X с / Y.Y с`), не прочерк.
7. **Таймаут отображается.** Поймать таймаут `greeting` (лимит 3 с, ловится на живом трафике при частичной загрузке).
   Ожидание: у строки — бейдж «N таймаутов» (склонение верное), число вызовов растёт, `usd` не растёт от неудачного вызова.
8. **Ошибка отображается.** Спровоцировать `status='error'` (недоступный провайдер/сетевая ошибка на `chat`) — если недостижимо руками, свериться по юнит-тестам `ai-cost.service.test.ts`.
   Ожидание: рядом с таймаутами — «N ошибок» (склонение верное), тултип показывает «таймаутов N, ошибок M» раздельно.
9. **Отчёт родителю: неуспех тоже пишется.** Спровоцировать сбой генерации сводки (истекший таймаут/недоступный провайдер) для диагностического, недельного или месячного отчёта.
   Ожидание: строка `parent_report` получает `status='timeout'`/`'error'`, а не пропадает из учёта; случай `skipped` (нет ключа провайдера) по-прежнему не пишется — это ожидаемо, не баг.
10. **Пустые/старые данные не ломают вид.** На периоде только со старыми записями (до миграции, `duration_ms=NULL`) — колонка времени показывает `-`, не `NaN`; на смешанном периоде перцентиль считается по новым/успешным, старые и неуспешные не искажают картину.

### Админка: карточка ученика `/admin/users/:parentId`

11. **Тайминги и исход видны по конкретному ученику.** Карточка ученика с историей вызовов (в т.ч. с пойманным таймаутом/ошибкой, включая свежий `ocr`) → в блоке «AI-расходы» у каждой фичи медиана/95% и, если есть, «N таймаутов»/«N ошибок».
12. **Пустое состояние.** Ученик без единого вызова AI → «Вызовов AI ещё не было», без пустой таблицы и ошибок в консоли.
13. **Расхождение с дашбордом отсутствует.** Для одного и того же вызова тайминг/исход в карточке ученика и в общем дашборде за тот же период совпадают (перцентили считаются раздельными SQL-запросами — риск разъехаться при рассинхроне).

### Регресс / общее

14. **Грейдинг и функциональность не задеты.** Тренажёр и диагностика продолжают штатно проверять решения; распознавание с доски/домашка отдают результат ученику так же, как раньше — фича только добавляет учёт, не меняет бизнес-логику вызовов.
15. **Деплой без простоя.** Не ручной тест-кейс, но стоит свериться с DBA/автором, если менялась схема — в этом MR миграций не добавлено, только логика записи в существующие поля.
16. **`/api/metrics` (Prometheus).** Гистограмма `ai_request_duration_seconds` с лейблами `kind`/`model`/`status` — второй независимый канал; для случаев из п.1–2, 7–9 метка `status` должна совпадать с записью в БД, и должна появиться метка `kind="ocr"` (раньше `ocr`-вызовы в гистограмму не попадали вовсе из-за отсутствия `durationMs`). Эндпоинт по-прежнему отдаётся без авторизации — заметка не по скоупу задачи.
