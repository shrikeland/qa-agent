# QA-сводка за 2026-09-16

Команда: Mia. Статусы: Ready for Test, Testing. В скоупе 24 задачи: 4 новых, 1 обновлённая (важная находка - см. ниже), 2 с изменённым `updatedAt`, но без изменения контента (title/description/комментарии совпадают с уже задокументированным - заметки не тронуты), 17 без изменений.

- **MIA-174** (входная диагностика по первому блоку курса, MR !430) - новая, объёмная. Сделана и выкачена только часть про диагностику (5-6 задач по темам первого блока класса вместо всего курса), правки ЛК по доске Miro - вне скоупа этого MR, доска недоступна. Ключевой открытый вопрос: поведение гейта тренажёра по темам вне первого блока зависит от `SCORING_VERSION` на стенде (v1 - тема остаётся заперта, v2/v3 - открыта), значение из репозитория не видно.
- **MIA-172** (домашки в админской карточке студента + детальная страница, MR !415) - новая, объёмная админ-фича, read-only. Подтверждены оба заявления разработчика: удалённые домашки/задачи не пропадают из списка (только помечаются), редактирования из админки нет нигде.
- **MIA-167** (ревизия «Карта привязана» после неуспешного списания, MR !413) - новая, критичный платёжный флоу. Отказ списания теперь явно показывается («Не удалось списать оплату»), freemium-пользователь возвращается в freemium вместо вечного `awaiting_payment`. Пересекается с MIA-166 (freemium + открытая домашка после отката).
- **MIA-17** (трекинг ошибок, MR !416 - по факту self-hosted GlitchTip вместо Sentry) - новая, инфраструктурная. Прошлый раунд QA (15.09, ещё до присвоения статуса в этом трекере) дал FAIL по недоступности панели GlitchTip для проверки - в заметке описан обходной путь через `api/scripts/sentry-smoke.ts`. Отдельно зафиксирован фикс скраба ПДн (`2eeba8fe`, маскировка аргументов консоли и всех форматов телефона) как обязательная зона регресс-теста.
- **MIA-166** (тумблер домашки на фремиуме) - **обновлена, важная находка**. Прошлый QA-раунд (15.09) дал FAIL: на стенде домашка оказалась полностью открыта фремиум-ученикам вопреки задокументированному `false`. Перепроверка кода показала - это не баг: тумблер `HOMEWORK_ON_FREEMIUM` осознанно переключён в `true` коммитом `6d85a998` от 14.09 как часть **другого** MR (!408, «домашка как приманка»), никак не зафиксированным в Linear на самой MIA-166. Тест-кейсы в заметке полностью переписаны под текущее состояние (`true`), старые (под `false`) оставлены справочно.
- **MIA-147, MIA-161** - `updatedAt` вырос, но по содержанию (title/description/комментарии) расхождений с уже задокументированным нет - заметки не трогались.
