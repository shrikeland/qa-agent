# QA-сводка за 2026-09-23

Команда: Mia. Статусы: Ready for Test, Testing. Linear и GitLab доступны без сбоев. В скоупе 28 задач: 3 новых, 8 обновлённых (новые комментарии/находки после предыдущего прогона), 17 без изменений.

- **MIA-192** (алерты GlitchTip в отдельный Telegram-чат, MR !487/!488/!489) - новая, уже выкачено. По ходу работы починены три сопутствующие поломки: релей молчал с 20.09 (nginx кешировал старый адрес контейнера), `monitoring-setup` ронял релей на каждом прогоне, у тестового проекта не было правил алертов вовсе. Задача называется «Sentry», но в проекте это self-hosted GlitchTip.
- **MIA-103** (баг: «найди ошибку» гоняло по кругу шаг/суть, MR !352) - новая. Корневая причина (сборка ответа из двух частей диалога) пофикшена и подтверждена QA 22.09. Свежий FAIL 22.09 по кнопке «Не ответ» тем же вечером разобран автором: задание в прогоне QA было подставлено в обход штатной выдачи (заблокированный уровень), на задании из активного блока кнопки на месте.
- **MIA-208** (CJ «от ученика к родителю» после ML2, MR !481) - новая, крупная фича. Гейт тренажёра `parent_pending`, суточная ссылка приглашения, +50 баллов рейтинга - по коду реализовано полно. Автор прямо предупредил: e2e-сценарий написан, но не прогнан локально; в заметке остались 2 открытых вопроса про пересечение с существующим кабинетом родителя.
- **MIA-191** (зависшие `binding_attempt`, MR !460/!462/!463/!485) - обновлена. QA нашёл 21.09 реальную гонку: непокрытый CAS-барьер заставлял свипер ложно инкрементить `binding_attempts_recovered_total` и слать письмо «карта не привязалась», даже если вебхук уже закрыл попытку успехом. Пофикшена MR !485 23.09, 32 новых теста на гонку.
- **MIA-193** (отвал на дашборде, MR !445/!484) - обновлена. QA нашёл 21.09: триал, отменённый до первой оплаты, задваивался в «Триалы без оплаты» и в «Отключили автопродление». Пофикшено 23.09 - теперь карточка считает только семьи с успешной оплатой.
- **MIA-195** (пикер периода на страницах обратной связи, MR !454/!482) - обновлена. QA нашёл 21.09: на чистом URL страницы активности/тем падали с `TypeError`, дефолт периода не подставлялся. Причина - общий хелпер отдавал отсутствующий фильтр пустой строкой вместо `undefined`. Пофикшено 23.09.
- **MIA-177** (отчёты Unit-экономика и Retention, MR !438/!456/!483) - обновлена. QA нашёл 21.09: пустой период показывал шесть нулевых недель вместо empty state - пофикшено 23.09. Отдельно висит неадресованный комментарий Романа (19.09) про некорректный учёт формы на спотлайт-лендинге - ни один MR его не покрывает, нужен ответ разработчика.
- **MIA-178** (дашборд: 18 метрик, MR !435/!457/!458) - обновлена. Разбор 23.09 показал, что FAIL от 21.09 (воронка С0/С1 расходится с отчётом Unit-экономики) не подтвердился: расхождение объяснилось разными границами периода (дашборд считает ровно выбранный диапазон, отчёт округляет по неделям), при выравнивании окна цифры сходятся полностью.
- **MIA-161** (редизайн главной, баннер-карусель, MR !390) - обновлена (по факту переоткрытия дедупа - `updatedAt` в Linear действительно сдвигался). Код перечитан на том же коммите: изменений с 10.09 нет, оба известных дефекта (горизонтальный скролл на 320px из-за демо-доски/тулбара, хардкод даты акции `PROMO_ENDS` вместо данных оффера) по-прежнему не закрыты.
- **MIA-156** (месячный отчёт, MR !382) - обновлена. MR смержен 22.09: прогресс тем в отчётах переведён с мёртвого `mastery_score` на процент по ML-блокам (это же задевает и недельный отчёт MIA-150 - стоит зарегрессить). Карточка месячного отчёта в кабинете родителя по-прежнему пустая, хотя нужные для неё цифры уже дошли до бэкенд-контракта - фронт их просто не читает.
