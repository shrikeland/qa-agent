# QA-сводка за 2026-09-21

Команда: Mia. Статусы: Ready for Test, Testing. Linear и GitLab доступны без сбоев. В скоупе 34 задачи (13 в Ready for Test, 21 в Testing): 11 новых, 2 обновлённых (новые комментарии/находки после предыдущего прогона), 21 без изменений.

- **MIA-96** (архитектура «Родитель-Ученик-Класс», обновлена) - оплата места второму ребёнку смержена (MR !451), код прочитан и задокументирован. Найден и точно локализован в коде баг: админ-API `POST/PATCH /api/admin/plans` принимает `slots`, но молча теряет его на пути в create/update Plan (`catalog-admin.service.ts:57-131` без поля `slots` в интерфейсах) - конкретный DTO-разрыв, а не догадка QA. Это блокирует happy path семейного тарифа. Отдельно подтверждено по grep: запрос Романа (редактировать имя/класс ребёнка задним числом, удалить дубль, явно привязать ссылку к имени при нескольких детях) в коде не реализован - открытый пробел на будущее, не баг этой задачи.
- **MIA-189** (карта знаний в приветствии Мии, обновлена) - MR !461 чинит 2 других бага того же флоу (мёртвый сокет у ученика без имени - 45 пострадавших на проде; карточка карты уезжала за край на телефоне), но НЕ закрывает исходный FAIL «карточка после F5 показывает устаревший прогресс». Разработчик заявляет, что сегодня не воспроизводится, и объясняет это чинкой сокета - но по коду карточка/`/me` читаются чисто по HTTP, сокет там не участвует, так что объяснение архитектурно не сходится. Зафиксировано как открытый вопрос, дана настойчивая инструкция для живой перепроверки (несколько F5 подряд, на телефоне, свежий ученик).
- **MIA-191** (зависшие binding_attempt, новая) - выкачено на прод, PENDING=0, все 50 исторических попыток разобраны (49 FAILED, 1 SUCCEEDED без потери оплаты). Бэкфилл сняли со скоупа как избыточный - свипер сам вычерпывает историю. Единственный реально непроверенный пункт acceptance - доставка алерта в Telegram при всплеске отказов, нужна живая перепроверка.
- **MIA-177** (аналитика в админке: Unit-экономика + Retention, новая) - разделы «Воронка»/«AB-тесты» закрыты и удалены на уровне API (не только страницы), заменены двумя отчётами. Особое внимание в этом раунде: сценарий недоступной Метрики (не покрыт прошлым прогоном), корректность CAC=прочерк при budget=0, невозможность фильтра по ABC-варианту лендинга (задокументированное ограничение, не баг - бакет живёт в куке и не уходит в Метрику).
- **MIA-200** (добавить ребёнка из меню, новая) - MR !459, общий диалог для трёх точек входа (меню/подписка/пустой экран), защита от закрытия по Escape/клику фона во время запроса подтверждена и есть юнит-тест. Найдено расхождение: ветка `billing.status === null` (семья вообще без записи подписки) не получила блок добавления ребёнка - маловероятный, но не охваченный MR!459 edge-case, отмечен как открытый вопрос.
- **MIA-178 + MIA-193** (дашборд-изменение + отвал по трём категориям, новые) - воронку с кодами С0…С2 дважды перепутали (С1.1 «завершили» вместо «начали диагностику») и в итоге поправили в MR !458; это главная точка риска для перепроверки. Отвал (MIA-193, физически тот же MR !445) разложен на 3 непересекающиеся SQL-категории с окном 3 дня. Найдено маленькое расхождение в документации: `docs/admin-dashboard-metrics.md` утверждает, что шаг «открыт пейволл» остался в стадиях пользователя для фильтрации - в реальном `funnel-stage.ts` такой стадии нет вовсе (комментарий в коде говорит, что её намеренно не заводили).
- **MIA-199 + MIA-198** (чипсы помощи, полоса прогресса над доской, новые) - оба мелких UI-фикса без MR (прямые коммиты). Для MIA-199 нашлась точная причина «на телефоне признака не было»: в `chat-composer-pop.vue` у `:disabled` раньше не было `opacity` вовсе, только `cursor`. Для MIA-198 подтверждён общий источник данных для чата и полосы (`toCabinetTaskProgress`), расхождений формулировок больше не может быть архитектурно.
- **MIA-197 + MIA-196** (утечка служебной разметки модели, фремиум-стена после первой задачи, новые) - оба без отдельного MR, влиты напрямую (MIA-197 через MR!450, MIA-196 через MR!452, имена веток в коде отличаются от Linear). MIA-197: детектор на regex по скользящему окну 200 символов, реальный tool-call не переспрашивается, только словесная подделка; живой баг почти невозможно спровоцировать - тест-кейсы опираются на юнит-тесты + регресс легитимного вызова. MIA-196: сигнал «тема закрыта» теперь из одной точки (`topicMlProgressService.registerResolution`), старый счётчик попыток убран полностью, воронка на `free_topic_done`.
- **MIA-195 + MIA-194** (пикер периода в обратной связи, диагностика parse_error, новые) - MIA-195: важная находка - «за всё время» убрано не везде одинаково (клэмп 92 дня есть только на части страниц через `feedback-report.admin.service.ts`, на `feedback/index.vue` его нет и «за всё время» там всё ещё дефолт) - проверять каждую из 4 страниц отдельно, не ожидать единообразия. Страница «Челленджи» пикера периода вообще не получила, только модалку пояснения. MIA-194: скраб-фильтр Sentry перепроверен вручную (allow-list, `rawText` физически не передаётся) - утечки текста нет. Живая проверка в Sentry/GlitchTip недоступна - тот же организационный блокер, что в MIA-17.
