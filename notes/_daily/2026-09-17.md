При чтении кода нашли, что `GET /admin/dashboard` продолжает отдавать старые top-level поля `mrr`/`arpu`/`activeSubscriptions` по прежней формуле параллельно с новыми `metrics.*` - UI их не использует, но это может сбить с толку при прямой проверке API.
- **MIA-174** (диагностика только по первому блоку тем, MR !430) - новая. **Активный FAIL от QA (16.09):** после диагностики прогресс размечается для всех тем курса, а не только для первого блока. Чтение кода показало, что сам скоринг (`diagnostic-session.service.ts`) исправлен верно - подозрение падает на `GET /api/me` (`auth.controller.ts`), который вне диффа этого MR синтетически подставляет нулевые записи для отображения. Приоритетный тест-кейс - сверить БД/admin-эндпоинт напрямую, в обход `/api/me`.
- **MIA-167** (ревизия «Карта привязана» при неуспешном списании, MR !413) - новая. Первый слой фикса QA подтвердил (оптимистичный экран сразу после возврата больше не показывается). **Активный FAIL:** повторный клик «Обновить статус» после статуса `pending` снова показывает «Карта привязана». Нашли конкретное место в `binding.service.ts`/`payments.controller.ts`, где повтор без новых данных от провайдера падает в fallback-угадывание статуса.
- **MIA-17** (мониторинг ошибок, вместо облачного Sentry - self-hosted GlitchTip, MR !416) - новая. Прошлый QA-раунд не подтвердил ключевой acceptance из-за отсутствия безопасного доступа к GlitchTip UI (организационный блокер, не баг в коде). Нашли готовый smoke-скрипт `api/scripts/sentry-smoke.ts` для ретеста; отдельная техническая находка - `.map`-файлы отвечают `500` вместо `404`.
- **MIA-168** (Мия не меняла имя по просьбе, MR !411) - обновлена. Новый QA-комментарий (16.09): нестабильное сохранение женских имён в творительном падеже («Катей» вместо «Катя») - подтверждено чтением кода: `normalizeStudentName` не приводит словоформу к именительному падежу, только капитализирует.
- **MIA-166** (домашка на фремиуме по константе, MR !397) - обновлена. Важная находка: QA 15.09 зафиксировал «FAIL» (домашка открыта на фремиуме при выключенном тумблере), но чтение кода показало, что это не регрессия MIA-166 - более поздний отдельный коммit (`6d85a998`, 14.09, не упомянут в тикете) уже перевёл `HOMEWORK_ON_FREEMIUM` в `true` на master.
