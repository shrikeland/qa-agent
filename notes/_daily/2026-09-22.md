- **MIA-155** (главная под Узбекистан, новая) — полноценные UI-first тест-кейсы. Код прочитан на `origin/master` (MR !389, смержен) — финальный комментарий (22.09) говорит «выкачено на прод»: `/uz` перестал быть отдельной страницей, стал одной главной на оба рынка с различиями по данным. Приоритетный риск для перепроверки — изоляция рынков (в ранних комментариях был баг: узбекский тариф светился на русской странице в рублях); чтением текущего кода (`offers.ts`, `surfaceMarket`/`billingMarket`) похоже, что исправлено, но это первый пункт для живой проверки. Отдельно отмечены нерешённые вопросы: хардкод `v1` для редакции согласий (MIA-164) и не до конца ясный статус узбекского каталога тарифов (draft/публичный).
- **MIA-139** (контент узбекского курса, новая) — контентный чек-лист (без кода, только данные). Выкачено на прод (тег `2026.09.22.1`), сидеры прогнаны. Реальные файлы в `api/scripts/data/course-uz/` сверены: 141 уникальная тема (142 файла — два грузятся в одну тему, отмечено для ревью), 80 вариантов КР сошлось точно; по подсчёту файлов вышло 11 534 задачи против заявленных на проде 11 504 — расхождение ~30, отмечено как пункт для прямой проверки БД, не как баг. Подтверждено чтением сидеров: `_author-drafts/` физически не читается заливкой, механизм изоляции банков (`withCurriculum`/`subject.curriculum`) в коде есть.
- **MIA-191** (зависшие binding_attempt, обновлена) — новый QA-комментарий: FAIL по CAS-барьеру recovered-метрики. Подтверждено чтением кода: `resolve()` возвращает `void` (не отдаёт признак успеха CAS), `runStaleBindingAttemptTick` инкрементит `binding_attempts_recovered_total` безусловно после `resolve()`, не проверяя, выиграл ли тик гонку с вебхуком — ложный alert `binding-recovered-cards` возможен. Гонка не смоделирована существующими тестами (`resolve` в них безусловно замокан).
- **MIA-193** (отвал на дашборде, обновлена) — новый QA-комментарий: FAIL, trial без единой оплаты попадает в карточку «Отключили автопродление». Подтверждено чтением SQL: подзапрос `autorenew_off` (в отличие от соседних `churned_paid`/`churned_trials`) не содержит условия по факту оплаты — искажает одну из трёх ключевых метрик дашборда, приоритет P0.
- **MIA-178** (дашборд-изменение, обновлена) — новый QA-комментарий (FAIL): знаменатель С0/С1 расходится с отчётом Unit-экономика (60 у дашборда против 188 в отчёте за тот же период). Комментарий пришёл ДО фикса !458 (который правил С1.1 и агрегацию воронки) — чтением кода ПОСЛЕ !458 подтверждено, что расхождение НЕ починено: найдены два независимых нетронутых механизма (разное выравнивание периода по неделям в `rangeOf()` отчёта и разная группировка вызова Метрики — `byWeek=false` у дашборда vs `byWeek=true` с суммированием у отчёта). Добавлен приоритетный тест-кейс для разделения двух кандидатных причин.
- **MIA-177** (аналитика в админке, обновлена) — новый QA-комментарий: FAIL по пустому периоду Unit-экономики — вместо «За выбранный период когорт нет» рисуются шесть нулевых недель. Подтверждено чтением кода: `unitEconomicsService` всегда генерирует по строке на каждую неделю диапазона (`EMPTY_COHORT_ROW`), поэтому `rows.length === 0` почти недостижимо. Баг косметический, цифры не искажены, приоритет низкий.
- **MIA-194** (диагностика parse_error, обновлена) — новый QA-комментарий: частичный FAIL — не по коду, а по невозможности живого воспроизведения. Контракт, защита и изоляция сессий подтверждены, но реальный парс-фейл на стенде за 4 дня не произошёл, а детерминированного тестового переключателя в коде не нашлось (проверено чтением `test.controller.ts`/`system.routes.ts` и grep по `mock`/`simulate`/`chaos`). Зафиксирована рекомендация разработчику на следующий раунд — добавить безопасный тестовый роут.
- **MIA-195** (пикер периода в обратной связи, обновлена) — новый QA-комментарий: FAIL по дефолтам периода на чистом URL. Оба бага подтверждены чтением кода: `use-admin-list-query.ts` отдаёт `''` вместо `undefined` для отсутствующего `?period=`, из-за чего `?? 'all'/'7d'` не срабатывает и везде подставляется жёстко зашитый фолбэк «30 дней»; на двух из трёх страниц отсутствующий `?.` перед `.from` даёт необработанный `TypeError` вместо загрузки данных по дефолтному периоду.
