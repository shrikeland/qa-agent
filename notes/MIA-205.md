## Контекст

С 16.06.2026 письмо родителю «Первое задание на платформе Мия360 выполнено 🎉» перестало уходить вообще всем семьям, зарегистрированным после этой даты: 0 писем при 66 подписках, где ребёнок ответил верно (когорта 14–21.09 — 21 ученик решил верно, 0 писем). До 16.06 письмо доходило 40 из 48 раз (83%).

Причина: коммит `33081130` («LL-1910 Freemium…») сменил статус подписки, который выставляется при регистрации без инвайта, с `trial` на `freemium` (`api/src/services/auth.service.ts`), а отправка письма (`tryClaimAndFireFirstTaskDoneForStudent`, вызывается из `api/src/controllers/trainer.controller.ts:433` при верном ответе) продолжала искать подписку строго со `status: 'trial'`. У freemium-семьи (`plan_type = NULL`, `trial_ends_at = NULL`) такая подписка не находится, метод молча возвращает `false`, флаг `first_trainer_task_email_sent_at` остаётся `NULL`, исключений и записей в логах нет — баг незаметен без сверки с данными.

Тот же гейт `status: 'trial'` есть в `soft-card-prompt.service.ts:13` (и `VALID_FOR_SOFT_CARD` в `subscriptions.controller.ts`) — это независимое подтверждение даты/причины (soft card prompt тоже перестал показываться с 15.06), но **этот MR его не трогает** — это отдельный открытый вопрос в тикете.

Приоритет High, статус Ready for Test, назначено на Kirill Verzhitskii. Автор тикета — Aleksey Bobrakov (расследование по продовым данным и коду, без живого репро — стенд production).

**MR !497** «MIA-205: письмо «первое задание выполнено» для freemium и платных семей», ветка `fix/MIA-205-first-task-email-freemium` → `master`, автор и мерджер — Kirill Verzhitskii, 6 изменённых файлов.

## Что было сломано

- `TrialEmailService.tryClaimAndFireFirstTaskDoneForStudent` (`api/src/services/email/trial-email.service.ts`) искал подписку ученика через `prisma.subscription.findFirst({ where: { studentId, status: 'trial', firstTrainerTaskEmailSentAt: null, ... } })` — единственный допустимый статус был `'trial'`.
- Семьи на `freemium` (публичная воронка регистрации без инвайта, с 16.06.2026) этот фильтр не проходили → `findFirst` возвращал `null` → метод возвращал `false` без исключений → письмо не отправлялось, флаг оставался `NULL` навсегда (сам себя баг не чинит).
- Неиспользуемый метод-близнец `maybeSendFirstTaskDoneForStudent` в том же файле имел точно такой же жёсткий фильтр `status: 'trial'` — тоже был багованным, но нигде не вызывался.

## Что изменено

- Фильтр статуса заменён с одиночного `'trial'` на список `status: { in: REPORT_ELIGIBLE_SUBSCRIPTION_STATUSES }` (`api/src/data/subscription-status.ts`) — это `['trial', 'active', 'charging', 'freemium']`, тот же список, которым уже пользуются еженедельные/месячные отчёты (`report-scheduler.service.ts`).
- Добавлено окно в 7 дней (`FIRST_TASK_EMAIL_WINDOW_MS`): письмо шлётся, только если **первый когда-либо верный ответ ученика** (`MIN(trainerSubmission.createdAt)` по `isCorrect: true`) был не позже 7 дней назад. Без этого семьи, которые занимались ещё в июне (и из-за бага не получили письмо тогда), получили бы «первое задание выполнено» задним числом при любом следующем верном ответе после фикса — по оценке автора это ~18 freemium-семей и одна платная.
- Добавлена доп. защита от повторной отправки: `prisma.subscription.count({ where: { studentId, firstTrainerTaskEmailSentAt: { not: null } } })` — флаг живёт на подписке, а не на ученике, и переход ребёнка на новую подписку (например, покупка тарифа с freemium) раньше мог обнулить историю отправки для новой записи; теперь проверяется, не отправлялось ли письмо этому ученику уже на **любой** его подписке.
- Текст письма теперь зависит от статуса подписки (шаблоны в `api/src/services/email/templates/`, реестр — `render.ts`):
  - `trial` — как раньше, шаблон `firstTrainerTaskDone.mjml`: кнопка привязки карты (`start-binding?sub=...`), тариф-строка «После пробного периода — …».
  - `freemium` — новый шаблон `firstTrainerTaskDoneFreemium.mjml`: поздравление + кнопка «Открыть все темы» на `selectTariffUrl` (`/select-tariff?sub=...&t=<подписанный токен>`), без «Продлить доступ» и без «после пробного периода».
  - остальные статусы из списка (`active`, `charging`, т.е. платные) — новый шаблон `firstTrainerTaskDonePaid.mjml`: только поздравление, без каких-либо платёжных кнопок/ссылок.
  - Роутинг шаблона — новая функция `renderSendable()` в `trial-email.service.ts`.
- Неиспользуемый `maybeSendFirstTaskDoneForStudent` удалён (в диффе отсутствует после правки — заменён единственным методом `tryClaimAndFireFirstTaskDoneForStudent`).
- Задним числом 66 ранее пострадавших семей **не догоняются** — явное решение автора в комментарии к тикету: «по открытым вопросам: задним числом не догоняем». Из-за 7-дневного окна большинству из этих 66 семей (у кого первый верный ответ был раньше конца августа) письмо не придёт вообще никогда — сработает только для тех, у кого первый верный ответ случится в течение недели от текущего момента (по факту это в основном новые семьи после релиза, плюс те самые ~18+1, для кого окно ещё не истекло).
- Аналитика не менялась: событие `EMAIL_FIRST_TRAINER_TASK_SENT` (`'email_first_trainer_task_sent'`, `api/src/constants/analytics-events.ts`) по-прежнему шлётся через `trackServerEvent` при успешной отправке — единое для всех трёх веток (trial/freemium/paid).
- Тесты: добавлены кейсы в `trial-email.service.test.ts` (поиск по списку статусов, freemium/paid/trial контент письма, тишина при «старом» первом верном ответе, защита от дублей при смене подписки, защита от гонки двойного claim) и в `trial-sequence.template.test.ts` (рендер двух новых шаблонов).

## Как перепроверить

Основной сценарий из комментария к MR/тикету:

1. Зарегистрировать ребёнка через публичную воронку/лендинг без инвайта → должна создаться подписка `freemium` (`plan_type = NULL`, `trial_ends_at = NULL`, `first_trainer_task_email_sent_at = NULL`), email родителя заполнен.
2. В тренажёре решить первое задание верно (важно сделать это в течение недели от регистрации — окно в 7 дней от первого верного ответа).
3. Проверить почту родителя: письмо «Первое задание на платформе Мия360 выполнено 🎉» пришло, содержит кнопку/ссылку «Открыть все темы» на `/select-tariff?sub=...&t=...`, ссылка открывает выбор тарифа **без входа в личный кабинет**; в тексте нет «Продлить доступ» и нет «после пробного периода».
4. Проверить в БД, что `subscription.first_trainer_task_email_sent_at` у этой подписки проставился (не `NULL`).
5. Решить ещё одно задание верно тем же ребёнком — повторное письмо не должно уйти (флаг уже стоит).
6. (Опционально) сверить, что событие `email_first_trainer_task_sent` зафиксировалось в аналитике один раз.

## Что посмотреть рядом (регресс)

- **Trial-семья** (обычный флоу с инвайтом/пробным периодом): письмо по-прежнему приходит один раз после первого верного ответа, с прежним текстом («Продлить доступ», «После пробного периода — …», кнопка привязки карты).
- **Платная семья** (`active`/`charging`): письмо приходит один раз, только поздравление, без ссылок на оплату/тарифы/привязку карты.
- Повторное решение задания (для любого из трёх статусов) не шлёт письмо повторно.
- Переход ученика с `freemium` на платную подписку **после** получения письма на freemium — новое письмо на новую подписку не должно уйти (проверка через `subscription.count` по всем подпискам ученика).
- Семья/ученик, у которой первый верный ответ случился больше недели назад (например, старая учётка, которая тестировалась до этого MR) — при повторном решении задания письмо не должно прийти внезапно задним числом.
- `trialEndingSoon` / `trialEnded` (планировщик `trial-scheduler.service.ts`) не затронуты — по-прежнему требуют `trial_ends_at IS NOT NULL`, у freemium это поле пустое, отдельная серия писем для freemium в этом MR не появилась (это отдельная продуктовая задача, см. описание тикета).
- Soft card prompt (`soft-card-prompt.service.ts:13`, `VALID_FOR_SOFT_CARD` в `subscriptions.controller.ts`) — фильтр по-прежнему `status: 'trial'`, этим MR не менялся; freemium-семьи soft card prompt по-прежнему не увидят. Это ожидаемо (отдельный открытый вопрос в тикете), баг-репорт по этому месту заводить не нужно, но если тест-план включает soft card prompt — не удивляться, что для freemium он не показывается.
- `api/src/services/email/trial-email.service.ts` — метод `sendFirstTrainerTaskDone` (обёртка `claimAndSend('firstTrainerTaskDone', ...)`) не менялся и напрямую нигде из прод-кода не вызывается кроме как через `tryClaimAndFireFirstTaskDoneForStudent` — проверять его отдельно не нужно.

## Открытые вопросы

- Задним числом 66 пострадавших семей не догоняются, и из-за 7-дневного окна большинство из них теперь **никогда** не получит это письмо (только новые верные ответы в первую неделю после первого решения задания попадают под условие). Стоит уточнить у продакт-менеджера/Kirill, ожидаемо ли это поведение или нужен отдельный разовый скрипт-догон для части когорты — тикет явно фиксирует решение «не догоняем», но не обсуждает, что это фактически «навсегда для большинства», а не «увидят чуть позже».
- Что показывать freemium-семье вместо «после пробного периода» в принципе, помимо реализованного варианта (поздравление + «Открыть все темы» на выбор тарифа) — в тикете это был открытый вопрос с тремя вариантами; MR выбрал один из них явно, но отдельного решения/подтверждения от продукта в комментариях MR не зафиксировано — стоит уточнить, что выбранная формулировка согласована.
- Соответствие soft card prompt (`status: 'trial'`) новому списку статусов остаётся нерешённым вопросом из тикета — не в скоупе MIA-205/этого MR, но может всплыть при регрессионном тестировании freemium-флоу как «баг», которым не является.
