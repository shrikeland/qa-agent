## Контекст

Контентная задача, не код-фича: сборка полного контента курса математики 5–9 для запуска в
Узбекистане — темы и контрольные в формате `api/scripts/data/course/`, готовые к заливке
существующими сидерами. Источник — официальные рабочие программы РУз (174 темы поурочно), контент
пересобран из российского банка (17,5к задач), валюта в текстах переведена в сумы. Разработки как
таковой не было (кроме отдельно вынесенной платформенной части — см. ниже), только ревью контента
и прогон сидеров. Уже задеплоено на прод (тег `2026.09.22.1`), разработчик прогнал воронку живьём.

Скоуп фактически шире исходного описания тикета: рядом с чисто контентной частью (ветка
`alekseybobrakov/mia-139-uz-course-content`) потребовалась платформенная — поле `subject.curriculum`
и фильтрация выдачи по программе (ветка `feat/MIA-139-multicurriculum`, задокументирована отдельно:
`docs/superpowers/specs/2026-09-21-multicurriculum.md`) — без неё заливка узбекского контента
переписала бы живые российские задачи. Она была нужна именно из-за MIA-139 и попала в тот же git-ref,
поэтому упомянута здесь, но это код, а не контент, и в этой заметке не расписывается тест-кейсами.

(«статус: wip», зафиксированы флаги R1–R17). Часть флагов на момент финальной заливки уже закрыта:

**Формат файла темы** (`tasks-uz-05-nahozhdenie-protsenta-ot-chisla.json`): `grade`, `section`,
`topic`, `hours`, `source`, `tasks[]` (`mlLevel`, `mlRole`, `level`, `kind`, `task`, `expression`,
`answer`, `rules`, `steps`, `hints`) — обычный формат `TaskFile`, который читает `seed-course-tasks.ts`.

**Формат файла контрольной** (`control-uz-gen-05-01.json`): `grade`, `section`, `controlTest`,
`orderIndex`, `afterLesson`, `source`, `topics[]`, `blueprint[]`, `mode: "generated"`, `variants[]`
(каждый вариант — `tasks[]` со `solution.steps`) — формат `ControlWorkFile`, читаемый
`seed-control-work.ts`; сидер валидирует соответствие каждого задания слоту каркаса
(`assertFollowsBlueprint`) до записи в базу.

**Валюта:** прогнал `grep` по всему `course-uz/` (235 файлов) на `₽` — 0 совпадений; на `руб`
(с исключением ложных срабатываний вроде «труба»/«грубая») — 0 совпадений валюты, только «труба» в
задачах на совместную работу и «грубая» в объяснениях find_error. На «сум» — 155 файлов содержат
слово, валюта переведена. Подтверждает заявление F10 из README о пересчёте номиналов, не только
переименовании.

**`_author-drafts/` действительно не читается сидером** — проверено чтением кода, а не только по
описанию: `seed-control-work.ts` (как и `seed-course-structure.ts`/`seed-course-tasks.ts`) берёт
список файлов через `fs.readdirSync(DATA_DIR)` **без рекурсии** по одному фиксированному
`DATA_DIR = data/course-{curriculum}`; `_author-drafts/` — подпапка внутри него, `readdirSync`
её не разворачивает, поэтому 40 черновиков физически недостижимы обычным прогоном без `--file=`
с явным путём внутрь `_author-drafts/`. Собственный `_author-drafts/README.md` объясняет и мотив:
пустой `blueprint` в 37 из 40 черновиков и 135 из 264 ссылок на несуществующие в УЗ-программе темы
всё равно уронили бы сидер, если бы файлы туда попали.

**Сидеры принимают `--curriculum=uz`.** Во всех трёх (`seed-course-structure.ts`,
`seed-course-tasks.ts`, `seed-control-work.ts`) одинаковый паттерн:
```ts
const CURRICULUM = arg('curriculum') ?? 'ru';
const DATA_DIR = path.join(__dirname, 'data', CURRICULUM === 'ru' ? 'course' : `course-${CURRICULUM}`);
```
Порядок прогона как в описании тикета: structure → tasks → control (подтверждено docstring'ами
скриптов и `_author-drafts/README.md`).

**Защита российского контента — ключ источника несёт программу.**
`api/src/helpers/content-source-key.helper.ts`:
```ts
// Программа дописывается в конец и только когда она не российская. Российские ключи обязаны
// остаться байт-в-байт прежними: иначе первый же прогон сидера не узнал бы ни одну из 11 050
// живых задач и создал бы им дубли. Узбекский банк на 2749 задач и 611 find_error дословно
// повторяет российский, и без этой приписки сидер переписал бы российские строки.
const withCurriculum = (parts: (string | number)[], curriculum?: string | null): (string | number)[] =>
  curriculum && curriculum !== 'ru' ? [...parts, curriculum] : parts;
```
`trainerSourceKey`/`diagnosticSourceKey`/`findErrorSourceKey` все прогоняют свои поля через
`withCurriculum`. Плюс `subject.curriculum` (`String @default("ru")`, индекс `(grade, curriculum)`,
миграция `20260921090000_subject_curriculum`) — отдельная строка `Subject` на каждую программу,
`seed-course-tasks.ts`/`seed-control-work.ts` ищут `subject` по `{ grade, curriculum: CURRICULUM }`,
а не только по `grade`. Оба механизма вместе и есть та защита, о которой пишет комментарий 4:
без них заливка совпадающих по тексту задач апдейтила бы существующие российские строки вместо
создания новых.

## Чек-лист для ревью

1. **Точечная сверка тем с рабочей программой РУз.** Недоступно агенту (нет доступа к исходным
   docx учебных программ) — ручной шаг для человека с доступом: выбрать 2–3 темы на класс + обе
   сгенерированные с нуля темы 5 класса (`tasks-uz-05-edinicy-dliny-massy.json`,
   `tasks-uz-05-perimetr-mnogougolnika.json`) + 2–3 `draft`/`generated` контрольные — сверить
   формулировки и соответствие разделу глазами методиста.
2. **Дубль темы «Решение задач» в 6 классе.** Два разных файла (`tasks-uz-06-reshenie-zadach.json`,
   `tasks-uz-06-reshenie-zadach-umnozhenie.json`) грузятся в одну и ту же тему по совпадению имени —
   проверить в кабинете, что тренажёр этой темы показывает задачи из обоих файлов и это ожидаемо
   (объединение банка раздела), а не потерянные задачи одного из файлов.
3. **Валюта.** Уже проверено агентом: `₽`/«рубл»/«руб.» не встречаются нигде в `course-uz/` (0
   совпадений на 235 файлов), «сум» — в 155 файлах. Стоит один раз перепроверить глазами 3–5
   выведенных в кабинете задач с денежным сюжетом — не потерялось ли форматирование чисел при
   пересчёте номиналов (комментарий разработчика упоминает конкретный пример: `{x+y=7; 2x+2y=14}`
   → `{x+y=7; 3000x+5000y=27000}`).
4. **`_author-drafts/` не участвует в проде.** Проверено чтением кода сидеров (см. выше,
   `readdirSync` без рекурсии) — механизм подтверждён. Ручной шаг: убедиться на проде, что ни
   в одной из 141 темы / 40 контрольных не всплывают формулировки из черновиков (они по
   утверждению содержат 900 уникальных авторских заданий, из которых только 38 совпадают с банком
   дословно — если что-то из черновика всё же попало в кабинет, это будет заметно по стилю).
5. **Изоляция банков RU/UZ.** Код подтверждает: `subject.curriculum` разводит предметы,
   `withCurriculum()` разводит `sourceKey`. Отдельной заметки/тест-кейсов по MIA-155 или общей
   архитектуре рынков в `notes/` не нашлось — при поиске найден только внутренний спек-документ
   `docs/superpowers/specs/2026-09-21-multicurriculum.md` (не QA-заметка). Ручной шаг: на проде
   зайти узбекским учеником и явно убедиться, что в поиске темы/тренажёре/диагностике/контрольных
   не всплывает ни одной российской задачи (заявлено разработчиком в проверке воронки — стоит
   повторить независимо, см. следующий пункт), и наоборот — российский ученик не видит узбекских.
6. **Прогон воронки — уже пройден разработчиком, повторить одним независимым прогоном.**
   Комментарий 4: регистрация на `test-1.mia360.uz` → рынок `uz` → кабинет с узбекскими темами →
   входная диагностика scored → тренажёр закрыл тему (ML1–ML5) → контрольная scored, российского
   контента в выдаче нет. Статус — PASS со слов разработчика, не переоткрывать с нуля, но стоит
   один раз пройти этот же путь независимо (другой ученик/другой браузер) перед закрытием тикета,
   раз это единственная сквозная проверка всей цепочки сидеров на живых данных.
7. **Число задач в БД vs в файлах.** Агент посчитал по файлам 11 534 задачи (11 146 в темах + 358
   в вариантах контрольных + 30 в диагностиках), Linear заявляет 11 504 на проде — расхождение 30.
   Не факт, что это баг (возможны дедупликации по `sourceKey` между файлами, которые агент не
   отследил), но стоит свериться прямым запросом к БД (`count` по `Assignment` с фильтром по
   узбекским `topicId`), а не полагаться только на подсчёт по файлам.
